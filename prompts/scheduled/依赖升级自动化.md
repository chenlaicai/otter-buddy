## 任务：依赖升级自动化（仅 Dependabot 驱动）

> 决策来源：搭档 2026-08-25 在 PR #419 的关闭评论——本定时任务只处理 Dependabot PR，
> 不再主动 `npm update`。依赖升级等 Dependabot 信号触发后再统一处理。

### 目标
检查 GitHub 上 Dependabot 创建的依赖升级 PR，关闭这些 PR，并按研发流程创建统一的依赖升级 PR。

### 执行步骤

#### 1. 检查 Dependabot PR
```bash
gh pr list --author "dependabot[bot]" --state open --json number,title,headRefName
```

#### 2. 无 Dependabot PR → 直接收工
汇报"无事可做"即可结束。**禁止主动 `npm update` 或基于 `npm outdated` 创建升级 PR**（PR #419 决策）。

#### 3. 有 Dependabot PR
- **关闭所有 Dependabot PR**：
  ```bash
  # 对每个 PR 执行
  gh pr close {PR_NUMBER} --comment "将合并到统一的依赖升级 PR"
  ```

- **删除 Dependabot 创建的分支**：
  ```bash
  gh api repos/{owner}/{repo}/git/refs/heads/{branch} --method DELETE
  ```

#### 4. 创建统一的依赖升级 PR
升级范围 = 刚才关闭的 Dependabot PR 覆盖的包（不是全量 npm update）。

- **创建 worktree**：
  ```bash
  # 按照 worktree-isolation skill 的流程
  ```

- **升级这些包**（按 Dependabot PR 中给出的版本）：
  ```bash
  npm install <pkg>@<version> ...
  ```

- **提交代码**：
  ```bash
  # 按照研发流程格式提交
  git add package.json package-lock.json
  git commit -m "[F{date}NNN][deps][Feature Update] 统一升级依赖版本"
  ```

- **创建 PR**：
  ```bash
  gh pr create --title "[deps] 统一升级依赖版本 ({date})" --body "..."
  ```

#### 5. 通知搭档
- **发送通知**：告诉搭档 PR 已创建，等待检视

### 注意事项
- 按照研发流程提交
- 主版本升级需要单独创建 PR，添加警告标记
- 不自动合并，等待搭档合入
