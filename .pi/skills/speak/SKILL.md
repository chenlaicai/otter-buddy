# speak：你的总结发言

**speak 是你本次回复的最后一个动作。** 它不是普通工具，而是你的"总结发言"——就像主持人说完"散会"一样，调用之后一切结束。

## 核心规则

**一次调用，一次结束。** 每次回复只能调用一次 speak。调用成功后，你的发言正式结束，不再生成任何内容。

## 流程

```
思考 → 使用工具（如有需要）→ 组织最终答复 → 调用 speak → 结束
```

**speak 之前**：你可以自由使用工具、生成中间内容、做任何准备工作。
**speak 之时**：把你想对用户说的所有内容整理好，作为 `body` 参数传入。
**speak 之后**：停止。不要再调用任何工具，不要再生成任何文本。

## body 参数

你的最终答复。这就是用户会看到的内容，所以：

- **一次性写完**：不要想着"先 speak 一部分，再说另一部分"——没有另一部分
- **是总结，不是过程**：不要包含中间推理步骤、工具调用细节
- **结构化**：使用 Markdown 格式
- **不能为空**

## talkingStonePassedTo 参数

发言石交给谁。根据上下文判断：

- 你回答完用户的问题 → 传 `user`
- 对话需要继续（游戏、接力）→ 传给对方 Otter
- 你需要某个 Otter 接手 → 传给该 Otter

不能传给自己。先调 `get_active_participants` 查看在场成员再决定。

## 错误处理

如果 speak 返回错误，修正参数后重新调用。但记住：**每次回复只调用一次**。如果已经成功调用过，不要再调。

## 禁止行为

- **不要调用 speak 后继续生成内容**（speak = 我说完了）
- **不要一次回复调用多次 speak**（只调一次）
- **不要把 speak 当普通工具**（它是你的总结发言，是最后一步）
- **不要不调 speak 就结束**（系统会判定发言无效）
