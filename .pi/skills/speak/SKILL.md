# speak：回合交接

## 你需要理解的核心概念

**发言石是同步机制，不是标签。**

当你调用 speak 并把发言石传给某人时：
- **你的回合立即结束**
- **系统会自动把你指定的人叫起来发言**
- **你不需要做任何后续操作**

这意味着：
- 你传给大獭 → 你的回合结束，系统叫大獭发言，你等待
- 大獭传回给你 → 大獭的回合结束，系统叫你发言
- 这样形成真正的轮流对话

**你绝不能在 speak 之后继续生成内容。** speak 的返回值 `[ok]` 只是确认，不是让你继续的信号。

## 流程

```
收到消息 → 思考 → 使用工具（如有需要）→ 组织答复 → 调用 speak 一次 → 停止
```

**关键：speak 是最后一步。** 调用 speak 之后，你的工作就完成了。系统会处理剩下的事情。

## body 参数

你想说的全部内容。这是用户和其他参与者会看到的。

- **一次性写完**：没有"下一次机会"
- **是总结，不是过程**：不要包含推理步骤
- **结构化**：使用 Markdown
- **不能为空**

## talkingStonePassedTo 参数

发言石交给谁。这决定了**谁是下一个发言者**。

- 回答完用户问题 → 传 `user`
- 对话需要继续（游戏、接力）→ 传给对方参与者
- 需要某人接手 → 传给那个人

**不能传给自己。** 先调 `get_active_participants` 查看在场成员。

## 错误处理

如果 speak 返回错误，修正参数后重新调用。但注意：**每次回复只调用一次 speak**。

## 绝对禁止

- ❌ 调用 speak 后继续生成内容（你的回合已结束）
- ❌ 一次回复调用多次 speak（只调一次）
- ❌ 把发言石当标签（它是控制信号，传给谁谁就发言）
- ❌ 不调 speak 就结束（系统会判定发言无效）
- ❌ 自己和自己对话（speak 后系统会叫别人，你等待即可）
