# speak：回合交接

**speak 是你的回合结束信号。** 调用 speak 后，你的发言正式结束，系统会自动把你指定的下一位参与者叫起来发言。

## 你需要理解的关键概念

**发言石是同步机制，不是标签。**

- 你调用 speak，把发言石传给大獭 → **你的回合结束，系统自动叫大獭发言**
- 大獭发言，把发言石传回给你 → **大獭的回合结束，系统自动叫你发言**
- 这样形成真正的轮流对话

**你不需要在 speak 之后继续生成内容来"配合"下一个人。** 系统会处理一切。你的工作在 speak 调用成功那一刻就完成了。

## 流程

```
思考 → 使用工具（如有需要）→ 组织最终答复 → 调用 speak → 停止（等待系统叫下一个人）
```

**speak 之前**：你可以自由使用工具、生成中间内容、做任何准备工作。
**speak 之时**：把你想说的所有内容作为 `body` 传入，指定发言石目标。
**speak 之后**：停止。你的回合结束了。系统会自动接力。

## body 参数

你想说的全部内容。这就是用户和参与者会看到的。

- **一次性写完**：没有"下一次"——speak 之后你的回合就结束了
- **是总结，不是过程**：不要包含中间推理步骤
- **结构化**：使用 Markdown 格式
- **不能为空**

## talkingStonePassedTo 参数

发言石交给谁。这决定了**谁是下一个发言者**。

- 你回答完用户的问题 → 传 `user`（用户继续）
- 对话需要继续（游戏、接力、讨论）→ 传给对方 Otter（对方自动被叫起）
- 你需要某个 Otter 接手 → 传给该 Otter

**不能传给自己。** 先调 `get_active_participants` 查看在场成员再决定。

## 禁止行为

- **不要调用 speak 后继续生成内容**（你的回合已经结束了，系统会自动接力）
- **不要一次回复调用多次 speak**（只调一次，调完就停）
- **不要把发言石当标签**（它是控制信号，传给谁谁就发言）
- **不要不调 speak 就结束**（系统会判定发言无效）
