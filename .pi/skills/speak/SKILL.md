# speak：你的最后一步操作

**你的每次回复必须以调用 `speak` 工具结束。** 这不是可选的——不调用 speak，你的发言会被系统判定为失败。

## 行为规则

**生成内容 → 调用 speak → 停止。** 没有例外。

当你准备好回复用户时，流程是：
1. 生成你的答复内容
2. 把答复内容作为 `body` 参数，调用 `speak` 工具
3. 停止生成

## 何时调用

**每次回复都必须调用。** 具体来说：

1. **答复完成**：你已经完整回答了用户的问题 → 调用 speak
2. **任务完成**：你已经完成了用户交代的任务 → 调用 speak
3. **需要转交**：你需要把发言权交给其他参与者 → 调用 speak
4. **只调用了一个工具**：比如只查了记忆 → 也要调用 speak 把结果告诉用户

## 参数要求

### body（必填）

你的最终答复内容。要求：

- **是总结，不是过程**：不要包含中间推理步骤、工具调用细节
- **结构化**：使用 Markdown 格式，清晰分段
- **完整**：包含用户需要的所有关键信息
- **不能为空**：空 body 会导致调用失败

### talkingStonePassedTo（必填）

下一个应该发言的参与者 ID 列表。要求：

- **必须指定**：空数组会导致调用失败
- **不能传自己**：不能把发言石传给你自己（自己的 otterId），否则会报错
- **先查再传**：调用 `get_active_participants` 获取当前在场成员列表，然后从中选择目标
- **通常是用户**：如果你的答复是对用户问题的回答，传用户 ID
- **可以是其他 Otter**：如果你需要其他 Otter 接手，传其 ID
- **可以是多个**：数组可以包含多个 ID

## 错误处理

如果 `speak` 返回错误（如 `[错误] body 不能为空`），说明你的参数有问题：

1. 读取错误信息，理解问题
2. 修正参数
3. 重新调用 `speak`

**不要因为一次错误就放弃调用 speak。**

## 调用成功后

`speak` 返回 `[ok] 发言已结束` 后，**不要再生成任何内容**。你的发言已经正式结束。

## 禁止行为

- **不要不调用 speak 就结束发言**（系统会认为你出错了，会提醒你重试）
- **不要传空 body**（会被拒绝）
- **不要传空 talkingStonePassedTo**（会被拒绝）
- **不要在 speak 之后继续生成内容**（发言已经结束）
