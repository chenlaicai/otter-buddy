# web 结构库（结构先于视觉）

> 使用时机：design/redesign 动词的第 2 步。先从本库选骨架，结构未定不写任何视觉代码。

## 核心原则

**结构多样性**：不同 brief 必须配不同骨架。判断标准——把两个产物的颜色/字体都抹掉，骨架还长得一样就是模板换色（泔水的结构性根源）。

## 骨架维度

选结构 = 回答三个问题：

1. **叙事节奏**：信息以什么顺序密度展开？
   - 线性下潜（叙事流：现状→冲突→方案→证据，适合说服）
   - 中心辐射（单焦点+周边注解，适合展示一个核心物）
   - 分区并置（2-4 个平行块各自完整，适合对比/并列）
   - 仪表盘（高密度网格+主次区分，适合状态监控）
   - 时间轴（序列事件，适合过程/历史）
   - 杂志流（多栏不等宽+图文穿插，适合阅读型内容）
2. **信息密度**：一屏多少个信息单元？高密度（工具感）vs 低密度（呼吸感）——由受众场景定，不由默认审美定
3. **动线设计**：受众第一眼看哪、第二眼看哪——用尺寸/对比/位置引导，而不是全屏都重要

## 结构选择表

| brief 类型 | 推荐骨架 | 理由 |
|---|---|---|
| 汇报/简报卡 | 线性下潜 | 结论先行，证据后置，扫读友好 |
| 产品落地页 | 杂志流 或 中心辐射 | 避免行业默认 hero→三卡→CTA |
| 数据面板 | 仪表盘 | 密度是功能，不是缺点 |
| 对比分析 | 分区并置 | 平行结构天然支持对照 |
| 教程/指南 | 时间轴 或 线性下潜 | 步骤感即结构 |

**反默认条款**：上表是起点不是牢笼——若 brief 明确指向表外结构，用之并在质检说明中记录选择理由。

## 层级落地

骨架选定后，逐项列出内容单元并标注层级（H1 级/M 级/辅级/折叠级），这张层级表随设计稿一起交付——它是结构决策的可审计记录。
