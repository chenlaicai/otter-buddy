# slides 结构库（叙事流，结构先于视觉）

> 使用时机：design/redesign 处理 PPT/演示类 brief 的第 2 步。先定叙事骨架，未定不开页。

## 核心原则

slides 的结构是**时间艺术**：信息按时间轴展开，每页一个任务，页与页之间是叙事推进不是素材堆放。最常见的泔水不是单页丑，是**页序无叙事**（想到哪写到哪）+ **单页多任务**（一页塞三个论点）。

## 骨架维度

1. **叙事弧**（整体推进模式）：
   - SCQA：情境→冲突→问题→答案，适合汇报/说服
   - 金字塔：结论先行→分论据→细节支撑，适合高管汇报
   - 时间线：阶段1→2→3，适合进展/历史/计划
   - 演示叙事：现状痛点→方案→演示→效果→展望，适合产品发布
   - 教学递进：是什么→为什么→怎么做→练习，适合培训
2. **信息密度曲线**：注意力是稀缺资源——开场 3 页内必到「钩子」（冲突/结论/惊喜），中段密度起伏（重页后必须有呼吸页），结尾一页收束不塞新信息
3. **单页纪律**：一页一任务一句话主张（assertion headline——页标题就是该页结论），细节进备注或附录

## 页序模板（v1）

| 模板 | 页数骨架 | 适用 |
|---|---|---|
| 汇报模板 | 封面→结论页→3-5 论据页（各一主张）→风险页→行动页 | 工作汇报 |
| 发布模板 | 钩子页→问题页→方案页→演示页→数据页→路线图页 | 产品发布 |
| 培训模板 | 目标页→概念页→案例页→操作页→练习页→总结页 | 教学 |
| 评审模板 | 背景页→方案对比页→推荐页→风险页→决策请求页 | 方案评审 |

**反默认条款**：模板是起点；brief 指向自定义叙事弧时用之并记录理由。

## 层级落地

交付时附「页序-主张表」：每页编号 + 该页一句话主张 + 支撑形式（数据/图示/引言）。这张表是叙事结构的可审计记录，先于任何视觉设计。
