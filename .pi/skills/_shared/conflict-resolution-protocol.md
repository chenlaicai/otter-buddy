# 冲突解决协议（Conflict Resolution Protocol）

> 作者：mimo + kimi + 大獭 | 日期：2026-08-21 | 来源：Anthropic 论文启示 + 对抗讨论共识

---

## 1. 冲突类型定义

| 冲突类型 | 定义 | 严重性 | 典型场景 |
|---------|------|--------|---------|
| **目标漂移** | 小獭在多轮执行中逐渐偏离原始目标 | 中 | 开发獭做着做着开始重构架构 |
| **资源竞争（文件）** | 两只小獭修改同一个文件 | 中 | 开发獭和检视獭同时修改同一模块 |
| **资源竞争（记忆/术语）** | 两只小獭修改同一个共享资源 | 中 | 小獭 A 更新了术语，小獭 B 基于旧术语做判断 |
| **目标不兼容** | 两个小獭的目标互相冲突 | 高 | 开发獭要重写，检视獭要修复 |
| **审查僵局** | 开发獭和检视獭对同一问题反复争论 | 高 | 对立僵局、移动靶、僵尸循环 |
| **死锁** | 两只小獭互等对方完成才能继续 | 低 | 编排错误导致的循环依赖 |

---

## 2. 解决策略矩阵

| 冲突类型 | 自动解决 | 升级到大獭 | 升级到搭档 |
|---------|---------|-----------|-----------|
| 目标漂移 | 小獭自行回归目标 | 漂移严重/无法判断 | - |
| 资源竞争（文件） | worktree 隔离已解决 | 同一 worktree 内冲突 | - |
| 资源竞争（记忆/术语） | - | 大獭协调写入顺序 | 大獭无法判断时 |
| 目标不兼容 | - | 大獭重新分配任务边界 | 设计层面分歧 |
| 审查僵局 | - | 按 review-loop 收敛判据 | 对立僵局/移动靶/僵尸循环 |
| 死锁 | 超时熔断 | 大獭重新编排 | - |

---

## 3. 升级协议（Escalation Protocol）

当冲突无法在当前层级解决时，按以下协议升级：

```
Level 0: 小獭自行解决
  ↓ 无法解决
Level 1: 报告给大獭（speak 报告 + yield 传回行动权）
  ↓ 大獭无法判断
Level 2: 大獭报告给搭档（speak 报告 + yield 传给 user）
  ↓ 搭档决策
Level 3: 搭档做出最终决策
```

---

## 4. 升级报告格式

当小獭需要升级冲突时，使用以下格式报告：

```
## 冲突报告
- **冲突类型**：[目标漂移/资源竞争/目标不兼容/审查僵局]
- **涉及獭**：[獭A] vs [獭B]
- **冲突描述**：[具体发生了什么]
- **已尝试的解决**：[自动解决措施及结果]
- **需要决策的问题**：[明确的问题陈述]
- **建议方案**：[可选，提出者的建议]
```

---

## 5. 裁决记录格式

搭档或大獭做出冲突裁决后，使用以下格式记录到记忆系统：

```
## 冲突裁决记录
- 时间：<timestamp>
- 冲突：<简述>
- 裁决者：<搭档/大獭>
- 决策：<具体内容>
- 先例标签：<可检索的标签，如"文件修改优先级"、"设计方向分歧"">
```

**记录方式**：使用 `create_linked_resource`（fact 类型）记录，后续冲突可通过 `search_memory` 检索先例。

---

## 6. 与信任校准机制的对接

当信任校准机制检测到"不同獭对同一问题给出矛盾结论"信号时，应触发冲突解决流程：

1. 信任校准检测到矛盾 → 标记冲突
2. 引入冲突解决机制 → 按解决策略矩阵处理
3. 解决后更新双方信任度

---

## 7. 优先级层级

当目标不兼容时，按以下优先级决定谁的目标优先：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| P0 | 搭档（人类）指令 | 最高优先级，不可被任何 agent 覆盖 |
| P1 | 大獭的显式约束 | 大獭在 systemPrompt 中设定的边界 |
| P2 | Skill 工作流定义 | Skill 中定义的流程约束（如审视不通过不能提交） |
| P3 | 小獭自行判断 | 小獭在目标范围内的自主决策 |

**核心规则**：高优先级目标可以否决低优先级目标，反之不行。
