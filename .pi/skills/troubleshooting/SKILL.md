# Troubleshooting

结构化的问题排查：从现象到根因，从分析到修复。

## 触发

**触发条件**：搭档需要排查问题、调试、分析系统行为时。

**排除**：简单的信息查询（搜记忆、查对话历史）→ `core-workflow`。

**输入**：
| 输入 | 必选 | 缺失时 |
|------|------|--------|
| 问题描述 | 是 | 停下来问搭档 |
| 已有线索 | 否 | 主动收集：日志、错误信息、复现步骤 |
| 排查范围 | 否 | 从问题现象出发，逐步缩小 |

## 工作流

1. **收集信息**：读取相关文件、日志、配置；查询 memory 中的历史决策和类似问题；确认复现条件和影响范围。
2. **分析根因**：提出假设 → 逐一验证（读代码、查日志、对比配置）。区分症状和根因——修根因，不修症状。

   **修法排序**（确定根因后、动手前）：先问该不该存在，再问怎么修——① 在既有机制语义内修（缺啥补啥，默认路径）→ ② 收窄问题机制的管辖边界 → ③ 删除机制、接受其当初解决的原始问题回归（当机制维护成本已倒挂原始问题成本）→ ④ 新增机制（最后手段，须按 requirement-analysis 的机制预算四问论证）。选 ④ 跳过 ①②③ 时必须写明为什么它们不行。

   **机制识别检查点**（修法排序前逐项打勾，机械判断不凭感觉，F20260912fqgp）：本次修复是否涉及以下任一项？
   - □ 新增配置字段/枚举/开关
   - □ 新增状态生命周期（创建→存活→销毁）
   - □ 新增定时任务/后台进程
   - □ 新增信号类型/消息格式
   - □ 新增持久化存储（数据库表/字段/文件）
   - □ 新增决策分支（其结果被记住并在后续影响行为——如写入数据库/配置/记忆/文件的分支；纯运行时临时分支不算）
   - □ 新增跨模块调用路径

   命中任何一项 → 修复大概率含净新增机制。后续约束：若最终走修法排序④ → 四问必答（作者当场作答，写入特性文档）+ 重对抗门必过；若排查者判断走①②③ → 必须在排查结论中显式论证「为何命中清单但不涉净新增机制」（一句话即可），论证写入特性文档供每日清单核验——论证不出 → 改走④流程。全部未命中 → 默认走修法排序①②③。清单故意偏严——误触发成本是写几行字，漏掉机制的成本是补丁叠加。

   **存在性对抗分级**（修法排序选定后，F20260908pgrd）：
   - 选 ④（新增机制）→ **重对抗门**：动手前召检视獭（轮换、异模型）审查「这个修改在系统演化史中是治本还是治标」（要求检视獭 search_memory 查相关机制演化脉络）。门控三结论：`确认治本` / `疑似治标（附理由）` / `信息不足（附缺口说明）`——仅持「确认治本」方可继续；「疑似治标」暂停呈搭档裁决；「信息不足」作为合法结论呈搭档（禁止硬给质量可疑的答案），搭档裁决：补充信息后重审 / 基于已有信息自行决定继续或中止。门控通过后，后续 commit 声明 `Modification-Class: mechanism-addition`
   - 选 ①②③ → **轻对抗**：不召獭，后续 commit 须含 Modification-Class 声明行，取值对应：①→`narrow-fix` / ②→`scope-reduction` / ③→`deletion`（声明细则见 worktree-isolation 步骤 4）
3. **形成结论**：输出结构化结论（问题现象 + 根因分析附 file:line + 修复建议 + 影响范围）。将排查结论写入 worktree 中的特性文档（参见全局约定「特性文档」），首次写入时用 `create_linked_resource(type: "file", groupId: "<特性ID>")` 注册（groupId 可选）。写完后调 `sync_docs`（root_dir 传 worktree 绝对路径）立即入库，并用 `link_memory` 声明"当前讨论 produced 本文档"——让"这文档怎么来的"之后可被 get_related 拼出链。
4. **需要修复时**：转入 `worktree-isolation` 流程创建 worktree，在 worktree 内修复并提交。
5. **排查中需改文件验证假设时**：立即转入 worktree，验证完成后决定提交或 revert，继续排查。

> 约束：先读文件/数据再分析，不凭印象。结论必须附 file:line 引用。修复建议必须具体可执行。

## 产出

| 产出 | 下一步 | 执行者 |
|------|--------|--------|
| 排查结论（需修复） | worktree-isolation 流程（排查结论已写入特性文档） | 当前獭 |
| 排查结论（无需修复） | 记录到特性文档或 memory | 当前獭 |
