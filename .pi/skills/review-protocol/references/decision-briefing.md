# 决策简报

凡 yield to user 请求拍板时，发言必须附本简报——解决「搭档看到待决策清单、但不知道讨论了什么、方案全貌是什么」的信息不对等（盲签问题）。

简报按**三层结构**组织：3 秒层（执行摘要）→ 30 秒层（关键信息）→ 完整版（细节）。三层是同一份内容的三个放大倍率，不是三份不同内容——搭档扫一眼 3 秒层能决策就决策，想多看一眼有 30 秒层，想深挖有完整版。

> 设计依据（搭档 9/15-9/16 原话）：「我更想看到 问题是什么（描述清楚、简单易懂）、根因、分析、解决方案，然后让我选择，而不要过于为了简略文字而简略」「内容可能比较多，但有图有表，有三层结构，三秒看什么、三十秒看什么、完整版这种」。

## 三层结构

### 3 秒层（执行摘要）——放最前

- **一句话结论**：「我建议 X」——搭档赶时间只看这句也够
- **风险**：一句话（低/中/高 + 最关键的一条）
- **置信度**：高/中/低 + 一句理由

卡片化时，本层结论必须同时写进**卡片 title**——所有卡默认折叠（F20260916hcel），title 是折叠态唯一可见的信息。

### 30 秒层（关键信息）

- **背景 ≤3 行**：为什么走到这一步，触发点是什么
- **选项对比**：候选 A/B/C 各一句话 + 关键取舍，**含被否掉的方案和否决理由**——搭档最容易盲区的正是"还有哪些路没走"。≥3 个选项时用表格，推荐行高亮
- **獭间分歧如实呈现**：讨论中若有异议，双方观点都摆出来，不藏——大獭收敛结论不代表分歧消失
- **推荐 + 理由 + 最大风险**

### 完整版（细节）——卡片化时用 `<details>` 折叠

- **案发现场**：数据锚点、日志、对话引用
- **锚点**：特性文档 ID / 讨论位置 / file:line——想深挖顺藤摸，不想深挖信简报
- **引用**：分析文档、PR、记忆条目

## 卡片化规范（L2 决策必出 html-card）

L2 决策呈搭档拍板时，简报以 **html-card 议题汇报卡**交付（配套模板见 `templates/` 目录）：

- **一个议题一份汇报卡**——不每问一小卡（搭档 9/15：「难道每个问题就做一张卡片吗」）
- **title 承载 3 秒层结论**——如「议题：说人话失败整改 · 建议方案 B · 等你拍板」，折叠态即可决策
- **选项按钮用 `otterCard.submit`**——搭档点一下即拍板，不用打字
- **不要前置色块**（🟢🟡🔴 markdown 引用块）——搭档 9/15：「很低级也很难看」。状态标识放卡内，用文字徽章或色点
- **不为简略而简略**——内容可以多，靠分层和折叠控节奏，不靠砍信息
- 写卡前必调 `get_html_card_contract` 取完整契约（体积上限 64KB、单消息最多 2 张、默认折叠、高度自定 clamp [100,4000]）

纯文字场景（无法出卡或议题轻到不值一卡）仍按三层结构组织 markdown 正文：3 秒层加粗放最前，30 秒层次之，完整版放最后。

## 默认通过模式（L2 中低风险项）

「我推荐 X，理由如下，**今天内无异议就开工**」——把「必须即时响应」改成「异步默许」，搭档忙时不用专门回，有异议随时喊停。

**适用判据**（三条须同时满足，拿不准就往高风险归——宁问不默）：

- 无不可逆后果（或逆回成本低）——❌ 反例：删除 memory 表某字段、force-push 受保护分支
- 不涉及对外承诺——❌ 反例：承诺搭档/外部在 X 时间前交付 Y
- 搭档否决成本低于约 1 天工时——✅ 正例：引入新依赖库 X；✅ 正例：采用方案 B 而非 A（两者均已验证可行）

高风险 / 不可逆项**不适用**默认通过——必须等明确拍板。

## 示例

反例（裸奔拍板，禁止）：

> 方案讨论完了，有 3 个问题需要你拍板：1… 2… 3…

反例（决策点埋末位，禁止）：

> （400 字技术细节铺垫）……综上所述，你认为要不要做 X？

正例（纯文字三层结构）：

> **建议用方案 B（风险低 · 置信度高）。**
> 背景：A/B 均验证可行，B 省 1 天且可回退。讨论中 mimo 担心 X，我认为可控因为 Y。被否的 A 差在 Z。
> <details>细节在 F20260909xxxx，案发现场见对话 9/15 01:26。</details>
> 无异议今天开工。

正例（卡片化）：见 `templates/decision-briefing-card.md` 完整示例。

## 适用范围

- 代码 PR 终审（review-protocol A 步骤 5）
- 方案终审（review-protocol B / requirement-analysis 产出）
- 小改动 PR 终审（worktree-isolation 产出表）
- 任何其他 yield to user 请求决策的时刻（含审视僵局呈裁决）

## 分级边界

什么该问搭档、什么獭自己定，分级定义在 SYSTEM.md「决策分级」节。简报是 L2 层的强制输出物；L0/L1 层不出简报（L1 只留痕，可事后否决）。
