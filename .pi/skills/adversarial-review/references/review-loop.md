# 对抗审视循环协议

轮次结构、收敛判据与升级路径——作者、检视者、调度者三方共用的**循环**规则，单一真相源。

职责划分：检视者行为规则（焦点声明、发现分级、报告格式）见 `../SKILL.md`；作者对单条发现的处置（四分类、证据要求）见 `author-response-protocol.md`；本文件只管"循环何时继续、何时停、找谁裁决"。

## 轮次结构

- **第 1 轮**：全量 fresh-eyes 审视。检视者不附上轮材料，独立判断。
- **第 2 轮起：delta 审视**，不是全量重审。作者须向检视者提供：上轮发现清单 + 作者逐条处置 + 修复/修订 diff + **delta 核对材料**（代码 PR 路径：更新后的 PR 描述全文，核对 Discovered Issues 节 issue 落实；方案文档路径：更新后的方案文档或修订 diff，核对待办/决策史节的段落定位落实）。检视者职责变为：① 逐条验证修复是否正确、完整 ② 检查修复引入的回归（fix-regression） ③ **核对上轮非阻断发现处置的落实**（信息来源：大獭在材料中附的 delta 核对材料——检视者无 `gh` 权限，不自行访问 GitHub）。没有落实 = 处置未完成，不能收敛。
- delta 之外的新发现：允许报，但必须标注"此前轮次漏报"，默认归入非阻断发现，除非过阻断门槛（单凭该条能否决交付）。

## 收敛判据

**不设固定轮数上限。** 循环自然终止于：修复验证全部通过 + 无阻断回归。

出现以下任一信号，停止循环、呈搭档裁决：

- **对立僵局**：同一问题经一轮证据交换仍对立（处置流程见 author-response-protocol.md）
- **移动靶**：delta 轮冒出 delta 之外的新阻断问题——改动可能太大该拆，或该回设计阶段
- **僵尸循环**：连续 2 轮修复验证不通过——同一批问题修不对，继续循环无意义

搭档作为决策者不受此限：随时可加开检视轮，或直接拍板合入/打回/终止。

## 轮次记账

反驳的证据交换**不消耗审视轮次**——轮次按全量/delta 审视计数。反驳在对话内直接发给原检视獭，无需为它重建或重附材料。

## 报告合规门禁

作者收到审视报告后，先校验合规性（含"本轮焦点"声明、发现分级、file:line 引用）——不合规直接打回重做，不合规报告不进入处置流程。代码 PR 与方案文档两条审视路径同款门禁。
