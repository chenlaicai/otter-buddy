# Diagram — 技术图解

把「架构/流程/时序/关系」画成像人画的图：网格对齐、单流向、密度克制、token 配色。工具就是 html-card 内联 SVG——渲染层零依赖，不塞任何 JS 库。

## 触发

**触发条件**：发言内容涉及技术结构（分层/调用链/数据流/模块关系），或搭档点名要图。主动判断：正文出现「A 调用 B」「分三层」「流程是」「依赖关系」这类结构叙述时，先问「这段文字能不能变成一张图」——能则出图，别把图解写成一堆文字。

**排除**：展示设计（美学优先）→ visual-design；纯数据对比 → 表格；单句能讲清的关系 → 言语直答，不强行出图（每条都出图等于没出图）。

## 输入

| 输入 | 必选 | 缺失时 |
|------|------|--------|
| 图解主题（一张图回答的一个问题） | 是 | 从正文提炼；提炼不出 = 不该出图 |
| 图中实体与关系 | 是 | 从方案/代码核实，不编造 |

## 工作流

1. **选图型**（按要回答的问题选，不按习惯选）：
   - 「系统分几层、各层职责」→ **分层堆叠图**（横向层条自上而下，状态/职责注记）
   - 「步骤/流程怎么走」→ **流向图**（左→右或上→下单一主流向，箭头串联）
   - 「谁在什么时候调用谁」→ **时序图**（泳道纵线 + 带序号的横向消息箭头）
   - 「模块间关系/依赖/归属」→ **节点连线图**（节点分组分区，连线表关系）
   - 「方案 A/B 差异」→ **不是图，用表格**（.tbl 预设）
2. **定骨架再动笔**：先列节点清单与网格坐标（x/y 对齐表），同类框等高等宽、间距一致；节点 >12 个就分层分组或拆两张图。骨架不定不写 SVG。分层堆叠图直接抄 `references/layered-architecture.md` 的网格坐标表与 SVG 骨架（含 marker/配色/出卡围栏），替换层数与文字即可。
3. **绘制**（技术规范）：
   - `<svg viewBox="0 0 W H" width="100%" style="font-family:inherit">`，禁视口相对高度；正文图宽 W 建议 680-760，字号 ≥10.5（标题 13-16）
   - 配色只用设计 token：底 `var(--paper)`/`var(--otter-50)`、描边 `var(--line)`、强调 `var(--teal-500)`、警示/缺口 `var(--caramel-500)`、文字 `var(--ink)`/`var(--ink-3)`——不自造色值
   - 箭头统一 `<defs><marker>` 定义一次复用；文字居中用 `text-anchor="middle"`，长标签 ≤2 行
   - SVG 内第一行 `<text>` 写结论句（折叠摘要可提取 SVG 文本）；**检索/记忆占位只保留卡片 title**——title 必须自成结论（如「说话治理全景：图形层断腿定位」），别指望图内文字被检索到
4. **出卡**：普通 html-card 围栏 + `importance="high"`（图的感知动词是「看」，折叠态等于没发）+ `chip="图解"`（覆盖 high 缺省的「简报」角标）；正文配 1-2 句结论，图外叙述不放图内。体积参考：常规 <20KB，256KB 上限是保险丝不是目标。
5. **过质检门**（不过门不出稿）：
   - [ ] 单图单主题——标题能回答「这张图说明什么」，答不出就拆
   - [ ] 网格对齐——没有随手摆放、大小不一的同类框
   - [ ] 单一主流向——箭头不交叉回绕；必须回绕时改用编号断点
   - [ ] 密度克制——图内文字是标签不是段落，段落已移到图外正文
   - [ ] 全 token 配色、无 JS 库、无 base64、无外网引用

## 产出

| 产出 | 下一步 |
|------|--------|
| 图类卡 + 正文一句话结论 | 随发言交付，不需额外登记 |
| 搭档对图的反馈（看不懂/混乱点） | 记为规范迭代素材，回本 skill 修订 |
