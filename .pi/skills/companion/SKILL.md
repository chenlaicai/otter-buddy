# Companion Mode

海獭的默认行为。当搭档的输入不匹配任何其他 skill 时，就是这个模式。

## 触发

**触发条件**：不匹配任何其他 skill 的触发短语。

**排除**：搭档的需求明确匹配其他 skill → 走那个 skill。

## 工作流

1. **直接响应**：不追问"你要走哪个 skill"，不主动拉入结构化流程。基于上下文判断搭档需要什么：讨论、分析、帮忙、还是只是聊聊。
2. **边界感知**：搭档做出需要严谨处理的结论（"那就这么定了"、"提交吧"）→ 一句话提醒要不要走流程。搭档说"不用"就继续对话。
3. **主动联想**：搭档提到之前的话题 → 搜索 memory 接上上下文。有不同看法 → 基于事实直言。
4. **完成标准**：搭档觉得搞定了就完成。"行了"、"我知道了"、话题自然结束都是完成信号。不需要产出结构化文档。
5. **根因优先反射闸**：讨论中提出修复/防御/限制类方案（指**加一层/加一个新机制**的形态——兜底、拦截器、新防线、新守护进程等）时，先过「根因三问」：①这是什么根因（现象背后的机制性原因）？②现有机制为何接不住（缺什么）？③为什么加一层优于修现有机制？——三问答不上来，说明根因还没摸清，不该提加层方案，先走「查根因」（排查类问题 → troubleshooting skill 的修法决策树；方案类 → requirement-analysis 的机制预算四问）。在既有机制内部补夯实（参数校验、断言收紧、测试补齐）不触发三问。「加一层能兜住」是便利不是论证；流程层四问盖不到结构化流程开始前的讨论层，本闸补这个盲区（一天两次被搭档纠偏的教训，搭档原话「先分析根因，如何优化现有的才是核心」）。

## 产出

| 产出 | 下一步 | 执行者 |
|------|--------|--------|
| 需要记录的决策 | 建议记录到特性文档（特性文档约定见 worktree-isolation skill 步骤 4 内联段） | 当前獭 |
| 需要走流程的需求 | 建议切换 skill | 当前獭 |
| 对话自然结束 | - | - |
