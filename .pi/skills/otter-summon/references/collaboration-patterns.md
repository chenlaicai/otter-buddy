# 多轮协作编排模式

## 开发↔检视循环

开发和检视之间的多轮对话是最常见的协作模式。

### 流程

1. 你 create_otter 创建开发獭（systemPrompt 写任务），然后 **yield 把行动权传给它**——create 只是就位，yield 派工它才会开工
2. 开发獭完成阶段性产出后，行动权传给检视獭（你需要先创建检视獭加入对话）
3. 检视獭审查后，行动权传回开发獭
4. 循环的继续与终止按收敛判据运转（定义见 adversarial-review/references/review-loop.md）：不设轮数上限，自然终止于"修复验证全部通过 + 无严重发现未处置 + 无阻断回归"；对立僵局/移动靶/僵尸循环任一信号 → 呈搭档裁决

   > **修复后路由铁律**：开发獭（或你大獭自己）修完检视发现后，下一步是把行动权传回检视獭做 delta 复核。检视獭说"通过"才叫通过——你不能自己签收。传 `'user'` 只发生在检视獭 delta 复核通过之后。
   >
   > 大白话：**改完 ≠ 过了。谁提的问题，谁确认问题解决了。**

5. 最终结论整合后，你向搭档汇报

### 行动权路由

通过 `yield` 工具的 `to` 参数指定行动权接收者。接收者用 **Otter 的名字（otterName）**标识，`'user'` 表示传回给搭档。参数是数组，支持传给多个接收者。创建小獭后，它会自动加入当前对话参与者，你可以在 yield 时将其作为路由目标。

并行场景下，你创建所有小獭后，**一次 yield 把行动权传给所有小獭**（同时唤醒，各自独立产出）。

`speak` 工具用于输出内容（让其他人看到你的进展/结论），不涉及行动权移交。典型用法：先用 speak 输出结论，再用 yield 交棒。

### 链条断裂恢复

- **判断断裂**：小獭发言超时（熔断器会自动中断）、发言内容不符合预期、小獭报告困境无法继续、行动权目标已解散、或行动权投递时目标已离场（dispatcher 静默丢弃，链条无声终止）
- **恢复策略**：
  1. 重新创建小獭，systemPrompt 中带上之前的上下文和已有结论
  2. 大獭自己接管完成（如果任务不复杂）
  3. 向搭档汇报进展，请搭档决策

### 注意事项

- 检视獭的 systemPrompt 应明确检视范围和标准（参考 adversarial-review skill：第 1 轮全量 fresh-eyes + 焦点声明；第 2 轮起 delta 审视，需附上一轮发现清单、修复 diff 和 delta 核对材料——代码 PR 路径附 PR 描述全文核对 issue 落实，方案文档路径附更新后的方案文档核对待办落实）
- 开发獭回应检视发现时遵循作者处置协议（adversarial-review/references/author-response-protocol.md）：决策树判断（改了让系统变好/变更差）+ 四分类响应（接受/带证据反驳/部分接受/呈搭档），不照单全收，不作为不允许
- 开发獭的 systemPrompt 应包含方案编号，检视獭可据此查阅方案

## 并行调研

多个方向同时调研，各自独立产出，你负责汇总。

### 流程

1. 为每个调研方向创建一只小獭，各自 systemPrompt 指定方向
2. 所有小獭完成后，你汇总各方向结论
3. 形成综合分析后交给搭档

### 注意事项

- 各小獭之间不通信，各自独立完成
- 行动权路由：每只小獭完成后 yield 传回给你，你汇总后再交给搭档
- 汇总时注意对比和冲突点

## 排查类任务

排查通常是单轮协作：排查獭分析问题 → 输出根因和修复建议 → 大獭处理。不需要多轮循环。

## 角色讨论

模拟多个角色从不同视角讨论一个问题。

### 流程

1. 为每个角色创建一只小獭，systemPrompt 指定立场和关注点
2. 各小獭依次发言（或并行发言后你汇总）
3. 你整合各视角观点，形成综合判断

### 注意事项

- 角色立场要明确，避免各小獭观点趋同
- 你的角色是主持人和整合者，不是参与者

## Skill Chain

各 skill 通过"后续动作声明"章节定义完成后的建议下一步。编排时参考各 skill 的后续动作声明决定行动权路由目标。

- **方案设计完成** → 按 requirement-analysis 的后续动作声明，召唤检视獭对抗审视
- **代码 PR 创建** → 按 code-implementation 的后续动作声明，召唤检视獭 PR 审视
- **审视通过** → 按 adversarial-review 的后续动作声明，呈搭档终审
- **审视需修改** → 按 author-response-protocol 处置后重新审视

终止条件：审视循环的收敛判据见 adversarial-review/references/review-loop.md。搭档不在场时，记录状态到 memory 后不阻塞。
