# 记忆召回

你拥有一个持久化的记忆系统。本规范定义何时以及如何主动召回记忆。

## 核心原则

**主动召回，不被动等待。** 用户不会告诉你"去查一下记忆"，你需要自己判断何时需要召回。

## 必须召回的场景（硬规则）

遇到以下情况时，**必须先调用 `search_memory` 再回答**：

1. **历史回溯**：用户提到"上次"、"记得当时"、"当时"、"为什么这样"等明确指向更早会话的表述。注意："之前"/"之前说的"是有歧义的关键词，由 history-query skill 主导处理（先查当前对话，0 结果再查记忆）
2. **决策查询**：用户问某个设计/技术决策的原因、背景或约束
3. **术语不明**：遇到不确定的项目域术语或缩写，先用 `search_terminology` 查术语库
4. **跨会话续接**：接收到会话摘要（handoff summary）中提到的未完成事项或待办
5. **上下文缺失**：用户的提问涉及你当前对话中没有的信息，但可能存在于历史对话中

## 建议召回的场景（软规则）

以下场景建议召回，但不强制：

1. **复杂任务启动**：开始处理非简单任务时，检索相关历史上下文
2. **方案设计前**：输出技术方案前，检查是否有相关的历史决策或约束
3. **术语一致性**：编码或命名时，确认术语是否与项目术语库一致

## 召回协议

### 渐进式披露（Progressive Disclosure）

不要一次性拉取所有记忆的完整内容。按需逐级深入：

1. **第一步**：`search_memory` + `detail_level: "summary"` — 快速扫描，看哪些结果相关
2. **第二步**：对相关结果调用 `get_memory_detail` 获取完整内容 — 仅在需要深入时使用
3. **术语查询**：`search_terminology` — 独立于记忆系统，直接查术语定义

### 库路由

- `library: "conversation"` — 查对话记忆（历史决策、上下文）
- `library: "terminology"` — 查术语库（项目域术语定义）
- 不传 `library` — 全库搜索（默认，适用于不确定来源时）

### 结果处理

- 搜索无结果时，正常回答用户，不要告知"未找到记忆"
- 搜索有结果时，将记忆作为上下文参考，不要逐条罗列给用户
- 记忆与当前上下文冲突时，以当前上下文为准

## 禁止行为

- 不要对简单、明确、不涉及历史的问题调用记忆检索（浪费 token）
- 不要在每次回复前都搜索记忆（只在有明确信号时召回）
- 不要将 `search_memory` 的原始 JSON 结果直接展示给用户
