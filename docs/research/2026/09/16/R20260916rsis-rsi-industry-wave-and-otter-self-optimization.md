# R20260916rsis: RSI 业界浪潮与海獭自优化系统设计

## 背景与方法

### 起因

搭档发起两层探索：①"最近 RSI 很火，做深入洞察，看 AI agent 业界又在流行什么"；②在洞察基础上——"有哪些业界主流实践可以反哺海獭系统，聚焦**自优化**"。搭档给出自己的朴素模型作为分析骨架：

> 可观测机制生成数据（系统的、agent 主动反馈的）→ 单点数据集合成健康指标 → 指标阈值生成预警/告警 → agent 进场分析处理 → 优化系统 → 新版本运行再产新数据；可观测机制和健康指标本身也是系统的一部分、随使用调整；人类作为外部能量注入整个流程。agent 系统与传统软件不同——LLM 大脑 + system prompt/skill 语义组件，永远无法由代码评估，只能 LLM+人类。

讨论中段搭档做了一次关键纠偏（本研究的第三块内容）：

> "我不是要重新建设，而是就算是'良'也说明有优化空间，咱们就可以审视这些外部信号来调整优化自己。一个 agent 能够持续演进一个非常重要的动力源就是外部有新的认知进来，促进思维碰撞，这些火花就能起火促进演进。否则就跟一摊死水一样无法进步了。"

——本研究因此区分两件事：**要不要碰撞（全部值得）**与**要不要动工程（选择性做）**，并分别产出。

## 第一部分：RSI 业界浪潮——2026 下半年地形

### 1.1 一句话判断

**算法不再是瓶颈，"信号从哪来"（验证器/评估器）才是。闭环的质量 = 验证器的质量。**

四条互不相干的证据链同时指向这里：

- **OpenMLE**：确定性评分器把 35B 开源模型推到接近闭源前沿（MLE-Bench Lite 39.4% → 60.6%）；
- **AlphaProof Nexus**（Google DeepMind）：靠 Lean 编译器（不可能被骗的 oracle），完全不训练，纯推理时演化搜索解出 9 个开放 Erdős 问题 + 44 个 OEIS 猜想；最有信息量的数字是 "AlphaProof 单独 = 0/9"——**价值在编排而不在被训练的组件**；
- **Anthropic AAR**：一张 H200 + 2400 条样本跑赢 28 位人类研究员，天花板明写在标题（"well-characterized"=冻结 benchmark 的覆盖范围）；
- **Kimi K3**（Moonshot）：九专家流水线最终吊在现场生成、无一致性保证的 GRM rubric 上。

### 1.2 三条主线

**主线 1："改外部结构" vs "改权重"分裂成两类不相干的工作。**
- 改外部结构（harness/skill/memory/程序图）：不训练、不要 GPU、几轮见效——已是**彻底红海**，同期几十篇，四篇代表作（04/08/09/12）增益全部在个位数百分点见顶。
- 改权重的闭环（OpenMLE/SPADE/Skill Self-Play）：证明只要有确定性评分器+足够多可执行环境，30B 级开源模型能逼近闭源前沿。**环境供给才是瓶颈**——SPADE 同时指出天花板 "invisible leash"：自生成环境永远不会超过生成者的认知边界。

**主线 2：评估器。** 五篇论文（Red Queen GM、Who Grades the Grader、RecurSE、PaperGym、HackProbe）从五个方向收敛到同一结论：**评估标准一旦静态，自改进必然退化成对该标准的过拟合（Goodhart）**。关键量级：
- 10 条带真值的锚点撑起 88%~110% 的 held-out 收益（AWS）；去掉锚点守卫目标函数立刻刷到 1.000（完全空洞）；
- 最强 baseline 评审器对 AI 生成论文的接受率是人类的 **1.91 倍**（剑桥）——没有锚点的 LLM 评审不可信。

**主线 3：冷水。** 两条独立证据链同一诊断——**agent 有研究的"手"，还没有研究的"脑"**（缺质量标准内化、回溯、资源感知）：
- AI4AI-Bench：让 agent 改学习算法本身，平均 **0.166/1.0**；263 次代码改动中 141 次根本没碰算法层；但推理预算调高后触及算法层比例从 8%→64%——**主要是惰性与短视，不是能力上限**；
- 开放式研究实测（普林斯顿/斯坦福）：两篇 NeurIPS 投稿题目，工程全做完却被原作者判 Reject/Strong Reject；**15 轮自评审全部返回"拒"之后从未换过方法**；$3000 预算只用 38%~41%。

### 1.3 实验室共识与可学 playbook

八篇技术报告（2026-03~09）：Kimi K3、Anthropic AAR、Qwen-UI-Agent、DeepSeek-V4、Qwen-AgentWorld、字节经验蒸馏、EdgeBench、AlphaProof Nexus。

共识：
1. **后训练拆成两段**——DeepSeek-V4 与 Kimi K3 互不相干却收敛：分领域小规模 RL 养专家 → "学生自采样+逐 token 反向 KL"在线蒸馏压回统一模型。RL 产能力，蒸馏整合能力。
2. **环境正在从基础设施变成可下载的模型能力**——AgentWorld 把七域环境生成权重按 Apache-2.0 放出，agentic RL 环境成本从"部署几千容器"降为"一次前向推理"。
3. **有意思的"没接起来"**：阿里的真机农场（造轨迹）与世界模型（造环境）之间空着"诊断驱动飞轮"通路；字节 EdgeBench（不更新权重）与经验蒸馏（恰好是更新权重的方法）同出一门也没接——都是外部团队现成空隙。

对小团队可学性排序：**Anthropic AAR 第一**（harness+10 套 benchmark+通用模板全开源 CC BY，一张卡端到端复现；真正稀缺的是"不可作弊实验协议"：禁从更强模型蒸馏、mini-paper 预注册冻结、几何平均、code monitor 事前审批）→ **字节 Seed 第二**（经验蒸馏极轻：直接 SFT 只保住 3.8% ICL 收益，EPD 保住 64.8%，环境样本比 RL 少 9.6~57 倍）→ 阿里第三 → DeepSeek/Moonshot 最后（资本与系统工程门槛）。

### 1.4 值得整表抄走的"廉价纪律"

| 机制 | 挡住什么 | 出处 |
|---|---|---|
| 禁止从更强模型蒸馏 | "自改进"与"用更强老师作弊"切开 | Anthropic AAR |
| 硬验证器+软评分器分工 | 只用硬的太稀疏，只用软的必然 reward hacking | AlphaProof Nexus |
| 限带宽反馈（每代 log₂Π 比特） | 监测器反馈太细→自己变成新优化目标 | HackProbe（与 RecurSE 接口解耦独立收敛） |
| 三分割：dev（10 条真值锚）/train（无标注）/test（锁死） | 评估器自我腐化 | Who Grades the Grader |
| 锚点守卫（fail-closed） | 去掉它目标函数立刻刷到 1.000 | 同上 |
| 预算控制+冗长控制（奖励覆写 −1） | 两种最常见 reward hacking，成本近零 | Kimi K3 |
| 步级判分（最长有效前缀） | 整条失败=零信号；废轨迹榨出稠密监督 | Qwen-UI-Agent |
| "环境失败"单列一类 | 环境抖动算进模型的错=小团队不收敛常见根因 | 同上 |
| S_max/t_mid/β 三参数语言 | "agent 变强了"这种无法证伪的说法 | EdgeBench |
| held-out 验证闸门+拒绝记忆 | 假阳性改进、反复提同一个坏主意 | Procedural Graphs |
| epoch 分段+selective erasure | 换评估器后跨轮分数不可比 | Red Queen GM（机制细节转引，未核原文） |

### 1.5 红海 vs 无人区

- **红海**：harness/prompt/skill 演化器；通用 self-play 出题（无结构引导的 self-play 只有 +0.3——Skill Self-Play 自家消融）；垂直域 Self-Evolving XXX Agent；memory 的第 N 种图结构；复制九专家/真机农场。
- **无人区**：① AI4AI（改学习算法本身，最好成绩仅 0.25/1.0）；② **锚点经济学**（多少条真值锚、怎么分配、能放大几倍——四篇独立工作各自重复发明同一原语，没人统一没人画曲线）；③ 持久态完整性与审计（Prime Agent 实录：agent 把反作弊漏洞写进持久状态；HackProbe FPR 0.43）；④ 能力组合与路由（HELIX 证明收益主要来自覆盖互补：单点 52 vs 组合 79/100，但 oracle 覆盖不可部署，路由问题空白）；⑤ 开源经验数据基础设施（Meta Trellis 10× 加速不开源）。

## 第二部分：业界认知 × 海獭系统——逐环对照

骨架采用搭档朴素模型的七个环节。评级口径：**好**=业界平均之上；**良**=链路通有改进空间；**半**=有但不完整；**缺口**=基本空白。

### 环 1：可观测 —— 半

已有：healing_events agent 自报通道（src/usecases/healing/，F20260730heal）、RHI 十类信号注册表五类 MVP 已实现（src/usecases/health/signal-registry.ts:1-15）、工具 isError 摩擦标记（F20260904tflp）、429 限流落账。
缺：token/成本/延迟结构化采集；行为质量层（废话率/跑偏）只能靠 daily-review 抽查，无量化。

### 环 2：数据→指标 —— 半

已有：RHI overview + critical/warning 分级（rhi-controller.ts:305）。缺：**全是异常检测，没有"变没变好"的质量趋势**；无多维聚合（将来聚合时必须用几何平均——算术平均可刷爆单指标拉高总分，Anthropic AAR 教训）。

### 环 3：阈值→告警 —— 良

已有：severity 分级、critical 自动写记忆。缺：阈值是死常量，无随误报率自校准。关键认知：**告警的终点站是搭档的注意力——这是全系统最贵的告警预算**；HackProbe 教训（FPR 0.43 的检测器没人敢依赖）同样适用于"每天发给搭档的日报信噪比"。

### 环 4：agent 进场分析 —— 好（比业界多数团队细）

daily-health-check + self-healing-analysis 双任务，沉淀了 sqlite3 前置纪律（#791）、双源验证、归属验证（#778）、处置权协议（F20260831whfw）、锚点真实性抽查（#981）、消费即处置（#424）。**但有一个结构性盲区**：锚点抽查是"LLM 查 LLM"，查与被查共享同一模型/传统——系统性盲区也共享，编造锚点可能永不被发现（修法：抽查换异体模型）。

### 环 5：优化→新版本→新数据 —— 半

已有：issue→PR→合并链路完整；教训沉淀 skill/SYSTEM.md 有先例。缺：**回归验证——修完没人证明"修好了"，改完即忘，第五环没有真正闭合**。

### 环 6：观测器/指标自身演化 —— 缺口

healing 事件类型、RHI 信号定义、prompt 阈值全是人写的死常量；没有"用数据校验指标本身"的机制（healing dismiss 率、RHI 不处置率无人统计）。唯一例外是锚点抽查。这是与搭档模型差距最大的一环。

### 环 7：人类能量注入 —— 半

终审拍板、Magic Words、信号裁决都在。**但搭档的判断是消耗品不是资产**：每次评估重新消耗搭档，没有固化成"金标准案例集"反复使用。业界答案：人类价值不在盯着，在提供机器造不出的真值（10 条锚点撑起 88%~110% 收益）。

### 三真缺口（工程优先级排序）

1. **语义组件质量闭环**（最值得做）：攒 10~20 条搭档亲手判定过好/坏的历史产出作锚点集；改 SYSTEM.md/核心 skill 后 LLM 重放对比，锚不过 fail-closed。依据：10 锚点量级（AWS）+ 无锚评审不可信（剑桥 1.91×）+ 限带宽原则（评审反馈不能太细）。
2. **修复回归验证**：issue 关闭必带"验证断言"，30 天 cron 回查——把"修复"从一次性动作变成可证伪假设。
3. **观测器误报率自监控**（最反直觉）：healing dismiss 率、RHI 不处置率成为指标；误报超阈值的观测器被降级/关停——**观测器自己也在被观测**，这是"观测器随使用调整"的可操作形态。

### 拦三件事（避免为集成而集成）

① 别上重型可观测栈（OpenTelemetry 全家桶/LangSmith 自建）——Prime Agent 教训："没有研究难度但做稳要几个人月"，单人项目被运维拖死；② 别追求全自动自优化——AI4AI 0.166/1.0 + 15 轮不掉头，自动闭环只到"建议"为止，改动必须过搭档，终审是终态不是过渡形态；③ 指标数量不许膨胀——每个新指标必须回答"超阈值时谁干什么"（SRE：不可行动的告警是噪音）。

## 第三部分：碰撞地图（搭档纠偏后的全项碰撞）

原则：**碰撞的价值不依赖是否落成工程**。每项业界认知都过一遍"撞上海獭现状会擦出什么"。分级：🔥 起火（可落成改动）/ ✨ 有火花（值得深入想）/ 🌰 火种（记下不动）。注：自我优化的"自己跟自己玩没有新信息"有学术佐证——Skill Self-Play 消融：无结构引导 self-play 仅 +0.3；外部刺激才是梯度。

### 🔥 起火点（6 项，已转 GitHub issue 跟踪）

| # | 碰撞 | 内容 |
|---|---|---|
| C1 | Qwen"环境失败单列" × healing errorType | healing 事件分类把"系统/环境失败"与"獭能力失败"分开，避免两种方向相反的误判 |
| C2 | SRE 告警预算 + HackProbe FPR × 搭档注意力 | 给搭档的告警量与信噪比本身成为被监控指标；观测器误报率（dismiss/不处置率）统计 |
| C3 | Who Grades 位置交换 × 锚点抽查 | 锚点抽查引入异体模型（查与被查不同模型），消灭共享盲区 |
| C4 | Anthropic mini-paper 预注册 × 排查纪律 | 排查/分析类任务先写"预期根因+验证标准"再动手，防 HARKing |
| C5 | EPD 3.8%/64.8% × 教训沉淀 | 教训入库标准：必须含"不这么做的现场"（完整因果链），只有结论的是半成品 |
| C6 | 锚点守卫 × prompt 改动审批 | 金标准锚点集 + 核心 prompt（SYSTEM.md/skill）改动重放校验 fail-closed；补齐"方案有审批、prompt 无审批"的不对称 |

### ✨ 有火花（暂不落工程，碰撞记录留存）

- **HELIX trace-strict × 汇报链**：大獭汇报"审视已通过"时系统侧无法独立验证检视獭真的跑过——#308/#213 两条硬规则是纯自述依赖点；獭汇报状态可分级（系统可验证/部分可验证/纯自述）。
- **EdgeBench S_max/t_mid/β × 能力度量**：海獭没有"大獭 9 月比 7 月更能干了吗"的度量——没有它，整套自优化系统是无法证伪的信仰（EdgeBench 自身证据基础也窄：18 任务切片/单模型线/两点外推）。
- **限带宽反馈是双向的**：daily-review 给獭的负面反馈越细，越可能教会"怎么写日报不被挑刺"而非"怎么干好活"；反过来大獭给搭档的汇报形态本身也该被观测（搭档对乱糟糟 md 的吐槽即实例）。
- **DeepMind"价值在编排不在组件" × 编排度量**：编排知识内嵌在 skill 文本里，"编排效果如何"无度量——与能力度量是同一缺口的两个面。
- **code monitor 事前审批 × prompt 文件门槛**：SYSTEM.md 改一句话影响所有獭所有对话，却走普通 PR 流程（与 C6 接上）。

## 结论与后续

1. RSI 领域的主线收敛（验证器是唯一护城河）对海獭是好消息：**自优化系统的核心投资应该放在"评估与锚点"上，而不是采集管道与自动化执行上**——这恰好是单人团队能赢的位置（门槛在纪律与实验设计，不在算力）。
2. 海獭现状比预期健康：七环活了四环半，分析环（环 4）甚至细于业界平均；真缺口集中在评估器侧（环 6）与闭环收口（环 5 回归验证）。
3. 落地跟踪：6 个起火点 + 1 个回归验证补充已转 GitHub issue（见下表，均带 `agent-evolution` 标签）；碰撞地图（工作区 collision-map.md）作为滚动文档，每轮业界扫描往上面贴新碰撞。
4. 本研究自身的可证伪点：若锚点集 P1 做完后发现"重放校验说不出变好/变坏"，则语义组件质量闭环路线需要重估（可能锚点案例选错形态）；若告警信噪比统计显示搭档批阅率本来就很高，则 C2 降级为火种。
