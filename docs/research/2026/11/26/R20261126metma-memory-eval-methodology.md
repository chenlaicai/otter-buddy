# 记忆评测方法论沉淀：快照评测、双獭盲标与参数网格

## 先说人话：这份文档留的是什么

今天（2026-11-26）我们给记忆检索做了一次从头到尾的体检：先在干净的数据库副本上重建了一套「考题」（20 条真实查询 + 两只海獭独立打分的标准答案），再用它量出检索每一层的表现，最后扫了 25 组参数找出更优组合（已切换上线，见 F20261126swtch）。这篇文档把**怎么测的**完整留下来——下次再要标定参数（比如候选池加深到 50）、或者怀疑检索变差了，不用重新发明流程，直接复用 `scripts/` 里的九个工具。

三个贯穿全程的纪律，是这个方法最值得留的部分：

1. **证据与推理分离**：哪些记忆是「标准答案」不由写评测的人判，由两只独立的海獭按指南盲判，打分一致性（Kappa）达到 0.8544（门限 0.6）这批答案才可用。
2. **分层归因**：检索不好用不是一个笼统感受——「答案根本没进候选池」（漏召回）、「进了池被排出去」（排序压出）、「排进去了但最终没返回」（组装截断）是三种不同的病，药方完全不同。
3. **同基线确定性**：固定快照、跑完恢复权重、复跑方差必须为 0——否则你看到的「提升」可能只是抖动。

## 一、评测快照制作（phaseb-eval 前置）

- **快照 = 清理前备份的副本 + 对副本执行同款清理**。直接用脏快照会让 vec 池被死候选稀释，违背「与当前数据一致」口径。备份原件与活库只读不碰。
- **两个必踩坑**（已写进脚本注释，再踩就是没读文档）：
  1. `loadSqliteVec(db)` 必须在构造 repository **之前**调用——`checkVecTable` 探测失败会静默关闭 vec 路径（评测退化成 FTS-only 而不报错）。
  2. `localModelPath` 指向 models/ **父目录**（embedding-init 内部自己拼 `bge-m3`；指到 `models/bge-m3` 会拼重报找不到 config.json）。
- 快照库不进 git（4.6G）；重建流程 = 清理备份（`data/otter-buddy.db.bak-vec-hygiene-*`）→ 复制 → apply 孤儿清理。**清理备份的回收时点必须晚于「沉淀后的评测资产能独立重现验证」**（已与搭档确认后移）。

## 二、真实查询采样（sample-queries.mjs）

- 从快照 `search_query_logs` 抽真实查询（非人造查询——人造查询会无意识地贴合检索器的关键词习惯）。
- 分层贪心覆盖：每场景标签保 2 条 + 哈希序固定补齐（哈希序 = 可复现，重采样 queryId 序列逐条一致）。数据现实：关键词式查询日志 eligible 仅 51 条，cross-conv/confusable 两类无自然样本——**如实注明，不硬凑**。
- 保留查询发生时最近 3-5 条上下文（判「当前对话优先」场景需要）。

## 三、双獭盲标（render-workbench / merge-labels / kappa-calc）

流程链：**修指南 → 渲染盲标池 → 双獭独立标注 → 机械校验 → 加权 Kappa ≥0.6 质量门**。

1. **指南先行**（blind-label-guideline.md）：0-3 级定义（3=直接证据/2=相关/1=边缘/0=不相关）+ 7 类场景判定 + 纪律条款（判内容不判格式、旧条目按「是否仍为最新有效结论」判、截断按可见部分取低值）。指南是规则不是答案。
2. **乱序渲染**：候选以 #短码 呈现（q-idx.json 记录短码↔entryId 映射——**映射真相源**），标注者看不到来源表/检索路。池 = K=20 两路并集 ∪ slate-only 兜底（anchor 直通条目不经池也须可标）。
3. **独立标注**：两只獭（异模型，完全隔离——不交换任何判断），各自输出全量分数。
4. **机械校验**：每查询键集与池全集完全相等（无增删）、0-3 整数、查询全覆盖。merge-labels/kappa-calc 内置；池文件缺省时从 q-idx 映射推导池全集（映射覆盖池全集是渲染期不变量）。
5. **质量门**：二次加权 Cohen's Kappa（quadratic weights，w=1-(i-j)²/9）≥0.6 才可用。本次 κ=0.8544（完全一致 68.7%，±1 内 96.6%，无方向性偏移）。<0.6 时修指南重标，**不用分歧数据调参**。
   - 实现陷阱记录：一致性权重（对角=1）必须配公式 κ=1−(1−P_o)/(1−P_e)；套错约定公式会算出荒谬负值。
   - 标注可见性边界：盲标池只覆盖 k20 并集∪兜底，池外漏召回测不到——**真实 r_pool ≤ 测量值**，报告必须注明。
6. 搭档抽查约 10 条（R20261126amrca 既定，本轮未执行抽查——20 查询全量由双獭覆盖，抽查条款留给更大样本轮次）。

## 四、指标与双口径 r_pool（metrics-calc / fused-pool-recalc）——本次最重要教训

- gold = 双标均判 3（严格口径）；敏感口径（任一判 3）做对照。连续 gain = 双标均值。
- 指标集：r_pool、r_slate、recall@5/10、MRR、nDCG@5、延迟分解（embed/FTS/vec/total，中位+均值）。no-gold 查询排除出 r_* 与 recall 聚合并注明。
- **双口径教训**：r_pool 的「池」必须定义在**融合过滤之后**。
  - 原始并集口径（fts∪vec 原始候选）：k10=0.60 / k20=1.00——**高估**。
  - 真实融合池口径（vec 候选过 vecSimilarityThreshold 门后）：k10=k20=ftsonly=0.40——这才是检索层真相。
  - 本次就是被原始口径的「k20 r_pool=1.0」诱导过先导解读，审计后才修正。**任何「池」指标先问：过滤发生在算池之前还是之后。**
- r_slate≈0 的结构性成因：gold 均值 11 条 vs slate 10 槽——多证据场景装不下是「证据真的多」而非纯误伤；Phase D（组装层优化）立项判断要区分这两者。

## 五、阈值杀伤审计（vec-threshold-audit.mjs）

vec0 虚表默认 **L2 距离**；`vecSimilarityThreshold` 语义是 `(1−distance)≥threshold`，对归一化向量等价 **cos ≥ 0.5 + threshold/2**（t=0.3 → cos≥0.65）。bge-m3 在本语料的 gold 相似度典型 0.55-0.65——门设 0.3 时 vec 路过门率 ≤4%，96.4% 可及 gold 被杀。审计方法：绕过门控直接取 vec50 的 distance 分布，对照 gold 标注统计「能被 vec 找到但被门杀掉」的比例。这一步把「语义检索没在工作」从体感变成带 file:line 的机制定位（search-engine.ts filterVecHitsByThreshold）。

## 六、参数网格（phasec-grid.mjs）

- 组合空间：阈值 × vec 池深 × 消息半衰期（+ 现状同进程对照）。每组合全链路真实 search（RRF→rerank→dedup→quota→slice），**组合级权重恢复**（防频率信号跨组合污染），embedding 缓存共享。
- 验收门槛（R20261126amrca）：合成回归不退化；真实集 recall@10/r_pool 不下降；nDCG@5 或 MRR 稳定提升；延迟无明显回退；**没有明确赢家就保留默认值**。
- 本次结果：25 组合方向一致（阈值放宽+半衰期放缓全面提升），h14 全门槛通过当选；h21 真实集更优但 golden nDCG10 擦线低于地板出局——**门槛真的会否掉看起来更好的选项，这套门槛有牙齿**。
- 半衰期安全性专项（复活检查）：h7→h21 复活条目全部 ≤30 天、零 superseded 旧结论复活——区分「近期条目被压过狠」与「老古董复活」两种完全不同的问题。
- 确定性纪律：同基线两次重跑必须全等（本次 PASS）；跨基线 ±0.006 级漂移是**基线行为变化**的信号而非工具抖动——#2062 的 vecCandidateLimit 接线改变了 q3 并列分数条目的 tie 环境（两路召回不变）。工具恰好能捕捉这类变化，这正是它的价值。

## 七、工具清单与用法（scripts/，均已验证）

统一参数：`--repo-root`（默认脚本上级推导；需 build 过的 repo，含 dist/ 与 node_modules）、`--snapshot`（只读快照库）、`--eval-dir`（数据目录）、`--models-dir`（默认 `<repo-root>/models`）。归档样本在 `docs/research/2026/11/26/metma-data/`（无正文）。

| 工具 | 用途 | 关键用法 |
|---|---|---|
| sample-queries.mjs | 真实查询分层采样 | `--snapshot --eval-dir`；哈希序可复现 |
| phaseb-eval.mjs | 主评测（3 配置全链路 + 盲标池组装） | `--rerun-baseline <runs.json>` 方差=0 验收 |
| render-workbench.mjs | 盲标池乱序渲染 | 产出 q*.txt + q-idx.json |
| merge-labels.mjs | 标注分片合并校验 | 输入 labels-A-part*.json |
| kappa-calc.mjs | 双标一致性 | 归档数据复算 κ=0.8544 ✓ |
| metrics-calc.mjs | 指标计算 | runs 含正文不进 git，`--runs` 指定 |
| vec-threshold-audit.mjs | 阈值杀伤审计 | 只读库，不动权重 |
| phasec-grid.mjs | 参数网格 25 组合 | 组合级权重恢复 |
| fused-pool-recalc.mjs | 双口径 r_pool 重算 | 阈值放宽模拟 |

复算示例（无需任何含正文文件）：
```bash
node scripts/kappa-calc.mjs --eval-dir docs/research/2026/11/26/metma-data
# → κ=0.8544，与 2026-11-26 评测完全一致
```

## 八、边界与未决

- **20 条真实查询是小样本**：组合间 ±0.03 级差异低置信；结论方向（25 组合同向）高置信，逐组排序不保证。
- **标注可见性**：池外漏召回测不到（真实 r_pool ≤ 测量值）；扩池验证需先扩盲标池重标。
- **golden 的盲区**：合成回归是 FTS-only mock 口径，阈值维度测不到——阈值类改动只能靠真实集网格 + 未来真 Vec capability 评测覆盖。
- **K=50 未决**（R20261126amrca 问题 #4）：t=0.1 时有 8.1% gold 独占增量、t≥0.2 时为 0；参数切换稳定后单独验证，届时直接复用 phasec-grid + 盲标流程。
- **时点回放局限**：历史查询重放时，晚于查询创建的条目也参评（ageDays 为负）——严格时点回放需要按查询时间裁剪快照，本轮未做，结论解读时已知。
