## 2. 业界方案盘点

### 2.1 Apple：Liquid Glass 是原生材质，web 无官方方案

Apple 官方文档（Liquid Glass 技术概览，2026 抓取，逐字引文见附录 A）的定位与原则：

- Liquid Glass 是「跨 Apple 平台的动态材质，结合玻璃光学性质与流动性」，实现层是 **SwiftUI/UIKit/AppKit 的标准组件**——原生渲染管线（系统合成器）提供，非 web 技术。
- 官方设计原则（HIG）**正面印证搭档对问题 2 的直觉**：「Be judicious with your use of color in controls and navigation so they stay legible and allow your content to infuse them and shine through」——玻璃/染色只用于**控件与导航层**，内容区保持克制让背景透出来；标准组件自动获得材质，自定义元素按需局部施加。（机制推断，中：Apple 桌面层表面下基本无持续高频动画，其原生玻璃无本项目等效的「每帧重采样闪动」触发场景；无论合成器逐帧输出还是采样源静止，结论同向。）
- 官方对存量应用的路径是「采用标准组件 + 遵循 HIG 最佳实践」，不是自己从零搭玻璃效果。

**web 端的现实**（webkit.org 官方博客 Safari 26 beta #16993 / Safari 26.0 #17333 两篇，一手原文，逐字引文见附录 A）：

- Safari 26 系列没有任何「Liquid Glass for web」API。唯一相关条目是「The ability to applying backdrop-filter to content behind a transparent webview」——即允许网页的 backdrop-filter 采样到 webview 之外的系统桌面。这是采样范围的放宽，**不是提供系统级玻璃材质**。
- 两篇清单均未提任何新的玻璃/模糊类 web CSS 能力——除上述条目外，关键词检索仅另命中一处 "backdrop root" 术语（view-transition 修复项，非玻璃能力）；blur/glass 零命中。

**结论**：「苹果官方方案」在 web 上不存在；web 端能做到的玻璃上限就是 `backdrop-filter`（效果）+ 自界设计学说（稳定性）。苹果在 web 端给的答案是「用标准 web 能力自己组合」，苹果自己的「官方方案」只属于原生 App。

> 附注（机制解释两说并存，均中置信度、未实机验证，无论何者成立本文结论不变）：解释一——Apple 桌面层（桌面/Launchpad/Dock）基本无持续高频动画，采样源静止故无重采样闪动；解释二——原生材质由系统合成器逐帧统一输出，不存在 web backdrop-filter 的「采样失效→重建」间隙。两解释指向同一个工程启示：web 端无法复制任一机制，只能靠 R→0（静态采样源）达成严格不闪。如需实证可后续真机录屏逐帧比对。

### 2.2 Windows：Mica/Acrylic 双材质学说——业界最早的系统性答案

微软在 Fluent 设计体系里把「模糊材质」拆成两种，各自的适用边界写得极其明确（learn.microsoft.com 官方设计指南原文）：

**Mica（不透明基底材质）**：

- 「Mica is ideal as a **foundation layer** in your app's hierarchy」——只作**基础层**，采样**桌面壁纸**提取主色调，合成**静态**的着色底。
- 两层学说：「apply Mica as the base layer of your app and add an additional content layer that sits on top of the base layer. The content layer should pick up the material behind it, Mica, using **LayerFillColorDefaultBrush, a low-opacity solid color**」——内容层不用模糊，用**低不透明度实色**叠在 Mica 上。
- Mica 无持续重采样：壁纸不常变，着色一次性合成，永不闪。

**Acrylic（透明采样材质）**：

- 官方明确「**Avoid layering multiple acrylic surfaces**: multiple layers of background acrylic can create distracting optical illusions」——**多层亚克力叠加会产生干扰性光学错觉**。这与本次闪动同构（我们不但多层，还嵌套采样）。
- 「For vertical panes or surfaces that help section off content of your app, we recommend you use an **opaque background** instead of acrylic」——垂直面板（侧栏！）建议用**不透明背景**，不用亚克力。
- 「Rendering acrylic surfaces is GPU-intensive」——GPU 密集、耗电，省电模式自动关闭。
- 瞬态面（菜单/弹层）才推荐采样材质：保持与触发内容的视觉关联。
- 微软从 Win10 Acrylic 时代就因滚动闪动/性能被骂（社区共识，训练知识，**未交叉验证**），Win11 Mica 正是把「采样壁纸」从「采样内容」中拆出来的一次架构级修正。

## 3. 第一性原理：闪动的本质

### 3.1 本质定义

`backdrop-filter` 不是「贴一张模糊图」，而是**每帧对下层像素实时重采样**。定义三个独立变量：

- **R（重采样）**：下层有像素变化 → 玻璃面输出必然变化。
- **C（覆盖）**：玻璃面积占视口比例——比例越大，变化越可见。
- **N（嵌套）**：玻璃叠玻璃时内层采样的是外层的滤波输出，下层变化被放大级联。

则：**闪动可见度 ≈ R × C × N**（乘法示意联合削弱，非严格定量）。三者作用不同——**R→0 是唯一严格不闪保证**，C 与 N 只控制可见度与级联强度：

- R→0（下层静止或玻璃改为采样已静止的东西）→ 严格不闪；
- C→小（玻璃只占小面积）→ 闪动低于感知阈（减弱，非消失）；
- N→浅（不嵌套）→ 无级联放大（减弱，非消失）。

### 3.2 三因子对照业界方案

| 方案 | R | C | N |
|---|---|---|---|
| 原生 Liquid Glass | 合成器逐帧统一输出（机制推断，中——§2.1 附注两解释并存，无论何者成立结论不变） | 控件/导航层，小 | 合成器管理，无级联 |
| Windows Mica | 壁纸静态，R≈0 | 全窗口基础层，大 | 单层 |
| Windows Acrylic 指南 | 接受 R>0，但只给瞬态面 | 小面 | 明令禁止多层叠加 |
| 本项目现状（v2.3 体系） | 运行中持续变化 | 顶栏+三栏+气泡全覆盖 | 气泡嵌套采样面板输出 |

本项目的问题不是「玻璃效果做错了」，是 **C 和 N 的设计越了界**——业界全都把大面积+常驻的表面留给静态材质，把实时采样材质留给小而瞬态的表面。

## 4. 收敛：分层材质学说（方案骨架，待搭档拍板后细化设计）

第一性原理映射到本项目的可执行学说——**按「采样源是否静止 × 表面是否常驻大面」分配材质**（本文 L0-L3 为材质分层、自底向上编号，与 F20260724glas 的 L0=顶栏 chrome 编号语义不同，实施设计时须重新映射避免撞号）：

| 层 | 采样源 | 常驻大面 | 材质 |
|---|---|---|---|
| L0 底层 | 壁纸/背景图 | — | **Mica 化**：取图主色静态着色（一次性合成）或微预模糊，永不重采样 |
| L1 面板层（顶栏/侧栏/中栏容器） | L0 | 是 | **低不透明度实色**（LayerFill 模式）；侧栏类垂直面板业界明示用不透明 |
| L2 内容层（气泡/卡片） | L1 | 是 | 实色卡片（可带身份色染），**去 backdrop-filter** |
| L3a 菜单/浮层（小瞬态面） | 内容 | 否 | **真玻璃保留**——业界一致认为小而瞬态的面正适合采样材质（与内容保持视觉关联） |
| L3b 弹窗 scrim（全屏大面） | 内容 | 是 | **不回推实时采样**——维持六轮终局语义（F20260909scrf6：modal-open 内容自模糊 + scrim 静态暗化）；全屏面按本文公式 R>0 × C 大必闪，不得并入「小瞬态」 |

配套原则：

1. **玻璃全局占比大降**（直接回应问题 2）：常驻大面不再是大玻璃，玻璃只出现在瞬态层与局部强调面。
2. **闪动免疫**：L0-L2 常驻层与 L3b 弹窗 scrim R=0（静态着色/实色/自模糊）——不管运行中像素怎么动都不闪；仅 L3a 菜单/浮层保留 R>0，且面积小、不嵌套（减弱可见，非免疫）。
3. --glass-t 透明度滑杆体系保留（控制 L1 实色的不透明度档位），自定义背景与玻璃观感解耦不冲突。
4. 用户看到的「苹果感」来自**层级与材质对比**（画布浮起面板、面板浮起卡片），不来自「处处透明」——HIG 原则「allow your content to infuse them and shine through」。

## 5. 残余风险与开放问题

- **方向变更需搭档拍板**：现行体系哲学是搭档 7/24 亲定的「画布之上全层玻璃」（F20260724glas 用户亲定材质哲学）——本次学说实质修订该哲学（常驻大面退出实时采样），必须搭档点头，不是技术自治域。**呈终审时的已知残差**：L3a 菜单/浮层保留真玻璃（R>0），开在流式内容上仍可能低幅闪动（面积小、不嵌套，处于感知阈附近）；弹窗 scrim（L3b）已归入免疫面，不受此残差影响。
- 主源归因的实机复现未做（Paint Flashing 观测）——新学说下 R→0 覆盖 L0-L2 与弹窗 scrim（常驻面全免疫），不依赖主源归因的正确性，该开放问题降级为非阻塞；**L3a 菜单/浮层保留 R>0，不在此保证内**。
- 「Apple 桌面无持续动画」为机制推断（中置信度），不影响学说成立（学说本身有 Windows 侧独立证据链）。
- iOS Safari 低配机上 backdrop-filter 性能损耗（微软明示 GPU 密集）随玻璃面积大降同步受益。
