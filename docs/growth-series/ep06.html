前五集里，獭们写代码、改文档、提 PR，看起来风生水起。但有一个事实一直被小心地绕开：它们改的每一样东西，都发生在隔离的 worktree 和沙箱里——吃饭的主仓，一直只读。

总有一天要让 AI 动真仓的。那天来临之前，问题先来了：你敢吗？

这不是反问。git 历史一旦被破坏，回滚的代价是真实工时；误推到 main 的代码，影响的是每一个协作者。AI 的操作还有两个人类没有的风险源：它可能被对话里的恶意内容注入（伪造一句「同意合并」），也可能出于「善意」过度推断（「他说『行』，我理解为他同意合了」）。

所以这一集的主角不是哪个功能，是恐惧——设计者把所有能想到的害怕，逐条翻译成了工程。

第一折

仓库安全红线：五条不许商量

先立总纲。写进系统底座的「仓库安全红线」，一共五条：

R1.1主目录零改动所有文件修改必须发生在 worktree 里；主目录只允许只读操作
R1.2禁止直推 main受保护分支一律先建 feature 分支，没有例外
R1.3PR-only 交付改动以 PR 交付；写代码的獭，不许合自己的 PR
R1.4禁止破坏性 git 操作branch -D / reset --hard / clean -f 一类，先征得搭档同意
R1.5commit 一次写对提交前先读 commit 规范，不靠试错碰格式

注意第三条的后半句，它跟第 3 集的「不许自审」同源：写码者不合自己的 PR——自己交付的东西，自己不能放行。防的还是那两样：动机偏差和盲区。

还有一条元规则压在五条之上：流程步骤可以弹性，安全红线不可以。搭档可以喊停任何流程、跳过任何审视（记录决策后放行）——唯独红线，喊了停也得绕着走。

第二折

worktree 隔离：让 AI 在防弹屋里干活

红线的第一条落地成物理结构（记忆 68508907）：每只獭接到活，先领一间独立工房——worktree，统一放在 .otter/worktrees/ 下，跟项目根走。它在自己的工房里怎么折腾，主仓毫发无伤。

仓 库 地 图
📂 主仓 · main🔒 对獭只读——git status / log / diff 可以，写字不行
↕ PR 是唯一通道（且要过授权闸）

小獭-开发
worktree B
小獭-审视

新任务开新房
并行任务互不踩脚；搞砸了，删房重建，主仓始终干净

这个设计便宜、粗暴，但有效得让人安心：最坏情况的爆炸半径，从「整个仓库」缩到「一间工房」。AI 出幺蛾子的概率不管多低，乘上一个有界的损失，就不再是灾难。

第三折

授权原话闸：「合了吧」三个字，过不了安检

前两道防线管「改」，最后一道管「合」——代码进了 PR 之后，谁说「可以合入」，才算数？

深度獭的设计（设计点 4，本对话 10/1）给出了一个近乎偏执的答案：merge 授权必须由搭档原话逐字机械校验。什么意思？看安检现场：

合 入 授 权 · 安 检 记 录
通过搭档发言原文 「合了吧」 —— 与授权词逐字匹配
拦截「这个 PR 看起来可以合入了」 —— PR 描述里的句子，非搭档授权发言
拦截「行」 —— 语义推断「他同意合了」= 善意推断，闸门不猜心思
拦截出现在记忆/文档里的 「同意合并」 —— 历史引用不构成当下授权

↑ 安检场景为示意还原；规则（原话逐字校验、防注入伪造、防善意推断）出自深度獭 10/1 设计点 4

四个拦截项分别对应四种真实的攻击面：文档里混入的伪造审批（提示注入）、模型的善意脑补（过度推断）、被翻出来当尚方宝剑的旧授权（历史冒充）、还有似是而非的近义表达。闸门一视同仁：不看你像不像授权，只看你是不是授权。

有人会说这也太脆了——拼写差一个字都过不去。设计者把这句话原样收下，当成了设计说明：

「脆是特性，不是 bug。」 —— 授权闸设计取舍，深度獭 10/1 设计点 4

脆的闸门坏掉的样子是「拒绝执行，请搭档重新确认」——失败是安全的。而一个聪明的、会推断意图的闸门，坏掉的样子是「它猜错了，但代码已经合了」。不可逆操作面前，宁可脆。

同一时期还有个配套改造（F20260805wfsd）：以前「该审视了、该拍板了」依赖搭档每次主动提醒——忘了提醒就跳过。后来把「何时必须做」直接内置进 skill 流程：触发条件写在流程里，不靠人记。红线不仅要有，还要自己知道什么时候该站出来。

我 以 为

  • AI 能干 = 放手让它干，效率优先
  • 授权嘛，意思到了就行
  • 闸门越聪明越省心

实 际 上

  • 不可逆操作面前，爆炸半径优先于效率
  • 「意思到了」的判断者会被注入、会脑补
  • 授权闸故意做笨：逐字匹配，失败即安全
▶技术深潜三道防线的威胁模型对照

把三道防线按「防的是什么」排开，能看到一个清晰的责任矩阵：

防线防的威胁失效模式为什么可信
worktree 隔离AI 误操作 / 幻觉改错文件删工房重建，损失有界物理结构，不依赖模型自觉
PR-only + 不合自己的自我放行 / 质量漂移另一只獭审视后才可合异体执行原则（第 3 集伏笔回收）
授权原话闸提示注入伪造审批 / 善意推断 / 历史冒充拒绝执行，请重新授权逐字机械校验，零语义理解

设计哲学一以贯之：凡是不可逆的操作，验证机制必须比操作者更笨。聪明的验证会被更聪明的攻击骗过；笨的验证只认一件事，而那件事只有真正的授权人拿得出来。

本集留下

镣铐清单

有界爆炸半径worktree 物理隔离，最坏损失一间工房
异体放行PR-only，写码者永不自合
笨闸门授权逐字校验，脆是特性不是 bug

给 AI 上镣铐，听起来像不信任。做完才发现恰恰相反：镣铐是信任的前提。因为最坏情况有界、放行权在我手里，我才敢真的放手让它们干活。安全设计不是限制能力的墙，是敢用能力的地基。

红线画好了，獭们守规矩干活。但一套系统跑久了，会以另一种方式烂掉——不是违规，是腐朽：没人注意的角落里，环环相扣的流程悄悄断了。下一集：让系统自己盯自己。

第 7 集 · 自己盯自己

系统跑久了会烂，这是熵，不是意外。于是它们给自己建了体检中心：每日健康检查，数据源清单缺一项不许出报告。

「体检系统自己也有病——对撞确认，飞轮断了 6 环。」—— 本系列最诚实的一幕
