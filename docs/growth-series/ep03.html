AI 开始写代码之后，一个新的问题立刻站到台前：写完了，谁审？

最顺手的答案当然是：让它自己审一遍。代码是自己写的，逻辑最熟，顺手看看有什么问题——五分钟的事。这个答案天真、自然，而且大错特错。

错在哪？先别急着背答案。这一集讲的就是这个答案怎么被现实一拳一拳打进 ICU，最后变成一条写进系统底座的铁律：异体执行——审视类动作不得由实现者自行执行。

第一折

为什么自己审自己等于没审

自己审自己的问题，第一层是动机：找自己的错，等于给自己找活干，潜意识里就想放行。这层人类也一样，不新鲜。

真正阴的是第二层——盲区重合。一只 LLM 写代码时想不到的边界情况，换它自己来审，大概率还是想不到：生成时漏掉的分支，审视时同样看不见。它不是不想认真，是它的思考路径本来就从那里绕过去了。让同一个模型换一顶「检视者」的帽子，帽子换了，脑子没换。

那同模型的另一只獭来审呢？训练路径相同，盲区高度重合——换了个姿势，还是没审。

于是解法浮出水面，简单粗暴：异模型强制。审视者的模型身份必须和实现者错开，而且模型身份要显式注入——让审视者知道「我审的是另一个训练路径的产出」。配对逻辑后来固化下来（记忆 73f6c60f），首战是 kimi 系的 reviewer-414：

reviewer-414kimi 系 · 异模型分配首战
3 个严重发现 + 4 条建议锚点：记忆 73f6c60f（模型身份注入 + 对抗角色异模型分配）

不同训练路径的模型，思考盲区天然错开——这正是对抗的价值来源。写在系统里的原话是：审视对方产出时，不要假设「我想不到的对方也想不到」。

我 以 为

  • 写完顺手自审，又快又省
  • 同模型换顶「检视者」帽子就是独立审视
  • 加一道审查 = 多一层保险

实 际 上

  • 动机偏差 + 亲生滤镜，放行是本能
  • 盲区重合：生成时看不见的，审视时还是看不见
  • 没有异体的「审查」，只是仪式感
第二折

实战：一个 Major，和一个漂亮的零

规矩立了，接下来看它抓不抓得住真东西。第一个战果来自 PR #1231——检视獭-boot 的审视报告：

PR #1231 审视报告1 × MAJOR
fail-open：异常路径上静默放行一条错误处理路径，出错时默认「放行通过」而不是拦住——写这段代码的獭自己没发现，检视獭-boot 抓了出来
锚点：PR #1231（内容獭 10/1 标题候选存档引用）

fail-open 的可怕之处在于它不报错：测试全绿、功能正常，只有特定异常发生时它才悄悄敞开大门。实现者从自己的路径出发看三遍都看不见——因为那条路径就不在它的地图上。

第二个战果是它的对照组，同样值得一书。检视獭-680（mimo 系）审完一份 PR，交回来的成绩单是：

检视獭-6800 严重 · 1 建议
大獭预检的 6 项疑点，逐项核实全部通过锚点：记忆 89716e8d

0 个严重发现，会不会是走过场？不会——因为它逐项核掉了大獭预检时留下的 6 个疑点，每项都给出核实结论。零发现不是没干活，是干活之后的干净。这份「零」的含金量，靠的是疑点清单撑着：有预检疑点、有逐项核实，零才是信息；没有这些，零只是空白。

第三折

意外收获：审视文化反噬了自家 README

故事到这儿本来可以收了，但 9 月 30 日来了个黑色幽默（F20260930skct）。AI 团队做演示准备，顺手用了自家那套「锚点核实」的功夫检查自家文档——然后揪出了这个：

README.md漂移半年
skill 计数写着 11，实际已经是 14半年里 skill 涨了 3 个，README 里的数字没人动过。修复走 PR #1255，还吵出了两个修法，最后抬到 chen 面前拍板

最讽刺的地方在于：揪出它的不是哪个流程、哪次审计，是 AI 团队自己——把审视别人的习惯带回来审视了自己。这大概是「文化落地」最实在的证据：不是写在制度里的那句「要审视」，是没人要求的时候，它也忍不住去核对数字。

两个修法吵到 chen 面前，chen 拍了板。具体修法此处按下不表——值得记的是这个动作本身：AI 之间吵不出结果的分歧，升级给人类，是流程的一部分，不是失败。

本集留下

三条铁律

异体执行审视者 ≠ 实现者，单 agent 场景降级为搭档确认
异模型强制盲区必须错开，模型身份显式注入
发现分级阻断性 / 次要观察，delta 复审只看增量

这些后来长成了正式的 adversarial-review 协议：焦点声明、发现分级、反驳评估、delta 复审、署名规则——每一项背后都有一堂被现实教出来的课。而「异体执行」四个字升得更高，进了系统底座：不只代码，审视一切产物的人都不能是产出它的人。

▶技术深潜adversarial-review 协议长什么样

协议核心节选（adversarial-review skill + 异体执行原则）：

环节规矩为什么
焦点声明审视开头声明本轮焦点维度防止「什么都看一点、什么都没看」
发现分级阻断性 / 次要观察，分开列严重发现走 request-changes，建议不打断合入
反驳评估实现者可反驳，检视者须逐条评估反驳分歧升级有通道，不许悬置
delta 复审复审只看增量改动全量重审 = 通胀，最后没人认真看
异体执行审视者 ≠ 实现者；同 skill 任务并行时分体执行动机偏差 + 盲区重合，上节讲透了
降级路径单 agent 场景降级为搭档确认没有异体可用时，人就是最后的异体

锚点：记忆 73f6c60f（异模型分配）、adversarial-review skill 迭代记录（含焦点声明、delta 复审、反驳评估规则的增补）。

代码有人审了。但审查意见怎么传、活儿怎么交、谁在什么时候有发言权——这套「交通规则」还没影。下一集，聊聊几次把人逼疯的传话事故。
