每个系统出生的时候，都揣着创始人的一厢情愿。otter-buddy 也不例外。

2026 年 7 月 8 日，一个新仓库初始化（F20260708r6p5）。在第一行代码之前，chen 脑子里的画面是这样的：

期 望 清 单 · chen 的初始画面（issue #3 §1.1）
一AI 像人一样躺在通讯录里：有名字，有头像，点开就能找
二每个 AI 一个固定聊天框，像微信一样，历史自然沉淀在里面
三活儿大了就拉群，谁在群里谁干活
四没有 issue，没有 session，没有工单号——聊天本身就是干活

注意第四条，它被标了强调色——因为本集后半段，它会被现实请回来喝茶。

这个画面天真吗？天真。但天真也有天真的用处：架构师给它的定性不是「需求文档」，而是「这不是改良，是范式跳跃」。范式跳跃的意思就是：从这往下，每一步都没有现成的路。

第一折

连设计它的架构师，第一天都没搞懂它

要把这幅画面翻译成系统，得先有人把它翻译成架构。issue #3 里，两位架构师进场了。

第一位交付的第一版分析，把这套东西定性为：Chat as Interface——聊天是一种界面。听起来很有道理：聊天窗口嘛，新一代的命令行，本质还是给人看的 UI。

第二位的对抗审视，只坚持了一件事——（下面对白为剧场演绎，论据出自 issue #3 原文）

架构师-2
你把它读浅了。看看业界——ChatGPT、Copilot Chat、Slack Bots，全是 Chat as Interface：聊天是 UI，底层有 session/task/state 管理。但这个系统要的不是皮，是地基。Interface 意味着聊天只是给人看的皮，皮底下还是原来那套任务系统；Substrate 意味着聊天本身就是系统——所有状态都在对话中，所有协作都在对话中。皮换了楼还在，地基换了楼就塌了。

最终定性：Chat as Substrate。而 chen 在需求里其实早就写过这句话，只是当时没人意识到它有多重——

「聊天是大脑沟通，对外的触达则是手脚。」 —— chen 原话，issue #3

聊天不是皮肤，是神经。这是第一折：连负责设计它的架构师，第一版理解都会跑偏。范式跳跃之所以叫跳跃，就是因为专业人士的第一直觉，也会踩空。

▶技术深潜Chat as Interface vs Chat as Substrate：差一个词，差一整套系统

Interface 定位：聊天窗口 = 新版 UI。皮下面还是传统那套：任务、工单、状态机。聊天记录只是「给人看的日志」，系统真正的状态在别处。

Substrate 定位：聊天本身就是系统状态。每条消息都是事实，不可变、只增不改。架构决策 D18（F20260709x7k3）：消息存储 = SQLite append-only，决策理由里白纸黑字写着「消息不可变（Chat as Substrate）」。

一个直观的判断法：把聊天界面关掉，系统还在吗？Interface 派：在，聊天只是壳。Substrate 派：不在了——协作记录、审计依据、记忆系统的原料，全部就是这条消息流本身。

这个定性影响后来的一切：正因为「消息即状态」，记忆系统才有可靠的原料可挖，协作过程才可回溯、可审计。

第二折

「没有 session」的愿望，session 的回归

期望清单里最狠的一条：没有 session 概念。

后来的故事大家都知道了一半：session 还是长出来了。但先别急着宣布打脸——看看它长成了什么形状。转折点是 chen 自己提的两个需求（S1 文档编为 UA-8、UA-9，下面对白基于原话意图演绎）：

chen
聊砸了怎么办？封存已有对话作为反面案例——然后是一个新 AI，接着聊。（UA-8 原话：「封存已有对话作为反面案例、然后是一个新ai」）
chen
不是我新开一个会话，然后把我的问题复制一遍再问一遍。那不是解决问题，那是把复读的活儿甩给我。（UA-9 原话：「而不是我新开一个会话，然后复制我的问题再问一遍」）

于是架构里长出了一对行为规范（B4a/B4b，F20260709x7k3）：用户对回复表达不满 → 封存当前 session、标记为反面案例 → 创建新 session、注入前情摘要、换个角度重新处理。

看清楚：session 长回来了，但它不是你用烦了的那个 session——不是排队叫号的小票，不是上下文断崖。在这个系统里，一段 session 是一段「獭生」：干砸了不删、不覆盖，封存成前世；新的一段带着前情摘要转世，换个角度重来。

这就是期望与现实的第一次和解：「没有 session」没有活下来，但它讨厌的那种 session 也没有活下来。工单式 session 死了，獭生式 session 出生了。而跨 session 的连续性，不靠 session 自己扛，靠记忆系统。

我 以 为

  • 没有 session 概念，聊天连着聊天
  • 历史自然都在聊天框里，随手翻
  • 不满意就继续聊，为什么要「重新开始」这种操作？

实 际 上

  • session 长回来了——但它不是工单，是獭生
  • 干砸了：封存成反面案例（前世），新獭带前情摘要转世
  • session 只保留最近的对话；历史的重量由记忆系统扛
▶技术深潜session 没有消失，它变形了：从 UA-8/9 到「封存 + 叙事交接」

用户意图锚（S1 记录的原话意图）：

编号原话意图翻译成需求
UA-8「封存已有对话作为反面案例、然后是一个新 AI」重启獭生机制的雏形
UA-9「而不是我新开一个会话，然后复制我的问题再问一遍」不丢失上下文

落到架构（B4a/B4b）：用户不满 → 封存 session + 标记反面案例 → 新 session 注入前情摘要 + 换角度重新处理。

后来的演化：这套「封存 + 交接」最终长成正式的 restart 机制——前世 session 封存不可逆，前世记录靠交接档案（引擎叙事合成 + 机械供料）注入新世，谱系可查。小獭退场同理：任务结果经工具返回值传回大獭、存入记忆系统；Session 归档，记忆条目保留。

一句话总结：搭档否定的从来不是 session 这个词，是「工单式 session」那种东西——用完即弃、上下文断崖。獭生式 session 恰恰是他自己设计的。

第三折

出生头两周：不会说话，也不会自我介绍

地基定了，该跑起来了。幺蛾子从不迟到。

幺蛾子一：agent 不会说话。消息模型其实设计得很体面：两层架构——事件层负责流式过程，body 是最终答复（F20260713e8n4）。但实现跑起来才发现一个根本缺陷：agent 根本没有「发言」这个动作，body 从哪来？硬编码——一个字符串，"fixme"。

otter-buddy · 2026-07（示意还原）
fixme
fixme
agent 的最终答复，永远只有一个词

agent 把活干完了，界面上留给你的是一句 fixme。你再问一句，还是 fixme。它不是态度差——它是真的不会说。

7 月 21 日（F20260721spea），speak skill 诞生：agent 在结束前必须主动调用 speak 工具，自己设置最终答复和发言目标。「说话」从此是一个显式的、有规范约束的动作，不是代码跑完顺手漏出来的副产品。（这件事的后劲比想象中大——后来「说话的规矩」长成了整套协议：发言石、行动权……那是第 4 集的戏。）

幺蛾子二：自我介绍翻车。第一只海獭上线，开口第一句：

大獭
你好 chen，我是大獭，你的 AI 编程助手。
chen
打住。

这条自我介绍被当场否决，理由两条（F20260722 身份认知链）：一，定位太窄——这个系统的初衷是陪着处理工作加生活的多场景事务，编程只是其中一件；二，没有人味——日常对话像个模板客服，但又不能反过来油腔滑调。更重要的，是那句后来被写进设计的判断：身份认知不止于自我介绍，还要约束行为。

7 月 22 日起，身份认知体系开始搭建，定位重新确认：大獭 = 海獭团队的首领 + 搭档的工作生活伙伴。

注意「团队」这两个字——这个时候，一个小獭都还不存在。多 agent 从来不是这个系统的初始卖点，它是埋在身份里的演进方向：冷启动「比 ChatGPT 更懂你」，成长期「AI 工作伙伴」，成熟期才是「AI 团队」。你现在读的这篇连载，本身就走在这条第三阶段的叙事上。

▶技术深潜三层记忆模型雏形：为什么「记忆是核心」从第一天就写进了地基

session 只保留最近的对话，那历史去哪了？答案在数据模型（F20260709m2n8）的三层记忆里：

记忆层归属生命周期
工作记忆各 Otter 专有Session 级，只管眼前这段对话
历史对话记忆系统级共享所有 Otter 可检索（UA-14「所有信息通用」）
个人长期记忆各 Otter 专有跨 session 沉淀

一个被砍掉的第四层：原模型里还有「对话备忘录」——每个对话一个共同记忆空间。这层是 chen 想出来的，架构师一开始都没想到（「每个 agent 有各自的记忆空间，那每个对话也有一个共同记忆空间」）。后来小獭的定位改成「临时的」，这层就被砍了：临时工不需要持久桥接。

还有一次关键降级：历史对话记忆最初设计是「每 Agent 各自的历史」，因为「所有信息通用」的要求改成系统级共享。把研究级难题（完美上下文保持）降级为工程问题（记忆检索），是整个项目最聪明的一步棋——chen 原话：「新系统的核心，现在变成记忆系统了。」

本集留下

三块地基

以 Agent 为本系统的第一公民是 Agent，不是任务，不是工单
Chat as Substrate聊天不是系统的皮，是系统本身
记忆是核心session 只留最近对话，历史的重量由记忆扛

第三句是 chen 的原话撑着的——

「新系统的核心，现在变成记忆系统了。只要记忆系统很强，那么，就可以将历史对话作为『历史对话记忆』，而底层 agent session 还是只保留『最近的对话』。」 —— chen 原话，issue #3

地基打好了。下一集，第一块试金石就拍在脸上：记忆系统明明建好了，它们却什么都记不住。
