> 本文档是守卫规则的治理层：规则怎么分层、怎么生长、怎么退役。改守卫行为 的 PR 必须对照本文档。

## 一、分层原则（规则的宪法层级）

守卫每条规则必须挂靠且仅挂靠一层。层级由**不可逆性**决定——这是降级判据（实时拦 vs 放行+记录）的唯一依据：

| 层 | ruleLayer | 不可逆性 | 判定要求 | 现有规则（ruleId） |
|---|---|---|---|---|
| L1 防自杀 | `self_kill` | **不可逆**：主进程死亡 = 全场急停，所有会话上下文丢失 | 实时拦，宁可误拦；变体翻转策略（非字面量保守拦） | self_kill_literal / pidfile / byname / nonliteral / pipe_shell / script / eval / process_group / script_stop / indirect |
| L2 R1 闸门 | `r1_gate` | **高但可逆**：主仓写受 git 保护（可 reset），data/ 破坏部分可逆 | 实时拦，误报治理走 #1207 路径（cwd 感知持续精化） | main_write / data_destructive |
| L3 权限边界 | `permission` | **制度不可逆**：PR 合入是对外动作，合了就是合了 | 实时拦（机械闸，partnerApproval 原话校验） | pr_merge |
| L4 防绕过 | `bypass_guard` | **守卫完整性**：绕过面 = 上述所有层失效 | 实时拦，脚本文件执行必须拆解 | script_file_exec |
| L5 习惯 | `habit` | **无损害**：感知问题非安全问题 | 实时拦 + 指引（wait 工具） | sleep_block |

**降级判据**：只有 L5 有资格未来降级为「放行+结构化记录」（等 ruleId 数据 2-4 周再议）。L1/L3/L4 永不降级。L2 的误报治理靠精化判定（#1207 路径）而非降级。

## 二、生长规则（新规则必答三问）

**任何给守卫加规则/改判定/加豁免 的 PR，必须在特性文档显式回答三问**（审视獭按此核对）：

1. **挂哪层？**——新规则属于上表哪一层？挂不上任何层的规则不存在（防止「不知道该归哪就单开一类」的分类学熵增）。
2. **carve-out 是什么？**——这条规则的良性例外面是什么？有没有为良性用例留正道（如 L1 的 alpha.sh 隔离实例、L5 的 wait 工具）？**只堵不疏的规则必然产生误报集群**。
3. **退役条件是什么？**——什么信号出现时这条规则该精化或删除？（例：`ruleId 连续 N 周误报率 >X% 且零真报`、`正道使用量 >Y 次后拦截量仍高`）。**合格答案必须是可观测信号 + 量化阈值形态（N/X 写死）——「不再需要时」「过于频繁时」类主观时点表述视为未答，检视獭打回**；carve-out 填「无」时须说明为何不存在良性用例。没有退役声明的规则不许合入——「只增不减」从这里断根。

**双向生长检查**（#1240 教训）：修误报引入豁免时，PR 必须自查豁免的逃逸面——「豁免放走的命令集合」有没有扩大到别的层的拦截面。_示例：#1207 的 cd 豁免放走了 `cd /tmp && python heredoc 体绝对路径写主仓`，属于 L2 拦截面被 L2 自己的豁免击穿。_

## 三、退役与收敛（守卫版每轮三问）

修守卫的 PR 合入前自问：

1. **这次改动让哪条旧规则变冗余了？**（V1/V2 共存期的 eslint-disable max-lines 需要写明拆除条件）
2. **正则总量是否净增？**净增时给出理由（新增拦截面无法用现有模式覆盖）。
3. **指纹表同步了吗？**（`guard-intercept-classify.ts` 的 FINGERPRINTS——改文案/加规则必须同步，分类回归测试会红）

**退役通道**（现状如实标注）：规则退役的提议权在**月度剪枝审视**（monthly-prune-review 任务，F20260929rdsp D3 机制层）——但其当前审视范围（skill 静默/RHI 特性链/任务零产出）**不含 ruleId 消费，本通道为待接通状态**：接通需 monthly-prune-review 扩面（消费 healing_events 按 ruleId 聚合的误报/真报数据），扩面走独立 PR。在此之前，ruleId 数据已可在日常排查中手动聚合使用（SQL 见 F20260930gslog 验证节）。
