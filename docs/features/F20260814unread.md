# 修复左侧栏未读消息数字小红点不会消失

## 问题描述

左侧栏的未读消息数字小红点不会消失。用户有未读消息，但没有滚动到消息底部时，未读消息数字小红点不会消失。

## 根因分析

### 1. unreadCount 的计算逻辑
- 数据库层：`/Users/orca/ai/otter-buddy/src/frameworks/db/conversation/sqlite-conversation-repository.ts`
- 计算方式：`sequence_num > last_read_message_seq` 且 `status NOT IN ('streaming', 'speaking')` 的消息数量
- 依赖 `conversation_user_read_state` 表中的 `last_read_message_seq` 字段

### 2. markRead 的调用时机
- 前端代码：`/Users/orca/ai/otter-buddy/web/src/pages/conversation/index.tsx`
- 只在 `loadConversationDetail` 函数中调用 `markRead`
- 且仅当 `lastReadSeq === 0` 且 `unreadCount === 0` 时才调用（第 178-181 行）

```tsx
// 首次访问（无已读记录）：初始化已读到最新，避免下次进入显示全部未读
if (unread.lastReadSeq === 0 && unread.unreadCount === 0 && msgs.length > 0) {
  const maxSeq = msgs[msgs.length - 1]?.seq
  if (maxSeq != null) api.markRead(convId, maxSeq).catch(() => {})
}
```

### 3. 缺失的场景
- 用户有未读消息，但没有滚动到消息底部
- `MessageList` 组件中没有调用 `markRead` 的逻辑
- `useConversationListPolling` hook 中也没有调用 `markRead`

## 问题根因
前端没有在用户滚动到消息底部时调用 `markRead` API 来标记已读。

## 修复方案

### 方案 1：在 MessageList 组件中添加滚动到底部时调用 markRead
1. 在 `MessageList` 组件的 `handleScroll` 函数中，当用户滚动到消息底部时，调用 `markRead` API
2. 需要传入 `conversationId` 和最后一条消息的 `sequence_num`

### 方案 2：在 conversation/index.tsx 中添加滚动监听
1. 在 `conversation/index.tsx` 中监听 `isAtBottomRef` 的变化
2. 当用户滚动到底部时，调用 `markRead` API

## 修复实现

### 1. 修改 MessageList 组件
- 添加 `onReachBottom` 回调
- 在 `handleScroll` 函数中，当用户滚动到底部时，调用 `onReachBottom`
- 在首次渲染滚到底部时，也调用 `onReachBottom`

### 2. 修改 ChatView 组件
- 添加 `onReachBottom` prop
- 将 `onReachBottom` 传递给 `MessageList` 组件

### 3. 修改 conversation/index.tsx
- 添加 `handleMarkRead` 函数
- 在 `handleMarkRead` 中调用 `api.markRead`
- 添加防抖机制（500ms），避免频繁调用 API

## 变更文件
