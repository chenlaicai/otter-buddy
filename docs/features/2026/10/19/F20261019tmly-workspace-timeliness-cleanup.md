# 工作区时效性清理——临时材料随 PR 合入自主清掉，不再请示授权

## 背景

PR #1539 收尾时，大獭把工作区 10 个临时文件的删除清单列出来请示搭档授权。搭档纠正（2026-10-19 原话）：

> 我觉得工作区清理不需要我来授权，像你本次的整理、每一个文件有留痕、有沉淀、或者是 pr 草稿，那么，随着 pr 合入后，这些都应该自行清理掉，不需要来问我。（本质就是 时效性，既然都不再需要了，那就直接清理）

根因是旧条款被泛化：2026-08-31 post-merge-cleanup 落了「删除不可逆，宁可多确认不激进自动删——删除不可逆（R1 精神）」（F20260831ccnb），本意是防误删**有价值且未沉淀**的产物，实际执行滑成了**凡删必问**——把判断成本转嫁成搭档的授权成本，每次合入收尾消耗搭档一次注意力。

## 设计

### 时效性判据（三分类，取代「建议删除/默认保留」二分类）

| 类别 | 判据 | 动作 |
|---|---|---|
| 价值已沉淀 | 内容已转移进留痕产物：调研素材→R 文档/特性文档、审视草稿→PR 评论/PR description、汇报材料→决策简报/终审汇报 | 直接删，不请示 |
| 时效已尽 | 随 PR 合入失效的一次性材料：PR 描述草稿（已提交）、验证/复现脚本（验证已完成）、截图与调试输出（证据已附 PR）、中间生成物 | 直接删，不请示 |
| 疑难 | 删除不可逆**且**价值未沉淀（有内容但没进任何留痕产物）/归属不明（分不清临时材料还是交付资产） | 列清单呈搭档决策 |

配套两条边界规则：

1. **删前事实校验**：「已沉淀」必须核实是事实不是愿望——草稿对应的 PR 评论可查、素材对应的文档确已落库；校验不过归入疑难类。删除后回查存在性（对齐 post-merge-cleanup「清理状态对账」精神）。
2. **长期资产豁免**：有意产出的研究报告、方案文档（本该沉淀进 docs/ 或产物登记的）不在清理范围——未沉淀的先补沉淀再删，补不了的归疑难类。

### 旧条款的边界修正

「删除不可逆，宁可多确认不激进自动删」不是被推翻，而是被**收敛**：它保护的对象是「有价值且未沉淀的产物」，不是「一切删除动作」。判据从「删前是否需要授权」（程序问题）换成「时效是否已尽」（事实问题）。

**修法决策树判定**：走②（收窄管辖，`Modification-Class: scope-reduction`）。机制识别检查点七项全未命中（无新增配置/状态生命周期/调度/信号/持久化/跨模块调用）；唯一边界项「删前事实校验不过→归入待确认类」的分支结果纯运行时（删/问二选一，不落库不被记住），非「后续影响行为」的决策分支——不涉净新增机制。

### 域边界（回应「R1 精神」的误引）

R1「破坏性操作先确认」管辖的是 **git 追踪资产**——仓库历史可追溯、可恢复（reflog/远端）。工作区文件（`data/workspaces/`）非 git 追踪，对话归档时 removeWorkspace 整体删除——不同域，不适用 R1 的确认义务。F20260831ccnb 引「R1 精神」属类比借用，本特性显式澄清：类比只在「防误删有价值产物」这一点成立，不构成凡删必问的依据。

## 变更内容

`.pi/skills/post-merge-cleanup/SKILL.md` 三处：

1. **触发段「设计原则」区**：新增「时效性清理原则」段（含搭档拍板原话与域边界澄清）
2. **工作流步骤 8**：从「建议删除/默认保留+呈搭档确认」重写为「时效性三分类+自主清理+删前事实校验」
3. **产出表与报告模板**：「工作区清理建议清单 | 搭档确认后执行删除」拆为「时效性材料→自主清理留痕」与「疑难文件→搭档决策」两行；报告模板的「搭档未确认删除建议，跳过」改为「N 个时效性文件已删除；N 个疑难文件呈搭档」

## 验证

- 判据表覆盖搭档原话列举的全部三类（有留痕/有沉淀/pr 草稿）并留出兜底（疑难类）
- 下一次 PR 合入后清理实例为行为面验证：清理报告呈现「时效性文件已自主删除」即生效
- 本 PR 自身收尾即首个吃狗粮实例：工作区临时材料按新判据自主清理，报告留痕

## 非目标

- 不改批量扫尾模式的「等搭档确认」（那是 git 破坏性操作清单，属 R1 管辖，与工作区文件不同域）
- 不改 SYSTEM.md（R1 排除条款已明确非 git 追踪文件不受红线约束，无需新增全局规则）
- 不引入自动定时清理（清理仍是 post-merge 收尾的内置步骤，不加新调度面）
