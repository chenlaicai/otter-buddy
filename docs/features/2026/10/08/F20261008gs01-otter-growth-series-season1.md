# 獭群成长记第一季

## 背景

搭档计划在公司内部技术社区发帖介绍 otter-buddy，经两轮方向校准后定调（搭档原话意图）：

1. 「ai agent 发展到今天，能力展示向内容非常普通」——不写能力炫耀
2. 「要如实地写，既有故事的发展型（我一开始的期望），也有技术的成长和迭代」
3. 「放到一篇里够呛，设计一个七八集的小剧场」
4. 「不能光文字，要生动有趣的展示形式」
5. 「放到 github 仓库上，读者可以自行来当故事看」
6. 「readme 指向成长记……readme 内容很旧，堆叠了一大堆图片，目的是快速让读者看懂这是个啥、有哪些闪光点能吸引到他们」← 本 PR 同时落地 5+6 两条

## 内容

两部分：

**A. 成长记入库**：`docs/growth-series/` 下 10 个文件：index.html（全季目录）+ README.md（导引与素材溯源说明）+ ep01-08.html（8 集正片，每集自包含无外部依赖，1500-2100 字正文）。

**B. 双语 README 重写**（README.md + README.en.md 同步）：
- 旧版问题（搭档原话）：内容很旧、堆叠一大堆图片、不能快速让读者看懂这是什么
- 新版结构：一句话定位 → 30 秒看懂（你只跟大獭说话）→ 闪光点表格（6 项差异化：命名身份/活记忆/不许自审/红绿灯/机械闸/自己盯自己）→ 协作演示（README 计数漂移真实案例 + GIF）→ 成长记入坑链接 → 快速开始 → 进阶配置折叠区 → 为什么是海獭（三支柱压缩为一节）→ 架构 → 贡献
- 图片从 5 张收敛到 2 张（对话界面 + 多 Agent 协作 GIF）；健康面板与 Touch Bar 图仍保留在 docs/images/ 仓库内，仅 README 不再引用

每集统一叙事公式：当时的期望/痛点 → 现实打脸 → 技术被逼着迭代 → 留下了什么。

| 集 | 对应系统演进 |
|---|------------|
| 01 出生 | issue #3 设计哲学、Chat as Interface→Substrate 纠偏、UA-8/9、speak 诞生（fixme 时代）、身份认知体系 |

## 诚实声明执行方式

- 全部事件/数字/原话有档案锚点（素材库 materials.md 逐条登记，含记忆条目 ID / F 文档号 / PR 号）
- 演绎对白以「下面对白为剧场演绎」旁白 + anchor-note 原话注脚标注
- ep06「第一次动真仓」决策讨论无存档，按机制动机抽象写并在页脚注明
- ep08 炒股能力按 2026-09-23 下架事实写（不列为现行能力）
