# 根因优先反射闸：companion 讨论层 + 审视建议层补盲（#1248）

## 背景

搭档 9/29 13:41 纠偏原话（issue #1248 锚）：

> 「哎哎哎，你先不要搞兜底哈，咱们要从第一性原理出发来解决问题，先分析根因，如何优化现有的才是核心、解决根本问题，你不要上来就搞一大堆的兜底/限制机制、这都是错误的方向！」

同日 08:19 另一次裁决「兜底机制整体移除」（#1227 处置链，检视獭-1229 推荐 aging 二次注入兜底被搭档反转——「不处理就是一种态度（忽略）；兜底完全没有用……对异议信号功能本身不相干」）。**一天两次同类纠偏 = 模式而非单点。**

## 缺口分析（覆盖矩阵）

| 层 | 既有机制 | 覆盖时机 | 盲区 |
|---|---|---|---|
| 产物层 | F20260908pgrd 提案 1：修改场景存在性对抗（重对抗检视獭问「治本还是治标」/轻对抗 commit 声明） | 修改场景 | 盖住 |
| 回看层 | F20260908pgrd 提案 2：每日补丁清单（负空间信号：兜底/加固关键词） | 事后 | 盖住 |
| 方案期 | requirement-analysis 机制预算四问 + 重对抗门 | 方案成形时 | 盖住 |
| 实现期 | code-implementation 机制判定前置 | 动手前 | 盖住 |
| 排查期 | troubleshooting 修法决策树（①②③④先问该不该存在） | 根因确定后 | 盖住 |
| **讨论层** | **无** | **companion 默认模式** | **零覆盖——9/29 两次纠偏都发生在这里** |
| **审视建议层** | adversarial-review 审「作者的机制预算」但不管「检视獭自己提的建议」 | 建议产出时 | **1229 推兜底教训** |

9/29 两次纠偏场景的共同点：都是结构化流程**开始前**的讨论（「当时在讨论机制修复方向」）——四问/决策树/对抗门全部还没被触发，兜底提议直接溜出。

## 方案（两处最小落点）

### 1. companion 工作流加第 5 条：根因优先反射闸

讨论中提出修复/防御/限制类方案时，先过「根因三问」：

1. 这是什么根因（现象背后的机制性原因）？
2. 现有机制为何接不住（缺什么）？
3. 为什么加一层优于修现有机制？

三问答不上来 = 根因还没摸清 = 不该提加层方案，改走「先查根因」（排查类 → troubleshooting 修法决策树；方案类 → requirement-analysis 四问）。「加一层能兜住」是便利不是论证。

设计说明：
- **为什么落在 companion 而非 SYSTEM.md**：companion 是讨论层的默认入口（不匹配任何 skill 时进入），SYSTEM.md R 层已有增长纪律约束（每轮牵引力三问）且 A 层哲学已含事实优先——讨论层的场景型 know-how 按纪律归 skill；issue 建议改进节也首选「SYSTEM.md **或** 对应 skill」
- **为什么是三问不是四问**：机制预算四问（谁需要/失败后果/后续机制/退役条件）是「决定要不要加机制」的预算问；根因三问是「决定要不要提加层方案」的前置问——讨论层还没到预算阶段，先挡住「没摸根因就提加层」的反射。三问是四问的前置闸门不是替代
- **为什么闸在 companion 的方案讨论场景而非全部对话**：只在「提修复/防御/限制类方案」瞬间触发——闲聊、汇报、事实问答不受影响（A4：非结构化讨论不主动拉入流程）

### 2. adversarial-review 审查维度加一行：建议层根因闸

检视獭自己提的建议若是「加兜底/限制/拦截层」类，必须附根因三问答案——答不上来就改提「查根因」方向。锚：检视獭-1229 delta 复核推荐「aging→register 二次注入兜底」，搭档裁决反转（「兜底会稀释义务契约……任何晚救通道都在把『先忽略后补救』变成合法策略」）——审视者的工程冗余反射与实现者同源，审视建议层不是法外之地。

## 设计取舍

- **弃「SYSTEM.md 加 R 条」**：R 层是每轮注入的执行规则，讨论层的场景型触发（提修复方案瞬间）按「场景型 know-how 归 skill description 或对应 skill」的增长纪律归 companion——SYSTEM.md 加条会每轮注入但仅特定场景有用，稀释牵引力
- **弃「对话层机械拦截（speak 守卫）」**：兜底提议是语义判断非机械模式（「加一层重试」vs「修好现有重试」字面相似），机械守卫误拦面不可控——与「停下」魔词不同，这不是紧急拉闸场景而是方法论偏好修正，prompt 层约束 + 每日回看负空间观测已构成闭环
- **worst case 接受**：prompt 约束非物理闸，海獭仍可能漏触发——观测点是每日补丁清单（现成），若期观察仍高频出现讨论层兜底提议，升级路径是 SYSTEM.md R 条（已在此记录该升级条件）

## 与 F20260908pgrd 的关系

同族防线的分层补全：pgrd 盖「修改场景」（产物层）与「每日回看」（事后层），本特性补「讨论层」（事前结构化流程外）与「审视建议层」（审视者自身）。三层合并后的完整覆盖：讨论（companion 闸）→ 方案（RA 四问）→ 实现（code-impl 前置判定）→ 审视（对抗门 + 建议层闸）→ 事后（每日清单）。
