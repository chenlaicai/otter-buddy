# 獭之传说·镜湖终战 P2：五段式终战 + 429 换獭 + 封印咒语门

## 背景

方案 F20261009oqtd §7 分期：P0（#1422）✓ → P1（#1427）✓ → **P2 镜湖终战** → P3（README+GIF+Pages）。P1 的终章只是预告（lakePreview 一段文案），战斗本体属 P2 范围。

开工插曲（决策史）：P2 编码过半时 #1427 误合入事故暴露（授权原话时间维度缺失，issue #1431），搭档指示「停下 P2 开发，处理事故」；事故根因落档后搭档放行「那你现在继续p2镜湖」，本 PR 即恢复后的交付。

## 目标

1. **T1** 镜湖终战五段式：占卜（search_memory）→ 召唤（create_otter）→ 结界（worktree 隔离）→ 洞察（异体审视，首刀必中）→ 顺着漏洞刺入（翻倍伤害），五动作映射五能力，每步带映射点破文案
2. **T2** 429 哑火→换獭：洞察獭非首刀 15% 哑火（配额见底），换獭重新召唤、首刀必中保底——配额轮换机制的游戏化
3. **T3** 封印咒语门：逐字校验「合入」，错拒对过——授权原话机械校验的终章复刻（与试验田封印门同构）
4. **T4** 战败→重生：死亡不是终点（前世已封存成档案、谱系+1），「纯硬莽打不赢它」入图鉴
5. **T5** 数值保底：正路最坏情况必胜（无随机翻车）、纯硬莽 100% 必败——两头都确定

## 非目标

## 方案设计

### 1. 战斗状态机（game/index.html battle 段，约 170 行）

`B` 对象 16 字段单源：hp/mp/foe/foeTalk/divined/ally/allyTired/allyFresh/insight/shield/selfChain/turn/busy/over/seal/barrier。入口 `lakeBattle()`（S.allDone 时点镜湖触发），出口 `bWin()`（封印门）/`bLose()`（重生）。按钮可见性由 `bButtons()` 单源驱动，`actSummon` 是 `B.ally=true` 唯一入口且 `!B.ally` 恒推出召唤键（防 P1 式软锁死：任何状态转移后必有可点按钮）。

### 2. 五段式动作表

| 段 | 按钮 | 机制 | 映射点破 |
|---|---|---|---|
| ① | 🔮 占卜 | 查旧档案命中「它拒绝召唤/自言自语/自测无用/不让獭审视」弱点 | search_memory |
| ② | ✨ 召唤洞察獭 | `B.ally=true`，首刀必中 | create_otter |
| ③ | 🛡️ 结界 | shield=12，吸收敌伤 | worktree 隔离 |
| ④ | 🔍 洞察獭·审视 | 8-12 伤 + `B.insight=true`（下击翻倍）；非首刀 15% 哑火 | 异体审视 |
| ⑤ | 🗡️ 顺着漏洞刺入 | 14-18 伤（翻倍），标签随洞察切换 | 顺证据修，不硬莽 |

敌方「过去的大獭」：每回合 6-9 伤（无盾 +3），自言自语间隔递增（上下文爆炸演出，封顶 1.2s）。

### 3. 数值保底论证（T5 核心）

- **正路必胜**：占卜/召唤/换獭是零成本动作（不触发敌方回合），敌方回合只由结界/洞察/攻击触发。正路序列 = 结界(1) + 洞察(1) + 刺入×k（杀招不触发敌方回合）。最坏掷点：洞察 8 伤 → 敌余 92 → k=7 刺入（7×14=98≥92）；敌方回合共 8 次：前 2 次盾在（最坏透 6 伤），后 6 次 9-12 伤（最坏 72）→ **最坏总承伤 78 ≤ 100，恒胜**。429 哑火最坏多 1 敌方回合（强制自测场景）→ 90 ≤ 100 仍恒胜
- **纯硬莽必败**：硬莽 3-5 伤需 ≥20 回合杀敌；敌伤 9-12/回合，玩家 9-12 回合内必死 → **恒败**（战败即重生引导占卜，设计正反馈）
- 原稿数值（敌伤 6-10+5）正路最坏 98/100 只剩 2 点容错，429 场景必翻车 → 下调敌伤为 6-9+3 拉开容错（见设计取舍）

## 设计取舍

### 机制识别检查点判定（Modification-Class: mechanism-addition 依据）

- 命中「新增状态生命周期」：B 战斗状态机（创建→存活→重置/销毁）→ 修复可能走④，按规则四问必答（下表）
- 其余项不命中：无新增配置/枚举/开关、无定时任务、无信号类型、无持久化（纯 file:// 运行时）、无被记住的决策分支（B 状态不落盘）、无跨模块调用（game/ 零依赖）

### 机制预算四问（作者当场作答）

1. **谁需要它**：玩《獭之传说》的搭档/访客——需要一场能赢能输的战斗来演完「打败过去的自己」叙事；没有战斗系统，方案 §7 的终章只有空文案（P1 遗留的悬空预告）
2. **失败后果**：用户可感知损害（卡死/必败/不可通关=产品不可用）；对系统零损害（game/ 是纯静态内容产品，不进主系统运行面）
3. **后续机制**：B 状态机新状态的出错面 = 软锁死（无可点按钮）、状态转移死循环、数值失衡——同类事故先例是 P1 封印门软锁死（#1427 检视严重2）。修法预案：状态转移全覆盖 selftest（本 PR 已含全部转移路径）、按钮可达性单源（bButtons）、数值保底论证（本节）；本轮开发已实际修掉一个同型缺陷（召唤键漏推导致 actSummon 不可达死锁）
4. **退役条件**：游戏整体下线或被新版本重写时随 game/ 一并移除；方案 v2（F20261009oqtd）退役即本机制退役

### 取舍表

| 取舍 | 决策 | 替代方案 | 理由 |
|---|---|---|---|
| 敌伤数值 | 6-10+5 → 6-9+3 | 加大刺入伤害/减敌 HP | 保底论证要求容错 ≥10 点；降敌伤不改叙事张力（硬莽仍必败） |
| 刺入入口 | 按钮标签随 B.insight 切换（硬莽攻击→顺着漏洞刺入） | 只在对话标题里说「刺入」 | 旧 selftest 找不到「刺入」按钮是实证——机制不可见 = 不可用；标签切换让五段式第五段显性 |
| 429 自测 | selftest 强制 Math.random=0 窗口（点击同步 roll） | 依赖 15% 自然概率重试 | 确定性 > 概率重试；强制窗口只覆盖 roll 瞬间，不污染战斗其余随机 |
| 正路序列 | 显式五段式脚本 | 关键词优先级循环（旧版） | 旧循环把「洞察」排在「刺入」前导致永不刺入、40 轮空转——显式序列每步有断言，失败可定位 |
| 重对抗门 | 四问答毕，治本/治标判断由本 PR 检视獭合并承担 | 另召一轮门控獭 | 按 requirement-analysis 步骤 7「重对抗审查与对抗审视可合并为同一只检视獭的同一轮审视」，不重复召唤 |
