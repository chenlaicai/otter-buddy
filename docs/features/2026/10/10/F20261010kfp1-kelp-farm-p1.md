# 獭之传说·海藻农场 P1：8 点位全量三段式 + 静态层预烘焙 + SPOTS 元数据统一

## 背景

P0（#1422，已合入）交付了开局第一幕 + 点位 1 播种三段式 + 渐进解锁框架，检视留了两个非阻塞建议：

- 发现 3：每帧全场景重绘（tile 循环），量级随场景加密增长
- 发现 5：SPOTS 数据模型里热区与元数据（w/h）不同源，光环比热区宽 12px 类问题易复发

P1 的任务（方案 F20261009oqtd §7 实施分期）：8 点位全量三段式 + 教学梯度调平（每点位 ≤15s、全流程 ≤3 分钟），顺手处置两条检视遗留。

## 目标

1. 点位 2-8 按 P0 已确立的三段式框架落地，剧本与方案 §2 点位表对齐
2. 静态层预烘焙：状态变更时 rebake，帧循环只画动画层
3. SPOTS 元数据统一：w/h 单源驱动热区 / 发光环 / 标签位置
4. 视觉延续 P0 精绘规格（480×270 / 16×16 tile / 三层着色纪律），场景元素随点位扩展
5. 自检覆盖：8 点位闭环、封印门校验、3s 约束、像素取证、零报错、零外链

## 非目标

- 镜湖终战（P2，移植 quest-rpg/ 灰盒源）
- 音效 / BGM（方案明示非目标）
- 存档（file:// 单次会话内闭环）
- 移动端适配（方案 §6 只约束桌面 chrome）

## 方案设计

### 1. 点位剧本（8 点位映射 otter-buddy 能力）

| # | 点位 | 映射能力 | ① 问题任务 | ② 能力引入 | ③ 效果达成 |
|---|------|---------|-----------|-----------|-----------|
| 1 | 🌱 荒田 | 记忆入库 | 不记得昨天（工具找不到） | 种下「今天发生的事」 | 麦子入背包「记得今天了」 |
| 2 | 📖 种子库 | 记忆检索 | 同样的坑踩过想不起细节 | 开箱验档案：标签/日期/谁种 | 旧种子直接发芽（免重种）＋命中卡变绿动画 |
| 3 | 🚿 板结田 | 上下文管理 | 越记越多走路越慢 | 施肥翻耕（重的压成养分） | 速度恢复「轻装但都在」 |
| 4 | ♻️ 休耕田 | 前世封存 | 连种百季产量骤降 | 残茬翻土变堆肥 | 「+50%」下一世更好 |
| 5 | 🐞 瓢虫屋 | 自愈 healing | 蚜虫反复偷袭盯不住 | 建屋养瓢虫（不用你管） | 自动处理+台账 |
| 6 | 🦦 邻居獭 | 多獭协作 | 农活堆积一只獭干不完 | 敲门分工 | ×3 速度+配额轮换 zZz |
| 7 | 👴 老农獭 | 异体审视 | 自查三遍看不出叶背虫卵 | 放大镜扫田 | 卵显形清除保收成 |
| 8 | 🧪 试验田 | worktree 隔离+PR+授权原话 | 新品种直接进主田染病 | 玻璃罩隔离试种 | 丰收 → 「合入」封印门 |

（全 8 点位同表，格式同 P0：SCRIPTS 数据驱动，每点位 problem/act/effect 三段文案 + 演出钩子 on()，effect.map 为映射点破卡文案。）

### 2. 特殊演出：试验田「合入」封印门

点位 8 的效果达成不直接放行——先弹出输入框，须逐字输入「合入」两字（错字被拒，提示「原话不符」），通过后金麦流入主田仓。这是 merge_pr 工具「授权原话机械校验」的游戏化复刻：系统不猜你的意思，门要你亲手开。

### 3. 架构：静态层预烘焙（发现 3 处置）

```
bake()  → 离屏 canvas staticCv：天空/地面/湖底/田块/物件/标签（状态相关层也在内，状态变更 markDirty() 触发 rebake）
render() → drawImage(staticCv) + 动画层（星/水波/萤火/角色/光环/浮字/星火，量级 ~1k draw calls）
```

帧循环重绘量从全场景 tile 循环降为 1 次 drawImage + 动画层。60fps 稳态实测（headless shell）。

### 4. 架构：SPOTS 元数据统一（发现 5 处置）

每点位元数据 `w/h` 单源：`hotRect()` 统一计算热区与发光环（光环=热区+10px 边距视觉扩展），标签从 `x+w/2` 居中。发光环比热区宽 12px 的漂移问题从结构上消除。

### 5. 教学梯度调平

- 每点位三段按钮文案短（≤10 字），步骤间隔实测 ≤276ms（含脚本调度）
- advance() 后自动 walk 到下一点位 stand 位，玩家不用找路
- 每点位完成后 setWho() 换幼獭称号（「记得今天的幼獭」→「有安全感的幼獭」），8 个称号对应 8 种能力
- 全流程程序化走完 3.6s（无人为等待），预估玩家实际 2-3 分钟

- **像素取证**：827 色（P0 修复后 316 色 → P1 场景扩展自然增长）；木箱 wood0 74,48,24 ✓、湖水 w1 31,74,104 ✓、獭脸 face 201,160,106 ✓、湿土垄沟 44,33,21 ✓、试验田成熟麦穗区着色 ✓

## 影响范围

- `game/index.html`：625 → ~950 行（剧本数据 + 演出钩子 + 预烘焙层 + 新 sprite）
- 无后端、无依赖、无外部请求（file:// 单文件自包含）

## 风险与约束

- **单文件体量**：~950 行 HTML，继续膨胀会逼近可维护边界。P2 镜湖移植时评估拆分（方案 §6 允许拆 JS 资产但保持零依赖）
- **视觉复核盲区**：当前实现模型无视觉能力，像素级数值断言只覆盖关键坐标色值。终审前建议多模态检视獭截图复核
- **封印门文案**：「原话不符，再试」提示硬编码「合入」两字答案——首次玩家可能卡住（剧本设计为可重试，无死锁）

## 设计取舍

- **预烘焙 vs 每帧全绘**：选预烘焙。动画元素（水波/萤火/瓢虫巡逻）仍逐帧绘制，但地面 tile 循环（~200 tiles × 16px 纹理调用）从每帧移到 rebake。60fps 且余量充足，为 P2 场景扩展留空间
- **SCRIPTS 数据驱动 vs 硬编码**：选数据驱动。P0 已验证该模式（SPOTS/SCRIPTS 双表），P1 全 8 点位统一进表，P2 终战可复用
- **封印门用 input 而非按钮**：按钮降低仪式感且无法表达「机械校验逐字命中」——输入框+错拒反馈更能传达「原话」的严格性。代价是不可点穿（不能误触通过），这是有意为之
- **emoji 背包计数**：自检用 DOM children 计数而非 string.length（♻️ 等带 VS16 的 emoji 在 UTF-16 中占 2 code unit，string.length 会虚报）——测试坑记录在案
