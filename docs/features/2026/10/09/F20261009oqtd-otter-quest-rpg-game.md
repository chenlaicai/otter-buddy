# 獭之传说（Otter Quest）：README 游戏化获客

## 背景

搭档原话（意图锚）：

> 「我有个想法，我想优化下咱们海獭系统 github 的 readme，或者说，我期望有一种更有趣的方式、能够吸引 star。比如说，游戏。在游玩的过程中，又有乐趣，又能了解到海獭系统的各项功能能力。表现咱们海獭系统的功能能力。」（2026-10-09 11:10）

> 「我觉得扮演大獭是一个不错的 idea，但内容形式可以调整下，不要再是工作，比如说 打怪？用技能？你做一些概念映射」（2026-10-09 11:45）

> 「你提到的最终 boss 是"失传的大獭" idea 不错，屠龙者总成恶龙 这种命运循环的宿命感也是很多游戏的剧本。咱们就可以是 不断升级自己，那打败的就是过去不好的自己 这种寓意。那你继续，出方案」（2026-10-09 11:48）

历史先例（无否决记录，全为支持性脉络）：F20260828rdsc（README 首屏截图）、F20260829gifs2（首屏 GIF）、F20261009csp2（活类可玩形态——html-card-play 已合入，证明「玩」在产品内已有宪法地位）。「黑雾照亮」玩法意象出自 8/30 对话讨论，未落档（凭记忆未核实，仅作创意来源，非事实引用）。

## 目标

T1: GitHub Pages 托管的回合制 RPG《獭之传说》，浏览器零安装即玩（单 HTML/静态站点）
T2: 游戏机制与海獭系统能力同构——玩家通关即理解：编排、记忆先行、安全红线、异体审视、授权原话、重启不重置
T3: 终章剧情落地「打败过去不好的自己」寓意（屠龙者循环），制造情感高点与传播点
T4: README/README.en.md 首屏加入游戏入口（GIF 预览 + 「🎮 点击即玩」链接），不喧宾夺主
T5: 中文 + 英文双语（README 双语传统；i18n 架构就位，英文文案可后续迭代）

## 非目标

- 不做安装版/CLI 版（`npx otter-quest` 二期候选，本方案不含）
- 不做 ARG 彩蛋链、star 养成徽章（传播钩子，可后续叠加，本方案不含）
- 不做存档/读档云同步（localStorage 单会话足够，单局 ≤20 分钟）
- 不做联机/排行榜（单机剧情向）
- 不改动主系统任何运行时代码（game/ 是纯静态独立站点，零依赖 src/）
- 不做移动端深度适配（可玩即可，桌面优先）

## 未决问题

- Q1: 美术风格——像素风（技术成本低，AI 生成或开源素材包）还是 Emoji 极简风（零素材成本，全部用 emoji + CSS 绘制）？方案默认 Emoji 极简风（最快可交付、风格与 README 的「它们有名字」气质契合），搭档可推翻。
- Q2: 游戏名——「獭之传说 / Otter Quest」为工作名，搭档可另起。
- Q3: 结局封印咒语环节是否接入真实 GitHub OAuth（让玩家真的给 repo 点 star 才算封印）？方案默认**不接**（强制 star 感太差，掉好感；改为通关后温和提示「如果这趟旅程有趣，欢迎 star」）。

## 方案设计

### 1. 载体与部署

```
game/                        # 仓库内新目录，纯静态
├── index.html               # 单页入口（vanilla JS 或轻量构建）
├── src/                     # 游戏逻辑（战斗引擎/剧情数据/i18n）
├── assets/                  # 素材（emoji + CSS，或像素 sprite）
└── README.md                # 游戏开发说明

.github/workflows/deploy-game.yml   # push main 且 game/** 变更 → 部署 GitHub Pages
```

- **托管**：GitHub Pages，`https://chenlaicai.github.io/otter-buddy/`（仓库级 Pages）。技术约束侦察：仓库现有 workflows 仅 ci.yml + auto-close-external-prs.yml，无 Pages 冲突。
- **README 嵌入形态**：GitHub 会剥离 iframe/script，**无法内嵌可玩实例**——形态只能是「GIF 预览图 + 链接按钮」。GIF 录制 15-20 秒精华（召唤兽围殴 + 占卜 + 最终封印）。
- **技术栈**：vanilla TypeScript + Vite（或零构建单文件）。无框架依赖——游戏逻辑简单（回合制状态机），重的是内容。构建产物进 Pages，源码留 game/。

### 2. 概念映射（玩法核心，沿用头脑风暴定稿）

| 系统能力 | 游戏机制 | 教学效果 |
|---|---|---|
| 发言石（行动权） | 回合制回合权 | 獭间轮流拿石头说话 |
| search_memory | 🔮 占卜：揭示怪物弱点/图鉴 | 不占卜能打但很惨 → 记忆先行 |
| create_otter | ✨ 召唤兽：🔥火獭/🔍洞察獭/💨疾风獭等 | 编排 > 蛮干 |
| 异体执行 | 自测攻击被怪**弹开/无效化**，怪趁机回复；必须 🔍 洞察獭补刀「对抗审视」 | 自己审自己 = 没审 |
| 安全红线 | 闪光「主巢」可点击：前两次点击被「守卫结界」弹回（演出 bash 守卫拦截），执意第三次才 Game Over（「红线不可弹性」） | 红线是物理拦截不是事后爆炸 |
| worktree | 🪞 结界：开战前展开才能放技能，否则反噬 | 隔离环境改动 |
| 梯度护栏 | 连续独自行动 MP 消耗翻倍 | 交棒给队友 |
| 配额（429） | 召唤兽体力值，打空「哑火」，换模型复活 | 资源管理（首哑梗） |
| 需求变更 | BOSS 二阶段变身，占卜情报作废需重占（游戏内命名「**变局**」） | 需求变了，情报作废 |
| healing 台账 | 战斗经验自动入图鉴，同类怪占卜免费 | 教训沉淀 |
| merge_pr 授权原话 | 终章封印需输入搭档咒语「合入」 | 机械闸彩蛋 |
| 重启不重置 | 阵亡不 Game Over：前世封存成档案，新世带交接摘要醒来（谱系 +1） | 獭是跨 session 连续体 |

### 3. 关卡与剧情（4 章 + 终章）

**序章**：幼獭出道，教学关。占卜 vs 硬莽的区别（第一只怪不占卜打 3 倍伤害）→ 结界教学（首次正式战斗前引导展开结界，演示未展开反噬）→ 获得**第一只召唤兽**（预告版基础獭，第二章升格为「多獭编排」）→ 序章小 BOSS → 成就结算「你已掌握：记忆先行」——3 分钟完整小循环。

**第一章·黑雾森林**（主题：记忆）：怪物被黑雾笼罩，占卜照亮。BOSS「遗忘兽」——每回合让玩家忘记一个技能，逼玩家用图鉴（healing 台账）夺回记忆。

**第二章·分身荒原**（主题：编排）：怪物成群，单打必败，学会召唤兽分工。BOSS「千面兽」——免疫单一属性，必须多獭围殴。隐藏要素：闪光主巢第一次出现（诱惑陷阱教学）。

**第三章·捷径回廊**（主题：红线与审视）：宝箱怪「诱惑怪」许诺跳关，走捷径掉进「绕过审视」陷阱——陷阱里自测攻击被弹开无效化的机制被具象化为「你自己的攻击在这里打不中任何东西，而怪每回合都在变强——唯有召唤来的洞察獭能命中」。BOSS「变更兽」：二阶段变身，情报作废（需求变更教学）。

**终章·镜湖**（主题：宿命循环）：

最终 BOSS「**过去的大獭**」——镜中走出的自己：拒绝占卜（图鉴空白）、拒绝召唤（孤身）、每回合自言自语越来越慢（上下文爆炸：它的技能描述文字越来越长，长到溢出对话框，行动越来越迟滞）。

它使用的全是玩家第一章之前的打法：硬莽、自测、不占卜。

击败方式不是堆数值——它血厚到硬拼必输。**正确打法是展示完整系统能力**：占卜它的过去（揭示它「也曾经是你」）→ 召唤队友（它无法应对多线程）→ 结界防御 → 洞察獭审视（找出它的逻辑漏洞）→ 最后封印时需要输入授权咒语。

封印后它说：「……原来我一直缺的不是力气。」化作光点融入玩家——等级面板显示：**「你击败了 Lv.1 的自己」**。

通关画面：幼獭剪影长大成大獭，身后站满这一路上召唤过的所有队友。字幕：「They have names.」→ 落版：项目名 + star 邀请。

### 4. README 集成

README.md / README.en.md 在「30 秒看懂」之前插入紧凑区块：

```markdown
## 🎮 先玩 3 分钟，再读文档

[![獭之传说](docs/images/otter-quest.gif)](https://chenlaicai.github.io/otter-buddy/)

**[▶ 点击即玩《獭之传说》](https://chenlaicai.github.io/otter-buddy/)**——
扮演一只幼獭打怪升级，通关时你会理解这个系统的全部理念。
最终 BOSS 是过去那只不懂协作的自己。
```

位置原则：游戏是钩子不是本体——README 主体结构不变，入口控制在一个区块内。

### 4.5 前 90 秒承接（传播漏斗）

游戏内叙事再完整，对「从 GitHub 点进来的裸访客」缺一层承接：
- **落地页框架**：一行关联文案——「这是 otter-buddy 的交互式自我介绍：一个多獭协作系统。通关这场冒险，你就懂了它。」+ 随时可点的「跳过游戏，直接看 README」出口（不绑架访客）。
- **3 分钟体验锚点**：序章教学关本身设计成完整小循环（占卜 vs 硬莽对比 → 第一只召唤兽 → 小 BOSS → 成就结算「你已掌握：记忆先行」），3 分钟有独立满足感；想继续的自然进入第一章。README 文案「先玩 3 分钟」承诺的就是序章，不是全程。
- **一鱼两吃（P3 候选）**：F20261009csp2 的 html-card-play 已合入，同一份静态 HTML 未来可在产品对话内作为可玩游戏卡发放（demo 场景复用），本期不做，记入候选。

| 区域 | 影响 |
|---|---|
| README.md / README.en.md | 新增一个入口区块（~6 行） |
| .github/workflows/ | 新增 deploy-game.yml |

风险：Pages 部署失败只影响游戏入口 404，不影响仓库任何功能；README 改动可回滚。

**实施前置**：① eslint.config.mjs 的 ignores（eslint.config.mjs:40，当前不含 game/）需加入 `game/**`（或 game/ 独立 lint 配置），否则 pretest 的 `npm run lint` 会按主仓规则扫游戏代码致 CI 红——tsc 与 vitest 已核实不受影响（tsconfig include=src/tests/api-contract；vitest include=tests/**）。② GitHub Pages 需搭档在 repo Settings → Pages 手动将 Source 设为 GitHub Actions（一次性操作，deploy-game.yml 推送前完成，否则部署失败表现为 404 不易归因）。

## 风险与约束

- **内容质量风险**（最大）：游戏不好玩 = 反效果。缓解：先做序章+第一章+终章灰盒的可玩原型（竖切）给搭档试玩拍板，再铺全量内容。
- **工作量风险**：4 章+终章内容量大。缓解：数值系统从简（无装备无加点，成长=解锁更多召唤兽/技能），成本集中在剧情文案与战斗手感。
- **GIF 体积**：README GIF 需 <5MB，录制时控制时长与帧率（沿 F20260829gifs2 经验）。

## 设计取舍

| 取舍 | 决策 | 替代方案 | 理由 |
|---|---|---|---|
| 游戏载体 | GitHub Pages 网页版 | CLI（npx）/ README 内嵌 iframe | Pages 零安装门槛、可分享传播；README 内嵌被 GitHub  sanitization 剥离不可行（技术约束）；CLI 开发者味浓但拦人（二期候选） |
| 美术风格 | Emoji 极简风 | 像素 sprite | 零素材成本最快交付，气质契合；像素风留作升级路径（Q1 搭档可推翻） |
| 玩法类型 | 回合制 RPG | 工作模拟器 / roguelike | 搭档明示「不要再是工作，打怪用技能」；回合制天然同构发言石模型 |
| 成长系统 | 无装备无加点，成长=解锁召唤兽与技能 | 传统数值养成 | 成本聚焦剧情与机制映射；数值养成本身不传达系统理念 |
| 结局 star 转化 | 温和提示，不强制 | 接 GitHub OAuth 真点 star 才通关 | 强制 star 掉好感（Q3） |
| 终章 BOSS | 「过去的大獭」单 BOSS | 熵兽等抽象怪物 | 搭档选定「屠龙者循环/打败过去的自己」寓意 |
| 内容推进 | 竖切原型先行（序章+第一章+终章灰盒） | 全量一次交付 | 游戏手感不可纸面论证，可玩原型是 cheapest 拍板依据；终章五段式是全案最大卖点与最新战斗范式，最贵不确定性前置证伪 |

**机制识别检查点**（requirement-analysis 步骤 5）：本方案涉及新增静态站点目录与部署 workflow——逐项核对：□配置字段 ✗ □状态生命周期 ✗ □定时任务（workflow 是 push 触发，非常驻进程）✗ □信号/消息格式 ✗ □持久化存储 ✗（游戏 localStorage 属浏览器侧，非系统存储）□决策分支（结果写入系统）✗ □跨模块调用 ✗（game/ 与 src/ 零依赖）。**判定：不涉及主系统净新增机制**，跳过机制预算四问。deploy-game.yml 本身是新增 CI 机制，但其失败域=游戏部署，不触及系统行为面。

## 验证

1. **构建验证**：`game/` 构建产物本地可玩，Pages 部署后 URL 可访问

4. **回归**：CI 全绿（game/ 不进主构建，仅确认 workflows 语法）
