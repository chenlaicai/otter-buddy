# 发现闭环（F20261015gate）

## 背景：#1487 现场（一个字母的笔误捅穿一条流程）

2026-10-14，PR #1487（node import 只读豁免修复）检视发现测试 describe 文本特性编号笔误 `F20261014mirw`→`nirw`：

| 环节 | 发生了什么 | 断在哪 |
|---|---|---|
| 检视 | 定级「建议」，结论写「初轮通过——0 严重 / 1 建议」，收尾措辞「可留可弃」 | 严重度单点评估没有兜底，「建议」被语义上等同「可不修」 |
| 合入 | 搭档 17:07 合入时看到的信号是「通过」，无人知道有一条发现悬着 | 合入不检查处置状态，处置责任悬空（「或由大獭裁决」出口无人走） |
| 修复 | 合入后修复才落在 worktree，未提交未推送 | 时机错（应在 PR 内修）+ 无「随修随提」纪律 |
| 复核 | 修复留在本地 → 检视物理不可见 → 无从 delta 复核；直到绕一圈开小 PR #1489 才补上 | 不进 PR 的改动在复核的可见范围之外 |

三个现象（可忽略 / 留本地 / 没复核）是同一条因果链的三个断点，不是三件独立的粗心事。

## 方案：一个原则、三个落点

**原则：发现必处置、处置完才合、合后零残留。**

「处置」不等于「必须修」——处置终态四选一：修复+delta 确认 / 反驳成立（改了更差，理由留痕）/ 建 issue+登记 / 搭档裁决。但不允许没有终态。

### 落点 1：检视结论口径（adversarial-review/SKILL.md + references/review-loop.md）

- state 决策表：「通过」仅适用于初轮零发现或全部发现已处置；「仅建议发现」行语义从「悬置，不挡不放」改为「待处置——不构成合入依据」
- 硬规则块：发现未处置不得给「通过」；**禁用「可留可弃/可忽略/可选」措辞**——建议级只表示优先级低，不表示可不处置
- 收敛判据：「无严重发现未处置」→「无发现未处置（含建议级）」

### 落点 2：合入前置（review-protocol/SKILL.md）

- 呈搭档终审前必须核对**发现处置表**（每条发现 + 终态），随终审简报呈递；有未终态发现不得呈终审/请求合入
- 这是专门给搭档的兜底：严重度评错时，处置表把每条发现的去向摆在搭档眼前，合入点击是知情决策

### 落点 3：worktree 纪律（worktree-isolation/SKILL.md + post-merge-cleanup/SKILL.md）

- **零悬置改动**：worktree 改动随修随提（commit 进 PR 分支），禁止「改了先放着」；修复必须有明确提交者与 PR 载体
- **合入后修复走小 PR**：清理时发现合入后顺手修的未提交改动，要么立即小 PR（检视后合入），要么显式回滚留痕，禁止悬置或随手丢弃

## 机制识别检查点判定（Modification-Class: mechanism-addition 依据）

- **新增决策分支（命中）**：「发现处置表全终态」成为呈终审/请求合入的前置分支，判定结果随终审简报留痕、被 delta 复核与后续 merge 机械闸消费（结果被记住并在后续影响行为）——命中检查点，按修法决策树④处理
- 其余检查点（配置字段/枚举/开关、状态生命周期、定时任务/后台进程、信号类型/消息格式、持久化存储、跨模块调用路径）均未命中——纯 skill 文本变更
- **选④而非①②③的理由**：#1487 三个断点不是既有机制语义内的缺失（①无从补——「建议=可不修」是语义滑坡不是缺字段），不是问题机制边界过宽（②无边界可收窄），更不可删除（③处置责任恰恰需要归口）——只有新增「处置表合入前置」这一强制闭环才封住「每一环都能合法漏球」

## 机制预算四问

1. **谁需要**：所有审视线（代码 PR / 方案文档）——#1487 不是孤例，「建议级被悬置」在多条线有轻量变体（如「建议建 issue 跟踪」说了没建）
2. **失败后果**：若处置表流于形式（獭照抄「已处置」不核对），防线退化为文案——但处置表逐条列终态+delta 复核独立核验，造假会被复核抓（#1361 虚假签收被抓先例）
3. **后续机制预测**：不预测新补丁——本改动是把既有 author-response 处置协议（「没有第三条路」）从建议升为合入前置，收紧而非增机制
4. **退役条件**：当 merge 层出现机械闸（如 merge_pr 工具校验处置表字段）或连续 4 周零「未处置合入」事件、处置表成为肌肉记忆后，本细则可收敛回 review-protocol 一句话引用

- 5 个 skill 文件：adversarial-review/SKILL.md、adversarial-review/references/review-loop.md、review-protocol/SKILL.md、worktree-isolation/SKILL.md、post-merge-cleanup/SKILL.md
- 无代码改动、无测试改动、无 prompt/scheduled 改动

## 取舍

- **不加机械闸**（如 CI 校验处置表）：处置终态是语义判断（反驳是否成立），机械校验只能查「表存在」查不了「终态真伪」，先靠协议+复核双层，机械化留给后续 merge_pr 工具演进（退役条件里写了出口）
- **不禁「建议」分级本身**：优先级分层是审视线的效率来源，问题出在「建议=可不修」的语义滑坡，修语义不修分级
