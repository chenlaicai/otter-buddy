# 獭桌三麻雀魂化 UI 重排——牌河居中主骨架

## 背景

搭档原话（意图锚，2026-10-20 15:23，本对话 seq 468）：

> 「优化ui布局，可以参考雀魂，打出的牌放到中间，以及立直、牌型提醒、倒计时等等，这些都可以慢慢加，但最终效果要先立主」

拆读（引用为锚，不意译）：
- 「可以参考雀魂」——布局参照对象是雀魂（Majsoul）的牌桌：三家牌河聚拢于牌桌中央区域，各家牌河按座向旋转归位，摸打沿桌沿进行
- 「打出的牌放到中间」——本期主改动：牌河从各家面板内移出牌桌中央
- 「立直、牌型提醒、倒计时等等，这些都可以慢慢加」——立直入口（现有按钮）、牌型提醒、倒计时是渐进增强项，不是本期硬交付
- 「最终效果要先立主」——本期目标=主骨架布局定稿，细节槽位留好，后续迭代往里填

### 需求结晶（本需求偏「明确+隐含」类，模糊度低，五问自答留痕）

- C1 为谁解决什么问题：打牌的人（搭档+獭牌搭子）——当前牌河分散在左右侧栏玩家面板内，自己的牌河又在底部自家区，「谁打了什么、第几巡打的」需要满屏扫，不符合麻将牌桌直觉
- C2 现状怎么应付、代价是什么：现状是「面板式」布局（web-mahjong/index.html：左=上家面板 / 中=日志+提示 / 右=下家面板 / 底=自家区），各家牌河嵌在各自面板里。代价：牌河空间被面板宽度挤窄（6 列小牌 28px），中央大区域却给了日志——视觉重心错配（日志是辅助信息，牌河才是牌局主状态）
- C3 成功长什么样：打开牌局页，视觉中心是三家牌河围成的「桌心」——上家河在顶位居中、下家河在右侧、自己河在近侧（v3 座向，定稿见 D1），各家立直牌横置可见；日志退居底部通栏；第一眼就知道「现在打到第几巡、谁立直了」
- C4 明确不做什么：不做 3D/斜视角牌桌（雀魂是斜 45° 2.5D，我们保持俯视 2D）；不做图片牌面资源（继续 Unicode 麻将字符）；不改引擎/API 契约；本期不做牌型提醒与倒计时的功能实现（只留槽位）
- C5 最小可交付：牌河居中网格布局 + 各家面板瘦身为「信息条」（头像位/点数/风/立直徽标/副露）+ 日志/聊天移底部独立通栏

## 目标

T1：三家牌河聚拢牌桌中央（雀魂式桌心）——上家/下家/自己的牌河按座向摆放于中央区域，立直牌横置、摸打位置可辨
T2：主骨架布局定稿——场况角标、桌心（牌河+信息盘）、自家手牌区、动作栏的相对位置固化，后续增强（牌型提醒/倒计时/立直醒目化）往槽位里填
T3：布局改动不改引擎/API 契约——纯视图层重排（view.js 视图模型 + app.js DOM + style.css），服务端零改动
T4：渐进槽位落地——**保留现有计时器渲染位随动作栏迁移**（计时器是已在运行的功能：app.js renderActions 在 `awaitingHuman.deadline` 存在时渲染 `[data-deadline]` 元素，tickTimer 每 300ms 刷新常驻——重排动作栏时该渲染位必须随迁不丢，属回归风险项而非新功能）；场况角标预留牌型提醒位（本期可为空）

## 非目标

- ❌ 不做 3D/斜视角/动画特效（吃碰杠/和了横幅维持现状 by design，F20261020mjfx 已知口径）
- ❌ 不引入图片/字体资源（继续 Unicode 牌面 + 纯 CSS）
- ❌ 不改引擎、API、SSE 契约（T3 约束）
- ❌ 本期不实现牌型提醒（听牌提示/向听数）与倒计时功能逻辑——只留布局槽位
- ❌ 不动大厅/入座/结算遮罩的信息架构（仅随骨架适配样式）
- ❌ 不改聊天框交互（#1532 已落地，仅挪位置）

## 现状分析（锚点均来自本世工具读取）

### 当前布局（面板式）

`web-mahjong/index.html`（主仓，52 行）骨架：

```
header#field（场况栏：局数/本场/供托/余牌/宝牌/连接态）
main.table（三列 grid：minmax(210px,1fr) | minmax(300px,1.7fr) | minmax(210px,1fr)）
  ├ section#left.player--left（上家面板：内含其牌河 .discards）
  ├ section.center（claim 提示 + turnStatus + 牌局日志 ol#log + 聊天条）
  └ section#right.player--right（下家面板：内含其牌河 .discards）
section#self（自家区：meta 行 + 自己牌河 #selfDiscards + 动作栏 + 手牌）
```

痛点（对照雀魂）：
1. **牌河分散三处**——上家/下家牌河挤在 210px 侧栏里（`style.css` `.discards` 6 列、牌 28×38px），自己的牌河在底部 `#selfDiscards`（max-width 300px），三家牌河物理距离远，巡目对照困难
2. **中央给了日志**——`.center` 的主内容是 `ol#log`（max-height 240px 滚动列表）。日志是辅助回溯信息，雀魂的桌心是牌河——视觉重心错配
3. **无座向感**——三家面板横排三列，自己单独在底部，「桌」的空间关系（谁坐我上下手）不成立（三麻无对家）

### 可复用资产

- 视图模型纯函数层 `view.js`（330 行，零 DOM 零网络）：`panelsByPosition`（视角变换）、`playerPanel.discards`（牌河模型，含 riichi 横置标记）、`fieldInfo`、`actionBar`、`tileState`——单测 22 例（tests/web-mahjong/view.test.ts，grep 计数核实），改布局时这层大部分可不动
- 真 Chrome 视觉回归 `page-visual.test.ts`（4 例——入座渲染/聊天回显/观战入口/大厅页，grep 计数核实 + 截图基线 MAHJONG_SHOT_DIR）
- 样式变量体系（`style.css:5-25` 的 :root 设计 token）、`.tile--riichi` 横置样式已存在（`transform: rotate(90deg)`，牌河内）
- `.actionbar .timer` 计时器功能已在运行（app.js renderActions 渲染 `[data-deadline]` + tickTimer 300ms 常驻）——重排时随迁保留，非新建
- 三麻特性：无对家——雀魂四麻桌心的「对面牌河」位在三麻里天然留给场况扩展信息（宝牌/余牌/本场），空间反而宽松

## 方案设计

### 布局骨架（v3 定稿——搭档 16:56 拍板「v3 方向对了，按此开工实现」；真雀魂参照：Playwright 截 B 站牌谱视频，工作区 mahjong-ui-hifi-v3.html 为高保真定稿）

```
┌──────────────────────────────────────────────────────────────┐
│ 牌桌台面 .table-felt（一整块绿毡径向渐变，无面板拼接）            │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 角标（左上）：宝牌指示 · 牌型提醒槽位 · 连接态             │ │
│ │        [上家信息条·置顶] 名·风·点数·立直徽标（紫描边醒目）  │ │
│ │        [上家暗牌 背纹横排]  [上家副露]                    │ │
│ │              ╔══ 上家牌河（矩形区·置顶·牌全正朝向）══╗     │ │
│ │   ╔═════════╗  ║                                  ║     │ │
│ │   ║ 下家河   ║  ╚══════════════════════════════════╝     │ │
│ │   ║(右侧矩形 ║      ┌──── 中央信息盘 ────┐              │ │
│ │   ║区·牌全正 ║      │ 東X局·本场·供托棒·余牌 │            │ │
│ │   ║ 朝向)   ║      │ 〔兼〕结算停驻/claim浮层 │            │ │
│ │   ╚═════════╝      └───────────────────┘              │ │
│ │   [下家暗牌·竖排] [下家副露]                              │ │
│ │              ╔══ 自己牌河（矩形区·近侧·牌全正朝向）══╗    │ │
│ │              ╚══════════════════════════════════╝     │ │
│ │ [自己信息条·左下]                    [自己副露·右下]      │ │
│ │         [动作栏：按钮+提示+⏱计时器随迁]                 │ │
│ │         [自家手牌：近端底部大牌横铺·摸打分离]            │ │
│ └──────────────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────┤
│ 聊天通栏（独立底部，不与任何玩家条挤）：[日志流横排] [输入框+发送]│
└──────────────────────────────────────────────────────────────┘
```

**v3 核心决策（D1 翻转定稿）**：牌字符**全正朝向**（不倒不侧），旋转的是**摆放位置**不是字符——上家河在桌心远侧、下家河右侧、自己河近侧，三块矩形牌河区围桌心三方。真雀魂参照证实：雀魂牌河即矩形区域按方向摆放、牌字符永远正对玩家。

**中央必驻信息落位**（不变）：claim 浮层盖桌心绝对定位；结算停驻在中央信息盘位互斥切换（对局=信息盘，结算=结算面板）；turnStatus 并入信息盘（「轮到你了」指示）。

**聊天独立**：日志/聊天从早期的折叠面板方案改为**底部独立通栏**（日志流横排左 + 输入框右）——被否教训：不与任何玩家条挤。折叠面板机制四问/未读徽标随之**作废**（v3 无折叠态，机制增量归零——机制识别检查点恢复「无净新增机制」）。

**计时器**：保留随迁动作栏（回归风险项，不变）。

关键取舍说明：
- **牌河方向**：雀魂实体牌桌各家牌河朝自己（旋转 180°/90°），但我们是俯视 2D + Unicode 字符牌面——上家牌河旋转 180° 字符会倒立不可读。决策：**三家牌河全部正常朝向**（文字可读优先），座向由牌河在桌心的位置表达（顶=上家、右=下家、近侧=自己），定稿见「设计取舍」表 D1 与上方骨架图
- **中央信息块**：四麻的「对面牌河」位置放场况扩展（场风盘/余牌数/本场供托棒图形化）——雀魂桌心中央正是这个信息盘
- **日志/聊天移底部通栏**：`ol#log` 与聊天输入从桌心移到**底部独立通栏**（日志流横排左 + 输入框右，最新消息在最左常显；v3 无折叠态，不存在「收起才看得到」），与任何玩家条不共占——日志是回溯工具不是主状态
- **玩家面板瘦身**：左右侧栏从「完整面板（含牌河）」瘦身成「玩家条」（名字/风/点数/立直徽标/副露/暗牌数），牌河交出后宽度需求大降，桌心得以放大

### 观战态说明（发现 9 处置）

观战（seat=null，如 presetProxy 全 AI 试跑）时三家手牌对观战者全可见（app.js renderHand 现状）。重排后：观战态的玩家条扩展显示各家手牌横幅（玩家条增高模式，手牌不可点、无遮罩），桌心牌河区与对局态同构。入座遮罩（lobby）逻辑不动。

### 渐进槽位（本期留位不实现）

- **倒计时**（修正，发现 2 处置）：倒计时**功能已存在**——引擎 `awaitingHuman.deadline` 字段下发决策时限，app.js 渲染计时元素并 300ms tick。本期动作=动作栏重排时**保留 timer 渲染位迁移**（回归风险项，写进 T4 与验证）。真正的「新机制」是超时自动打牌/超时代打——那才需引擎侧立项，另行讨论
- **牌型提醒**：场况角标 `#field` 内留 `.fc-hint` 槽位（本期占位文案「牌型提醒 · 预留」）——听牌提示需要裁判引擎暴露听牌/向听数据，API 契约扩展另行立项
- **立直醒目化**：已落地——立直玩家信息条紫色描边（`.pinfo.is-riichi`，CSS 纯样式零新机制）+ 牌河立直牌横置沿用；牌河内立直棒图形图标本期未做（可选增强，不进验收）

## 影响范围

- 纯前端静态资源（web-mahjong/），服务端零改动，API/SSE 契约不动

## 风险与约束

| 风险 | 等级 | 缓解 |
|------|------|------|
| Unicode 牌面旋转不可读，座向感弱化 | 中 | D1 决策全正朝向+位置归属；若搭档实测后仍想要雀魂式旋转，可作为后续迭代（需接受上家牌面倒立或换图片资源） |
| 窄屏（<940px）桌心被挤 | 中 | 断点重排：台面压成单列纵队（角标入流置顶 → 上家块 → 信息盘 → 下家块 → 自家行 → 手牌），牌河降 26px 紧凑、聊天通栏堆叠——page-visual 窄屏用例断言单列与角标入流 |
| 通栏日志只显最近若干条，更早消息需横向滚动回看 | 低 | 日志横排新在最左（最新消息常显不漏看）+ `slice(0,40)` 保留 40 条可滚回溯；v3 无折叠态，原「折叠后聊天不易察觉 + 未读徽标」风险随折叠面板作废 |
| 三麻无对家的空位利用不当显空 | 低 | 中央信息块填场风盘/余牌/本场——雀魂桌心本来就有这个信息盘 |

## 设计取舍

| # | 取舍 | 决策 | 替代方案 | 理由 |

## 机制识别检查点（逐项，v3 定稿口径）

- □ 新增配置字段/枚举/开关——无
- □ 新增状态生命周期——**无净新增**（论证见下）
- □ 新增定时任务/后台进程——无（计时器 tick 已存在，仅渲染位随迁）
- □ 新增信号类型/消息格式——无
- □ 新增持久化存储——无
- □ 新增决策分支（结果被记住）——无（布局分支纯运行时）
- □ 新增跨模块调用路径——无（同模块内重排）

**状态生命周期为何算无净新增**：

- v2/D2 支路的「折叠面板展开/收起态 + 未读计数徽标」在 **v3 定稿时作废**（v3 无折叠态，日志/聊天独立底部通栏）——下「折叠面板机制四问」整节随之失去宿主，仅作历史留痕，实现未落任何一行
- claim 显隐、结算显隐、轮到谁三种展示在**旧骨架已存在**（renderCenter 内按 decision/settlement 切换），v3 只是换了渲染位置（claim 盖桌心 / 结算占信息盘位）
- 新增的 `felt[data-state="play|settle"]` 是**派生属性不是独立状态**：每次 render 由 renderSettle 重算，无同步负担、无生命周期管理、不被任何逻辑回读（与既有 `#app[data-state]` 同一模式）

**判定：机制增量 = 0 → 不升重对抗门**，常规对抗审视照走（首轮已走，delta 复核会覆盖本节修订）。对应 commit 声明 `Modification-Class: narrow-fix`（既有视图层语义内重排，非机制新增）。

<details>
<summary>折叠面板机制四问（v2 支路，v3 已作废——历史留痕）</summary>


1. **谁需要**：折叠面板是主骨架的副产物（日志让位于牌河后必须有家），不是独立需求；未读徽标服务「折叠态下獭牌搭子聊天不漏看」
2. **失败后果**：折叠态/未读数错乱最坏=用户多点一次展开，无数据损坏、无引擎影响——失败代价极低
3. **后续机制**：不拉后续——不依赖后端、不扩展 API、纯 app.js 客户端小状态
4. **退役条件**：若后续日志找到更好位置（如桌心下方常驻窄条），折叠面板整体退役，无遗留负担

**实现约束声明**（发现 6 处置）：现状每条聊天消息触发整页 render 重建（innerHTML 全量）。折叠面板状态与未读计数必须由 app.js 独立小状态管理，**不随 render 周期重建**（否则展开态被打断、滚动位置丢失、未读数被重置）——实现期验收点。

**判定（v2 口径，已被 v3 覆盖）：机制增量=1 个会话内 UI 小状态（折叠+未读），四问过后果轻量** → 不升重对抗门。

</details>

### 关键实现决策（L1 留痕，侳检视獭核对）

1. **桌心用 grid 四行而非 hifi 的全绝对定位**：hifi 稿牌河是 `position:absolute` 定点，牌河长到 4-5 行会直接压到中央信息盘上；grid 下行高自适应，牌河增长只推不开不重叠。几何与 hifi 等价（上家河顶位居中 / 下家河右侧跨行 / 自己河近位居中 / 信息盘桌心）。
2. **claim 浮层 `pointer-events:none` + 卡片 `auto` + `.hand-zone{z-index:7}`**：浮层 `inset:0` 盖满台面时默认会拦死底部动作栏（吃碰和按钮在那里）；三层处理后压暗不压手——actionBar 与手牌保持命中（page-visual 用 `elementFromPoint` 锁死）。
3. **信息盘↔结算互斥 = `.table-felt[data-state=settle] .info-hub{display:none}`**：施工中自检发现只写了注释没写规则（结算面板半透明背景会透出信息盘），已补规则 + 新增状态契约测试锁死；行高由 `grid-template-rows` 的 `minmax(168px,1fr)` 兑住，退位不塔台面。
4. **DOM id 随座向语义更名**：`#left/#right` → `#kamicha`/`#shimocha`（v3 里上家在顶不在左，留旧 id = 误导）；牌河 `#riverSelf` + 座位块内 `.discards`；同步改 page-visual 4 处选择器。
5. **副露/拔北为空不占位**：删掉「副露 —」「拔北 0」占位字（截图自检：三条悬空占位字是泔水）；空区由 `.melds-zone{min-height:20px}` 兑高度，首副露出现不跳版。
6. **牌河轨道 `repeat(6, minmax(0,30px)) + justify-content:center`**：固定列宽、轨道组居中——窄屏下牌河通栏拉宽时牌不被拉散；窄屏断点降 26px 紧凑。
7. **`.selfrow` 用 `minmax(0,1fr) auto minmax(0,1fr)`**：两个 1fr 侧翼夹住牌河，保证自己河**精确**水平居中（测试锁 `|cx−台面中心|<8px`，上家河同阈值）。
8. **view.js 防漂移**：立直横置标记从 `playerPanel` 内联推导抽成 `riverModels`，`playerPanel.discards` 与 `riverTable` 共用同一处（测试断言两者 `toEqual`）；`playerStrip` = panel − discards，app.js 从 strips 取信息、从 riverTable 取牌河，**牌河只有一个渲染点**（D4）。
9. **计时器零改动**：`renderActions` 的 `[data-deadline]` 渲染位原样随迁进 `.hand-zone`，`tickTimer` 300ms 循环一行未动；测试新增断言「渲染位在 `#actionbar` + tick 回填 `倒计时 Ns`」（首渲染为空串，故 waitForFunction 等一拍）。
