# F20261020desg: 研发 skill 链路优化

## 背景与需求

### 问题描述

2026-10-20 外部洞察对话三条深挖（AI 代码理解困境 / tmux 多 agent 编排 / reason-network+graphicle）收敛出「信任工程」主线，搭档逐条裁决后保留三处缺口，全部落在研发 skill 链路：

1. **设计权保留缺纪律**：业界共识「LLM 写抽象，任务总能完成但不可维护」（HN 50151036 全树调研，全场最热观点）。我们方案期有搭档拍板，但实现期的抽象决策（模块切分、接口签名、数据结构）由 AI 自由发挥——信任链条上游（架构对）没人把关。
2. **验收标准散文化**：完成标准写成不可机械判定的描述，「验证通过」的语义留给人工自由裁量。调研共识③：验证有效性必须可测量。
3. **失效文档/决策无人补**：改动使既有文档/决策描述失效后过时残留。曾设计「PR 合入后提醒记录可能过期」机制，被搭档否决（16:56 原话要点：改动是自己做的有没有变化不知道吗、事后提醒是污染上下文、append only 记忆不需要「可能过期」措辞）——正确形态是当场纪律，不是事后扫描。

### 收敛过程（决策史，防漂移）

同日早前方案曾含「种 bug 审视有效性测量」「事后记忆对账提醒」两项，均被搭档否决（一次测试对概率系统无统计意义 / 事后提醒马后炮且污染 append only 记忆），就地终结不转世；「规格可执行化」最初误判与验收判据闸（docs/features/2026/10/13/ 下 acceptance-criteria-gate 文档）撞车，复核原文后修正：该特性管「纪律条文在位保护」，与「验收标准写成断言」是相邻不是重叠，真正落点即本文档第 2 项。

## 目标 / 非目标

### 目标

- code-implementation skill 增加设计面确认纪律（架构/抽象层拍板，代码填空 L0 自治）
- 特性文档「验收标准」段机械断言化（场景/操作/预期结果三列，PASS/FAIL 可判定）
- 影响面当场自检纪律（本 PR 内补失效文档/决策，禁事后补刀）

### 非目标

- 不建审视有效性校准制度（钓鱼实验已被否决）
- 不建记忆过期扫描/提醒机制（已被否决）
- 不引入符号级 AST 锚点等重型文档追踪（graphicle 式实现，评估为成本不配收益）
- 不改 worktree-isolation / requirement-analysis 等其他 skill（本 PR 只动 code-implementation；后续观察行为效果再定是否外溢）

### 机制预算四问（对三处纪律子段作答，S1 处置）

1. **防什么**：防设计权旁落（实现期抽象决策 AI 自由发挥）、防验收标准不可机械判定（验证有效性无法测量）、防改动失效的文档/决策过时残留。
2. **不防什么**：不防实现细节错误（测试/对抗审视覆盖）；不防审视习惯化（钓鱼校准已被搭档否决，明确不建）；不扫记忆过期（无扫描机制，当场性纪律仅限本 PR 作用域）。
3. **退役条件**：观察期（合入后约 2 周 / ≥10 个实现类 PR 行为样本）内若出现：设计面确认流于形式无人看、验收断言被「人工判读」出口滥用（机械断言占比 <50%）、影响面自检零触发——对应子段收窄或退役，不硬留。
4. **维护成本**：文本纪律零代码维护；每次实现类 PR 增加两个动作（列设计面、写 AT 表），观察期后按行为样本回看是否收敛。

### 取舍表

| 取舍 | 选择 | 理由 |
|------|------|------|
| 设计面确认放步骤 2 内 vs 新增独立步骤 | 并入步骤 2 | 工作流步骤编号被外部文档引用（「步骤 10」等），重编号破坏锚点 |
| 事后扫描提醒 vs 当场纪律 | 当场纪律 | 搭档裁决原话：改动是自己做的当场就知道，事后提醒是污染 |
