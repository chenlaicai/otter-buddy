# F20260717gure [memory] 术语库系统概念初始化

## [design-time]

> 以下章节在需求收敛与设计阶段（代码前）完成并锁定。
>
> 本文档设计术语库的系统概念初始化方案。术语库已有 8 个种子术语（来自产品形态定义），需要补充本系统特有的核心概念。
>
> **设计共识**：术语库收录本系统内部定制的词汇，这些词汇在非本系统中可能有其他语义。不收录通用概念（库、渐进式披露、Agent 等）。术语清单：9 个术语（8 个种子 + 1 个新增"发言石"）。种子数据外部化：将种子数据从代码硬编码改为外部 JSON 文件，实现数据与代码分离。
>
> **术语清单**：
> 1. 大獭（实体）- 用户唯一持久 Otter，带有独占能力
> 2. 小獭（实体）- 大獭按需创建的临时 Otter，任务结束解散
> 3. 对话（概念）- 用户与 Otter 的交互单元，可以是 1v1 或多 Otter
> 4. 重启獭生（机制）- 用户表达不满时触发的 Otter 个体内部机制
> 5. 统一能力库（模块）- 系统级 Skill 集合
> 6. 记忆系统（模块）- 系统级模块，标准化接口，多库架构
> 7. 手脚（概念）- 工具/Skill/外部系统
> 8. 对话关键信息（概念）- 每个对话的关键信息（开放机制）
> 9. 发言石（机制，新增）- 对话中的发言权控制机制，控制哪个 Otter 可以发言
>
> **约束输入**：
> - F20260716hkv3: 术语库实现已锁定
> - F20260709x7k3: 产品形态定义中的 8 个核心术语
> - 用户要求：术语库收录本系统内部定制的词汇

## 目标 [required]

### P1 - 术语初始化

在术语库中初始化本系统的 9 个术语（8 个种子 + 1 个新增"发言石"）。

### P2 - 种子数据外部化

将种子数据从代码硬编码改为外部 JSON 文件，实现数据与代码分离。

- 文件位置：`data/terminology/seed-terminology.json`
- 同步逻辑：比对差异，新增/更新，不删除
- 幂等性：每次启动都执行同步，但只在有变化时才写入

### 种子数据外部化

#### 当前架构

```
seed-terminology.ts（硬编码 SEED_ENTRIES 数组）
    ↓ 系统启动时（表为空时导入）
SQLite 数据库（terminology_entries 表）
```

#### 改进架构

```
data/terminology/seed-terminology.json（外部文件）
    ↓ 系统启动时读取
    ↓ 比对数据库差异
    ↓ 自动同步（新增/更新）
SQLite 数据库（terminology_entries 表）
```

#### 同步策略

| 场景 | 处理 |
|------|------|
| 文件中有，数据库中没有 | 新增 |
| 文件中有，数据库中有但内容不同 | 更新 |
| 文件中有，数据库中有且相同 | 跳过 |
| 文件中没有，数据库中有 | 保留（运行时用户添加的术语） |

#### JSON 文件格式

```json
[
  {
    "term": "大獭",
    "aliases": ["Big Otter"],
    "definition": "用户唯一持久 Otter，带有独占能力",
    "category": "实体"
  },
  ...
]
```
