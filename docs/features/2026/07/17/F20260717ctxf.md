## 4. 方案设计

### 4.1 变更点

**文件 1: `src/interface-adapters/agent-runtime/agent-invoker.ts`**

- `buildDynamicContext()` 方法：移除 `searchMemory.search()` 调用及相关代码（lines 178-191）
- 构造函数：`searchMemory` 依赖**保留**（HTTP API 和 MemoryController 仍需要）

**文件 2: `src/interface-adapters/agent-runtime/agent-invoke-port.ts`**

- `DynamicContext` 接口：移除 `memoryRetrieval` 字段（lines 23-26）

**文件 3: `src/frameworks/agent/system-prompt-builder.ts`**

- `DynamicContext` 接口：移除 `memoryRetrieval` 字段（lines 11-14，与文件 2 重复定义）
- `buildSystemPrompt()` 函数：移除 `## 记忆检索结果` 拼接逻辑（lines 56-58）

**文件 4: `src/frameworks/agent/pi-session-factory.ts`**

- `buildMessageWithContext()` 方法：移除 `## 记忆检索结果` 拼接逻辑（lines 446-448）

**文件 5: `tests/frameworks/agent/system-prompt-builder.test.ts`**

- 更新涉及 `memoryRetrieval` 的测试用例（lines 10, 60, 71）

### 4.2 不变的部分

- `search_memory` tool（tool-factory.ts）：保持不变，作为 agent 主动召回的唯一途径
- `get_memory_detail` tool：保持不变，渐进式披露
- `search_terminology` / `add_terminology` tools：保持不变
- `sessionSummary` 注入：保持不变（会话状态 ≠ 记忆）
- `searchMemory` 构造函数依赖：保留（HTTP API 仍需使用）

### 4.3 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| agent 不主动调用 search_memory | 对话缺少历史记忆上下文 | agent 已注册该 tool 且有使用能力；system prompt 中可添加指引 |
| 首轮对话无预加载记忆 | agent 需要自行判断何时检索 | 这正是设计意图——agent 有自主权 |


## 5. 设计决策记录

| 决策 | 正方 | 反方 | 结论 |
|------|------|------|------|
| 移除强制注入 vs 保留双通道 | 用户明确要求"作为工具提供"而非"强制注入"；双通道导致 agent 收到重复信息 | 移除后 agent 可能不主动检索 | 移除强制注入。UA-2 明确说"关键核心差异" |
| sessionSummary 是否保留 | 会话状态是运行时上下文，非"记忆召回"；agent 无法自行获取 session 信息 | 若保持一致性，也应改为 tool | 保留。会话状态 ≠ 记忆，性质不同 |
| searchMemory 构造函数依赖 | HTTP API 和 MemoryController 仍然需要 | 移除 buildDynamicContext 调用后，agent-invoker 内部不再直接使用 | 保留依赖。HTTP API 调用链不可断裂 |


## 6. 不兼容更新

- 相关测试用例需同步更新
