## 两遗留问题修复

### 修复1：scripts/otter-buddy.sh 端口口径对齐 loadConfig（修法① narrow-fix）

- **根因**：脚本第 7 行 `PORT="${PORT:-3000}"` 写死，健康检查（:96）与端口预检（:43）查错端口；服务监听端口唯一裁决者是 `config/config.yaml` 的 `server.port`（config-service.ts:609 applyDefaults `server: { port: d(raw.server?.port, 3000) }`）。
- **修法**：新增 `resolve_config_port()` 解析 config.yaml 的 `server.port`（grep 首个 `port:` 数字行，兼容可选引号 `port: "3102"`——对齐 TS 侧 d() 接受字符串的行为），端口优先级：`-p/--port` 显式参数 > config.yaml > 3000。usage 文本同步更新。
- **env 层否决**（检视獭-1258 S-1）：初版保留 `PORT` env 压过 config，但服务端 src/ 全域零消费 `process.env.PORT`——env 只改脚本探测口、改不了服务监听口，会重现错位误报，与本 PR 目的相悖。已删除 env 层，实现与注释、loadConfig 口径三方统一为三段式。
- **决策树**：① narrow-fix ✔（只改端口推导，不动健康检查逻辑）；② 无需加开关——config 不存在时回落 3000 与原行为一致；③ 不改默认值——3000 仍是缺省。

### 修复2：app.ts patrolWorker.start 移到 initAgentAndScheduler 之后（修法① narrow-fix）

- **根因**：`patrolWorker.start()` 原在 L265（schedulerService 声明于 L327 的 TDZ 期内），PatrolWorker.start 立即同步跑首轮 tick，'scheduler-reconcile' duty 闭包执行 `schedulerService.reconcileMissedWindowsNow()` → `ReferenceError: Cannot access 'schedulerService' before initialization`（dist/src/app.js:141:68，9/30 09:33 启动日志实证）。
- **修法**：构造保持原位（duty 闭包延迟绑定），`start()` 移到 `agentInvokerRef.current = agentInvoker` 之后（schedulerService 已初始化）；dispose 路径原加 `patrolWorkerStarted` 标志防御，**10/1 rebase 处置时删除**（stop 幂等实证：timer null 安全 + stopped 标志 + inflight await，src/usecases/health/patrol-worker.ts:60-66；且 rebase 净增行把 app.ts 顶破 max-lines 450 上限，删冗余标志回归 main 原状语义，见 commit 8b203ceb）。
- **决策树**：① narrow-fix ✔（只移动 start 调用位置，不动构造/duty 定义）；② 无需开关；③ 不改变 tick 语义（首轮仍在启动后立即跑，只是时序合法化）。
- **备选方案否决**：「首轮 tick 延迟」会改变运行时对账时效语义（#823 要求启动即对账），且延迟时长拍脑袋，不如顺序调整干净。

## Discovered Issues（不在本 PR 修复，是否立项由搭档决定）

1. **config 写保护/审计 + 守卫盲区收口**：主仓 config.yaml 可被任何 cwd=主仓的会话随手改写——本次正是小獭经 `python3 -c` 直执行盲区改写（初版误标为「搭档自己」，10/1 更正；此盲区使守卫防线对小獭失效，防护紧迫性高于初版评估）。建议方向：写保护开关或写入审计日志（谁、何时、改了什么）；守卫侧补解释器直执行形态（python3 -c / node -e）的主仓写检测。
2. **bash-safety-guard 拦截主仓跑 alpha.sh**：主仓根目录跑 `alpha.sh start` 会残留 `.otter-alpha.json`（本次 3146 实例至今存活），且与主服务共享 data/ 目录有交叉污染风险。建议守卫识别「cwd=主仓 + alpha.sh」组合并拦截。
3. **alpha.sh 与手工验证实例互检**：本次 77757 手工拉起 3102 与 alpha.sh 的 hash 端口段（3178）脱节，建议 alpha.sh start 前扫描 3100-3198 占用情况并告警，或在 `.otter-alpha.json` 登记手工实例。
4. **守卫误拦 worktree 内 otter-buddy.sh**：本次验证修复①时守卫把「worktree 内跑 otter-buddy.sh start」一律拦为主进程管理，实际目标端口 3194/3196 与主服务无关。建议守卫区分「worktree 隔离实例（端口≠3000 或 cwd=worktree）」与「主进程」。
5. **守卫误拦更宽形态**（检视獭-1258 补充）：只读 grep/sed 命令只要字符串里含 worktree 内该脚本路径也被拦（路径引用判为间接调用特征），且 commit message 文本含脚本名同样触发——扫描面应剥离「文本提及」。
6. **startRhiWorker 开关名语义错位**（检视獭-1258 A-2）：该选项现控制 patrolWorker 全部 duty（scheduler-reconcile/signal-aging/rhi-signal-aging/rhi-scan/embedding-retry），名字只提 RHI。建议后续改名 startPatrolWorker，本 PR 不动。
