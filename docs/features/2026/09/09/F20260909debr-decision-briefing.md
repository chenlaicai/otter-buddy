# 决策分级与终审简报——消灭盲签拍板

## 用户意图锚

| # | 来源 | 用户原话（逐字引用） | 架构师解读 |
|---|------|---------------------|-----------|
| UA-1 | 本对话 2026-09-09 | 有时候你们海獭讨论完一个方案后，大獭会让我拍板继续往下做。但此时往往我根本不知道你们都讨论了些啥，然后最终方案是啥。我其实是没有概念的，只看到了几个问题描述，说实话我很难给出准确的决策。 | 终审时刻信息不对等：决策材料（讨论脉络+方案全貌）没有随决策请求一起送达 |
| UA-2 | 本对话 2026-09-09 | 什么东西需要让我看到、让我决策，什么东西是你们海獭间自己就讨论决策了 | 需要显式的决策分级边界 |
| UA-3 | 本对话 2026-09-09 | ok。你继续 | 对方向（分级+简报两线）无异议，授权落地 |

## 背景

记忆脉络：F20260813dr27（big-otter-question-mode，issue #257）治过同一硬币的另一面——「大獭一次抛 5 个问题、部分可自行决策」，当时确立了「提问模式」条款（能自行决定的不问，给推荐方案+理由）。本次是互补治理：**该问的问了，但决策材料没给够**——现状「呈搭档终审」散落在 4 个 skill 里、各自一句话带过、无任何简报格式要求，这是裸奔拍板的结构性来源。

## 方案设计

### 1. 决策分级（SYSTEM.md 新增 R8）

| 层级 | 范围 | 动作 |
|------|------|------|
| L0 獭自治 | 实现细节、库选型、测试写法 | 不问，干完在汇报里提一句（现状已有：技术决策权条款） |
| L1 獭拍板+留痕 | 架构取舍、数据结构、流程内调整 | 獭定，记录理由进特性文档/决策记录；搭档事后可追溯、可否决——否决成本低的都归这层（**新增**，此前模糊、常被升级到 L2 烦搭档） |
| L2 搭档拍板 | 产品方向、资源投入、对外承诺、不可逆操作、獭间方向分歧 | 必须问，但必须配决策简报——不允许只抛问题裸奔 |

**默认通过模式**（新增）：L2 中低风险项用「我推荐 X，理由如下，今天内无异议就开工」——把「必须即时响应」改成「异步默许」。高风险/不可逆项不适用。

### 2. 决策简报（review-protocol/references/decision-briefing.md，新建）

凡 yield to user 请求拍板（含审视僵局呈裁决）必附六要素：①一句话结论 ②背景≤3 行 ③选项对比（**含被否方案+否决理由**——搭档最容易盲区的正是"还有哪些路没走"）④獭间分歧如实呈现（收敛结论≠分歧消失）⑤推荐+理由+置信度+最大风险 ⑥锚点（文档 ID/讨论位置）。

模板放 review-protocol references 而非散落各 skill 内联——单一真相源，四处引用。

### 3. 绑定点（4 个终审出口 + 身份 prompt）

- review-protocol：步骤 5 终审改为必须附简报；产出表同步
- code-implementation：步骤 9 审视通过呈终审 + 产出表
- worktree-isolation：小改动 PR 终审（产出表）
- adversarial-review：产出表 + 行动权路由表「传 user」行
- BIG_OTTER.md：新增「呈搭档拍板的硬规则」节，承接已有「提问模式」条款

### 4. 习惯养成

裸奔拍板纳入每日 review 观察项（统计次数）。软规则难在执行，观察项让退化可现形。

## 影响范围

纯 prompt/skill 层改动，零代码逻辑变更。所有经 .pi/SYSTEM.md 注入的海獭（大獭+小獭）生效；4 个 skill 的引用改动影响对应流程的呈终审发言。

## 取舍

- **简报模板放 references 而非内联各 skill**：内联 4 份会漂移；代价是 lint 警告（引用未内联），可接受
- **不做 UI 层强制（如 yield to user 前的机械校验）**：简报质量依赖情景判断（什么是"中低风险"），机械校验只能查关键词存在性，查不出"背景写了但等于没写"。先用观察项跑一段时间，若退化再考虑 golden 场景化
- **L1 层「事后可否决」依赖特性文档留痕**：与既有「决策记录进文档」约定叠加，不新增机制

## 验证

- `npm run lint:skills` 通过（11 warnings 均为既有类别 + 2 条新增「引用未内联」建议，属预期取舍）
- 行为验证：本 PR 自身的呈终审发言即按新简报格式输出（自举验证）
