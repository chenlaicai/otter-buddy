# RRSI 纪律移植：噪声带对照、负证据防线与剪枝出口

## 背景

今日雷达深挖 RRSI（google-research/rrsi，arXiv 2609.24972）——Google Research 的 agent harness 自动进化框架。其自动评测 loop 依赖三个海獭不具备的前提（ground truth 评分、任务可重复、评估便宜可烧），**不可搬运**；但其正则化设计中的三条纪律与海獭痛点一一对应（深挖笔记：外部洞察对话 `research/rrsi-deep-dive-2026-09-29.md`）：

| RRSI 兵器 | 对应痛点 | 海獭现状 |
|---|---|---|
| 噪声带 δ（涨分 <2σ 不认） | 「一直在改，效果凭感觉」 | 无——指标涨跌无人问「在噪声带内吗」 |
| 负证据纪律（被否机制不许换皮重提） | 事故后加规则，规则拟合事故 | 有教训库，无「提案前查否决」动作 |
| 剪枝即合法编辑（无改进组件删除算贡献） | 系统只增不减，细节藏问题 | 增长纪律只管增，无减的出口 |

关键既有事实：`GET /api/health/trends` 历史序列端点已存在（F20260829hviz，8-29 起积累数据）；RHI 特性链生命周期为 active/stalled/regressed/orphan 四态（zombie 态已在 F20260902sigm 删除；orphan 语义是 doc-gap——代码有 commit 但文档缺失，不是僵尸组件）；体检 prompt body 9164B，budget_bytes 9200B，超警告线 8000B 达 1164B——增量纪律要求加 X 减 X。

## 目标

T1: **噪声带对照纪律**——每日体检中所有健康指标涨跌声明，必须附近 7 日序列常态波动范围对照；带内涨跌降权或不报，超带才构成信号。
T2: **负证据防线**——立项/提案流程（requirement-analysis、otter-summon）前置「否决史检索」：新机制提案必须检索历史否决/教训记录，命中则在设计取舍中显式回应「为什么这次不同于被否情形」。
T3: **剪枝出口**——月度剪枝审视：基于 RHI stalled/regressed 态 + 引用静默期生成候选清单，呈搭档裁决，删除走 PR 可回滚。

## 非目标

- 不搬 RRSI 自动评测 loop（n=1 无 ground truth，强搬即重蹈 #1147 孤岛覆辙）
- 不建 A/B 或回归评测基建（#1147 已否决的路径，本特性不重开）
- 不动 SYSTEM.md 增长纪律（A4：纪律文字已有，缺的是出口；出口建在流程层，SYSTEM.md 不加字）
- 不做 skill 使用量的机械埋点（无使用日志表，代理信号足够，埋点是新增机制不划算）

## 未决问题

1. D3 静默期阈值：候选组件多久无引用算僵尸？（方案默认 90 天，待搭档拍板或首轮审视后定）
2. D3 周期：月度（方案默认）vs 双周——依赖首轮清单的候选数量再调。

## 方案设计

### D1 噪声带对照（T1）——落点：每日体检 prompt

**数据源（已存在，零新增）**：`curl http://localhost:<port>/api/health/trends`（近 7 日指标序列）。

**机制**：在体检 prompt「分析纪律」段新增「噪声带对照」硬规则（同步在数据源清单加 trends 一项）：

> 指标涨跌声明必须对照近 7 日序列：给出「今日值 vs 近 7 日 min-max（或 IQR）」，落在常态波动带内的涨跌不得作为信号上报（可列「带内」但不展开）；只有超出波动带的涨跌才进入 issue/日报素材。数据不足 7 日的新指标，标注「基线不足」不硬给结论。

**体积纪律（预算闸合规，实测出清明细）**：体检 prompt body 9164B（budget_bytes 9200B，超警告线 8000B 达 1164B）——增量纪律：加 X 减 X。本 PR 实测：新增噪声带段 355B，出清 10 处共 524B（锚点抽查#2 论证尾巴 67B / 信噪比标题重复修辞 63B / RHI 段标题 28B / healing 段标题 24B / healing 废除说明 42B / 止损线嵌套括号 23B / 范围约束例举 24B / 数据源#5 冗余途径 51B / 验证断言回查句 19B / 分析纪律括号展开 203B），修改后 body 8995B，**净减 169B**。

**指标适用范围（单调累积量不适用带对照）**：仅对比率/均值/日增量类指标（如 bugfix_ratio、日新增 issue 数）做带对照；累积量（total_commits、total_prs 等单调只增量）直接报日增量，不做带对照——否则「今日值落在 7 日区间内」会被误读为带内，把正常累积当噪声压制。新指标序列不足 7 日标「基线不足」不硬给结论。

**对照 RRSI 原设计**：RRSI 的 δ 是 bootstrap 统计噪声带，本方案用近 7 日 min-max 是粗粒度代理——体检是 LLM 读数判断，不是统计检验，粗粒度即可杀死「±5% 涨跌当信号」这类主要假阳性；不追求统计严格性。

### D2 负证据防线（T2）——落点：requirement-analysis + otter-summon 两个 skill

**requirement-analysis 步骤 3（检索上下文）改造**：现行为「search_memory 找历史决策」——找支持为主。改为**先找反对**：

> 检索顺序：①先搜「同类提案 + 否决/撤回/教训/翻车」类记录；②命中则定位当时的否决理由，写入「设计取舍」表——新方案必须显式回应「与被否情形的差异点」；③查不到否决史再走常规历史决策检索。litmus 问句（借自 RRSI critic）：「这个规则在不熟悉的场景里还帮忙吗，还是在拟合那次事故？」

**otter-summon 前置检查补强**：现有「MUST 先 search_memory 检查已有结论」保留，补一行「含否决史——被否决的方案路径不重复召唤，除非新证据推翻否决理由」。

**检索主力是记忆关键词，不是结构化关系**：实测（2026-09-29）features 表 supersedes 字段非空仅 3 条（722 条为空数组）——结构化否决关系覆盖率 0.5%，不能作为主力依赖。主力：记忆关键词语义检索（实测：「1147 撤单」「出厂判断门 取消」均能命中；「Jev 三段式」语义漂移到「搁置」——检索有漂移但可接受）；辅助：issue closed 状态 + F 文档 supersedes 关系（如有）。提升结构化程度需单独特性做否决关系标注，不在本方案范围。

### D3 剪枝出口（T3）——落点：月度定时任务 + RHI 消费

**分三层，全部消费既有数据，零新增存储**：

1. **候选生成（定时任务）**：新建 `monthly-prune-review` 定时任务（create_scheduled_task，月度），审视范围：
   - **skill 层**（`.pi/skills/` 全量）：memory 检索各 skill 名的最后实质引用 + 对话流提及——静默超阈值（默认 90 天）入候选。**代理信号局限性（如实声明）**：memory 里「skill 名出现」可能是「讨论」而非「使用」，routine 使用不产生 memory 条目——因此候选清单必须附「检索方式与命中明细」，裁决者认为代理信号不可靠时可要求补证据再裁；连续 3 轮全拒则触发退役条件
   - **机制层（代码机制）**：RHI 特性链 **stalled 态**（pr-stalled 投影，长期无推进）+ **regressed 态**（出过回退）+ `scheduled_task_executions` 长期零产出任务入候选。（注：zombie 态已在 F20260902sigm 删除；orphan 态是 doc-gap 语义（代码有文档无），不是剪枝候选——本轮审视修正）
   - **prompt 段落层：暂不实现**（原设计「纪律段产出 issue 零复发→纪律过时」需「纪律段→issue 类型→复发频率」三层映射，代码里无此数据，建映射表成本不成比例——降级为首轮只跑 skill 层 + 机制层，段落层视首轮效果再议）
2. **裁决（搭档）**：候选清单以 html-card 呈报（组件名/最后引用时间/静默天数/删除影响面/建议动作），搭档逐项裁决——删 / 留观 / 保留。**裁决权恒在搭档**（对应 RRSI 的 incumbent fast-forward 前的 critic 终审）。
3. **执行（可回滚）**：skill/prompt/代码删除一律走 PR（git 追踪文件，误删可 revert）；特性文档退役走 superseded 状态；定时任务撤销走任务删除。**剪枝即合法编辑**：剪枝 PR 与功能 PR 同等对待（同签名/同审视），不因「只是删除」跳过流程。

**对照 RRSI 原设计**：RRSI 的 n_prune=4 由引擎自动执行，本方案裁决权留搭档——系统级组件的删除影响面无法机械评估（无 S），人裁决是诚实的选择。

### 机制识别检查点（步骤 5 硬要求）

- D1：改既有 prompt 内容 → 无新增机制，不命中
- D2：改既有 skill 内容 → 无新增机制，不命中
- D3：**新增定时任务** → 命中「新增定时任务/后台进程」，四问必答如下

**机制预算四问（D3 月度剪枝审视任务）**：

① **谁需要它**：搭档——系统只增不减的直接承受者（「细节都藏着问题」）；大獭——增长纪律的执行者现在只有「增」的闸没有「减」的出口。具体消费方：每月一次清单裁决，约 10 分钟。

② **失败后果**：纯内部——清单质量差（误列活跃组件）时代价是搭档裁决时分心；无用户可感知损害。最坏情况：误删组件 → PR 可 revert，且删除走 PR 本身有审视闸。次要风险：月度空转（清单长期为空）→ 由退役条件兜住。

③ **后续机制**：新状态「剪枝候选清单」可能出错的方式与修法——误判活跃组件为僵尸（引用检索漏检：组件被高频使用但 memory 不记 routine 使用）→ 修法：候选清单必须附「引用检索方式与命中明细」供裁决者质疑；清单越积越大没人裁决 → 修法：清单超 10 项未裁决时任务自动降频并在日报标注；阈值漂移争议 → 修法：阈值写在任务 body 里，调阈值=改任务，留痕。

④ **退役条件**：连续 3 个月清单为空（无候选产出），或搭档连续 3 轮全部拒绝候选（信号=清单生成逻辑与搭档判断系统性脱节）→ 撤销该定时任务，留 feature 文档记录退役原因。

## 影响范围

- 每日体检产出形态：涨跌声明带波动范围对照，日报更短更硬（带内噪声被压制）
- 立项流程：requirement-analysis/otter-summon 增加一步检索，流程微增重（~1 次检索/提案）
- 月度新增一次搭档裁决交互（清单卡）
- RHI stalled/regressed 态从「展示态」升级为「消费态」——面板语义不变，下游多了出口

## 风险与约束

- **噪声带误杀真信号**：小基数指标（如 healing critical 数）7 日窗口波动天然大，可能把真异常吞进带内 → 缓解：critical 级信号不受带内压制（信号本身带 severity 语义，带对照只管「趋势类」声明）
- **单调累积量误判**（首轮审视发现）：total_commits 等累积指标的 7 日 min-max 不是波动带而是累积区间，「带内不报」会把正常累积误判为噪声 → 已在 D1 指标适用范围中限定：累积量只报日增量不做带对照
- **负证据检索漏检**：教训库无结构化「否决」标记，语义检索有漂移（实测「Jev 三段式」漂到「搁置」）→ 缓解：多关键词组合（否决/撤回/取消/回滚 + 领域词）；漏检率观察 1 个月，高则单独立项补结构化标注
- **剪枝的政治学**：删除建议可能触发「这个还有用」的保守倾向，清单长期全被拒 → 退役条件④已兜底（连续 3 轮全拒=机制与判断脱节，撤）
- 体检 prompt 预算闸：本 PR 必须净减或不增（见 D1 体积换体积）

## 设计取舍

| 取舍 | 决策 | 替代方案 | 理由 |
|---|---|---|---|
| 噪声带形态 | 近 7 日 min-max 粗粒度代理 | bootstrap 统计带（RRSI 原版） | 体检是 LLM 读数不是统计检验，粗粒度已杀主要假阳性；统计严格性需评测基建（#1147 已否） |
| 噪声带落点 | 体检 prompt + trends 数据锚 | SYSTEM.md 全局反问 | 搭档论断（否 jev 时）：纯反问=同模型二次采样，盲区共享；反问+数据锚=对质才值钱 |
| 负证据落点 | skill 流程动作 | 记忆系统结构化「否决」标签 | 结构化标签是新机制（四问成本）；先靠检索语义命中，漏检率观察后再决定加不加 |
| 剪枝裁决权 | 搭档终审 | 引擎自动执行（RRSI 原版） | 无 S 可评估删除影响面；RRSI 有 OOD 裁判我们没有；人裁决是诚实选择 |
| 剪枝候选源 | RHI stalled/regressed + 引用静默 + 执行记录 | 新建组件注册表 | 注册表是重量级新机制；三层代理信号零新增存储，先跑起来（注：首轮审视修正——zombie 已删、orphan 语义不符，改用 stalled/regressed） |
| 剪枝候选层 | 首轮只跑 skill 层 + 机制层 | 含 prompt 段落层 | 段落层需「纪律段→issue 类型→复发频率」三层映射，无现成数据，建表成本不成比例（首轮审视降级） |
| D3 触发周期 | 月度 | 双周 / 季度 | skill/prompt 数量级（~20 个）月度足够；首轮后可调（未决问题 2） |
| 机制识别 | D1/D2 不命中四问，D3 命中并已答 | — | 清单偏严原则：误触发成本是几行字，漏掉成本是补丁叠加 |
