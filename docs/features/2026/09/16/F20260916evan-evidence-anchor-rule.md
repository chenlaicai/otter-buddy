# F20260916evan: 证据锚点规则

## 背景与需求

### 问题描述

搭档 2026-09-16 反馈（本对话）：多次遇到海獭说「我们分析了 xxx，现在情况是 xxx，然后认为 xxx」，
搭档恰好了解情况指出不对，海獭随即承认看错。搭档结论：

> 你们给的"证据"都是假的，那基于证据推导出来的根因/方案那更是虚假的。……证据不能随口说，
> 必须给出来"真实的证据位置"：具体在哪个对话/什么时间/谁说的谁做的/哪个文件/哪一行。

### 与历史改进的关系

- **issue #352（2026-08-20，F: a1-investigation-methodology）**：同一问题的第一次修复——
  A1 补「先收集数据再归纳结论，不先推测再找数据佐证」。管的是**调查流程**（先查再说）。
- **#258（F: adversarial-review-fact-verification）**：对抗审视加事实验证步骤，schema 类发现强制
  file:line。管的是**审视流程**。
- **本次**：管的是**证据形态**——断言说出口时必须带可验证锚点，让搭档能当场低成本验证，
  而不是凭自己的记忆去撞。三次修复互补，不重复。

### 关键设计判断

光要求「给位置」不够——LLM 被要求锚点后照样能编一个长得像真的 file:line。所以规则第 2 条
要求锚点必须来自**当轮实际工具调用返回**，出处可回溯才算数。这是本规则与「随口要求引用」的
本质区别。

## 方案设计

在 SYSTEM.md A1 「信息来源校准」之前插入「证据锚点」段，四条：

1. 事实性断言必须附可验证锚点（file:line / 对话 ID+时间+谁说的 / 记忆条目 ID / F/R 文档 ID / issue/PR 编号）
2. 锚点必须来自当轮实际工具调用返回，禁止凭印象构造
3. 给不出锚点 → 显式降级标注「凭记忆未核实」或「推测」+ R6 置信度
4. 现象描述 ≠ 证据；「我分析了 xxx」后面必须能数出证据清单

放 A1 而非 R 层的理由：这是事实观的一部分，与「先收集数据再归纳结论」同源——A1 管事实，
规则条目是行为落点。

## 已知局限（诚实披露）

- **自我监管，无外部强制**（检视发现 2）：四条规则依赖 LLM 自我约束，存在「混合真假锚点」
  对抗模式——部分真锚点 + 部分编造锚点混合后比全不给更危险（虚假安全感）。外部强制需工具层/
  评测层配合，超出本 PR 范围，待建 issue 跟进。
- **A1 膨胀**（检视发现 5）：A1 已有三条互补规则（调查方法论 / 证据锚点 / 来源校准）分散排布，
  新规则注意力权重可能被稀释。长期可考虑重组 A1 结构，建 issue 延后。

## 影响范围

仅 `.pi/SYSTEM.md`（A1 新增一段，约 10 行）。影响所有海獭（大獭/小獭/检视獭）的事实性发言行为。
已知成本：事实密集的回答会变长（每条断言带锚点或降级标注）——已在方案讨论中向搭档披露并获确认。
