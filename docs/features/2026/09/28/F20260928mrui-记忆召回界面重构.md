# F20260928mrui [web] 记忆召回界面重构：多条件查询 + 结构化结果

## 用户意图锚

| # | 来源 | 用户原话（逐字引用） | 架构师解读 |
|---|------|---------------------|-----------|
| UA-1 | 当前对话 | 记忆召回应该是一个多条件查询的记忆数据召回机制，输入关键字召回相关的东西，要能看到数据结构，而不是零散的一堆 | ①多条件查询 ②结果按结构组织 ③数据结构可见 |

## 背景

前序 F20260730m9k1（07-30）完成了「Web 端能力对等」第一期（detail_level/library/
snippet 高亮/展开上下文/查找相似），当时 contentType 过滤被列为非目标（后端依赖）。
此后后端陆续补齐：

- F20260803fbit/F20260803chunk：contentType 多选过滤（`content_type` query 参数，逗号分隔）
- F20260805rbrg：created_after 时间过滤
- F20260811mrpy：debug 中间分值（rrfScore/finalScore/timeDecay/frequencyBoost/multiHitCount）
- F20260812mrcq Part 2：expand_context 邻域扩展（chunk ±1 / message 前后条，独立
  contextEntries 字段返回）

后端全部就绪，但 UI 只暴露 query/limit/layer/granularity/detail_level/library 六项，
结果区平铺卡片——同一篇文档的多个 chunk 散落各处，「零散的一堆」即此。

## 改动

### 1. 多条件查询面板（web/src/pages/memory/index.tsx）

新增条件（全部映射到既有后端参数，无检索算法改动）：

| 条件 | UI 控件 | 后端参数 | 备注 |
|------|--------|---------|------|
| 内容类型 | 多选 chip × 7 | `content_type`（逗号分隔） | message/fact/linked_resource/feature/feature_chunk/research/research_chunk，与 MemoryContentType 七类对齐 |
| 时间范围 | 下拉（全部/近1/3/7/30天） | `created_after`（ISO） | 快捷项而非自由日期——锚点=当前时刻-(n-1)天，非自然日边界 |
| 对话过滤 | 文本输入 | `conversationId` | conversation ID，可从结果组标题复制 |
| 邻域扩展 | 高级开关 | `expand_context=true` | 邻域条目以「邻域」标识弱化展示 |
| 召回诊断 | 高级开关（默认关） | `debug=true` | 返回中间分值 |
| 显示数据结构 | 高级开关 | （纯前端） | 每条结果展开 id/layer/contentType/granularity/score/来源/metadata 面板 |
| 结果数量 | 下拉 10/20/50 | `limit` | 原固定 20 |

### 2. 结果结构化分组（web/src/pages/memory/group-results.ts，新文件）

纯函数 `groupResults(entries, contextEntries)` 三类分组：

- **doc 组**：feature/research（summary）+ feature_chunk/research_chunk 按
  `(sourceTable, sourceId)` 聚合；doc summary 放 docEntry 槽位（layer quota 保底返回的
  概览与 chunk 并列不互斥）；组内 chunk 按 chunk_index 升序（章节路径）；组标题
  fallback 链 metadata.doc_title（summary→任一 chunk）→ sourceId
- **conversation 组**：message 按 conversationId 聚合，组内 createdAt 升序（时间线）
- **独立条目**：fact/linked_resource/术语条目独立卡片

组间按「组内主结果最高 score」降序（邻域条目 source='context-expand' 不计分）——
保留检索相关性排序语义。邻域条目归入对应组，渲染层以「邻域」徽章 + 浅色底弱化。

### 3. 命名与契约

- 全局改名「记忆搜索」→「记忆召回」：导航 label（api-contract/web/pages.ts）、页面
  标题、空态文案、按钮（搜索→召回）。skills 页测试中的用户 8/28 原话引用保留不改。
- api-contract/api/memory.ts SearchQueryDTO 补 `content_type`/`created_after` 字段声明
  （controller 早已读取，契约落后于实现——本次对齐声明，非行为变更）
- web/src/api/client.ts searchMemory() 扩展同名参数，query 拼装规则：
  content_type join(',')，expand_context/debug 传 'true'

### 4. 健康页徽章（附加，RHI 治理 A 方案治本的一半）

health/index.tsx 警报 tab 徽章从「open 信号总数」改为「未接单数（N 待接单）」——
与 #652 口径同源（low 置信不计），有效的行动数字。TriageQueue 的未接单置顶/已归口
折叠已由 F20260917trig 实现，本次只改 tab 徽章。

## 设计取舍

| 取舍 | 决策 | 替代方案 | 理由 |
|------|------|---------|------|
| 时间过滤交互 | 快捷项（近N天） | 日期选择器 | 覆盖主用例（最近改动/近期讨论），实现简单；自由区间可后续加 |
| 分组逻辑位置 | 纯函数独立文件 group-results.ts | 组件内联 | 可单测（11 用例），渲染组件保持薄 |
| doc 组展开状态 | 默认展开 | 默认折叠 | 主结果组常小于 3 条（FTS 预聚合每 source top-3），默认展开信息密度更高 |
| contextEntries 归组 | 归入对应 doc/conversation 组 | 独立「邻域」区块 | 邻域的价值在原位上下文，独立区块会重新散落化 |
| debug 面板 | score 旁 tag 化展示 | 独立诊断面板 | 与数据结构面板合并入口（显示数据结构开关下） |
| 契约补字段 | 本次顺手对齐 | 单独契约 PR | 声明性改动无行为风险，避免再开一轮 |
