## 变更内容

### #528 TestDeps any 收敛

**`tests/api/helpers.ts`**：
- `otterConfigProvider?: any` → `otterConfigProvider?: OtterConfigProvider`（接口 import）
- `modelPool: any` → `modelPool: ModelPoolLike`（真类型默认值现成——createMockDeps 用 `buildModelPool(...)` 产出真 ModelPool，`class ModelPool implements ModelPoolLike`）
- 其余 4 个 any（settingsRepo/manageScheduledTask/schedulerService/cronParser）**留后续批次**，注释写明原因：createMockDeps 默认值经 `mockMethods()` 产出 `Record<string, Mock>`（索引签名），与目标接口不满足 assignability（索引签名 → 命名属性方向不通），强行收敛需重构 mock 基建，收益不成比例。issue 原文即预期「可分批」。

**`tests/api/otter.test.ts`**：两处 mock 补齐 `getConfigs: () => new Map()`。

### #497 partnerResolver 非空断言消除

**`src/usecases/conversation/dispatch-chain-engine.ts`**（唯一残留处，:339 附近）：

原代码（issue 方案 A 描述的场景）：

```ts
const staticMode = !!resolver?.configured;  // boolean 中间变量切断 narrowing
if (staticMode) {
  label = resolver!.isPartner(...)  // 非空断言：staticMode 真 ⟹ resolver 非空，TS 不知道
}
```

改法（优于 issue 方案 A）：**三元式收窄绑定替代 boolean 中间变量 + 断言**——configured 时直接把非空 resolver 本身绑成 `staticResolver`，回调内退回普通真值判断，TS 控制流自动收窄，零断言：

```ts
const staticResolver = resolver?.configured ? resolver : undefined;
if (staticResolver) {
  label = staticResolver.isPartner(...)  // narrowed: 非空
}
```

**选型理由（方案 A'' vs A vs B）**：

| 方案 | 内容 | 判定 |
|---|---|---|
| **A''（选中）** | 回调外三元式收窄：`const staticResolver = resolver?.configured ? resolver : undefined` | **零断言**；`?.` 分支点留在回调外（不碰 .map 回调的复杂度门禁）；变量名 `staticResolver` 直接表达「静态模式下的 resolver」语义 |
| A'（首试被否） | 回调内直接 `if (resolver?.configured)` | 零断言但 `?.` 分支点携入 .map 回调，圈复杂度 12→13 超 eslint 门禁，pre-commit lint 拦截 |
| A（issue 建议） | 真值分支内 `const r = resolver!` | 可行但仍有一处 `!`；A'' 严格优于 A |
| B（issue 备选） | PartnerResolver 拆类型层级（未配置态/已配置态两类型） | 过度工程：`configured` 是运行时才知道的实例字段，拆类型层级需 brand 字段，改动面大收益小——否决 |

行为等价论证：`staticResolver` 非空 ⟺ 旧 `staticMode` 真（configured 恒为 boolean，真值表完全一致）；收窄只发生在编译期，运行时行为不变。
