# 记忆检索透明：让搭档感知到"有记忆"

## 问题

海獭不会主动展示记忆检索结果，搭档感觉"有无记忆系统都一样"。

用户原话：
> 海獭不会跟我说"我查了历史因果链，原来哪一天哪个对话中咱们已经涉及到了、做了什么工作了"

## 根因分析

| 层次 | 问题 | 现状 |
|------|------|------|
| 搜索触发 | 海獭不主动搜 | F20260814mbex 已通过工具描述解决 |
| **搜索展示** | **搜了但不说，或说了但不展示证据** | **未解决——本 issue 核心** |

## 方案设计

### 改动 1：R4 白名单扩展

将 R4 从"召唤前先搜"扩展为 4 个硬场景白名单：

1. **召唤小獭前**（otter-summon）：不重复召唤已有结论的工作
2. **排查问题 / 找根因时**：类似问题可能已有排查结论或教训
3. **方案设计 / 需求分析时**：相关领域可能已有方案、决策或被否决的路径
4. **搭档引用历史时**：提到 F/R 文档 ID、issue、"上次/之前/那会儿"——先搜再答

**设计决策**：白名单写法（列举 4 个场景 + 显式声明清单外不上收），避免滑向"每轮必搜"。

**R4 收口 vs SMALL_OTTER 放量的张力**：R4 白名单收窄了"必须搜"的场景（纪律约束），而 SMALL_OTTER 身份 prompt "开工前先搜记忆"是行为动机（人格化引导）。两者方向看似相反，实则互补——R4 是硬底线（不搜=违规），SMALL_OTTER 是软激励（搜了更好）。小獭在 R4 清单外的场景仍可由工具描述的隐性信号软触发搜索，SMALL_OTTER 的"开工前"措辞是引导而非强制，不与 R4 的"不上收"冲突。

### 改动 2：新增 R7 记忆检索透明

原则：**查了且实质影响回答 → 必须展示；没查或查了没用上 → 无义务**。

格式：`📜 记忆溯源：<什么时候的什么事> → <与本回答的关系>`

节制条款（6 条）：
- 搜了未命中 → 默认不提
- 同一会话同一主题已展示过 → 后续引用从简
- 一轮多次检索 → 合并为一条溯源
- 纯闲聊 → 不搜不展示
- 不贴原始检索结果列表
- 未实际调用检索工具 → 不得使用溯源格式（防伪造溯源）

**设计决策**：R7 独立于 R6（信任校准）——R6 管"信了怎么校准"（信任域），R7 管"干了要让人看见"（透明域），问题域不同。

### 改动 3：工具描述展示指针

search_memory 和 search_messages 工具描述末尾各加一句展示指针 → R7。

### 改动 4：身份 prompt 增补

- BIG_OTTER.md："像老搭档一样记得"——人格化动机
- SMALL_OTTER.md："开工前先搜记忆"——小獭行为约束

## 信道分工

| 信道 | 位置 | 功能 |
|------|------|------|
| 纪律层 | R4 白名单 | 4 个高价值场景"必须搜" |
| 纪律层 | R7 展示义务 | 搜了且影响回答→必须展示 |
| 工具描述 | search_memory/search_messages | know-how 软触发 + 展示指针 |
| 身份 prompt | BIG/SMALL_OTTER.md | 人格化动机 |

## 验收标准

1. 搭档问涉及历史脉络的问题时，海獭应回答含「📜 记忆溯源：」前缀
2. 闲聊场景不应触发 search_memory
3. 搜到记忆后应引用关键锚点（时间/文档 ID）
4. 未实际调用检索工具时不得使用溯源格式
