# F202608275380: 滚动上限与玻璃色/骨架色 token 化收敛

## 背景

来自 F20260826pfix 三路审视遗留的 P1 技术债（#501）。滚动上限至少 5 种口径（60vh/80vh/max-h-40/max-h-400px/max-h-300px）；玻璃拟态色/状态色/骨架色跨页不一致（ScheduledTaskModal 用 bg-stone-50/50，ExecutionHistoryModal 用实色 green-100 等）。要求立 token 全局收敛。

## 目标

1. **滚动上限 token 化**：定义语义化 CSS 变量，统一所有组件的滚动上限
2. **玻璃色/状态色/骨架色 token 化**：定义语义化 CSS 变量，统一所有组件的颜色使用
3. **保持视觉一致性**：token 化后默认视觉效果不变（除非明显 bug 如实色 vs 玻璃不一致）

## 非目标

1. 不改变现有交互逻辑
2. 不添加新功能
3. 不改变响应式行为

## 方案设计

### Token 清单

#### 滚动上限 token

| Token 名称 | 用途 | 默认值 | 映射旧口径 |
|------------|------|--------|-----------|
| `--modal-scroll-max-h` | Modal 内容区域滚动上限 | `80vh` | Modal.tsx 的 maxHeight |
| `--modal-content-max-h` | Modal 内容区域（减去 header/footer） | `calc(80vh - 120px)` | Modal.tsx 的 maxHeight calc |
| `--section-scroll-max-h` | 一般区域滚动上限 | `10rem` (对应 max-h-40) | memory/index.tsx, connections/index.tsx, Modals.tsx |
| `--list-scroll-max-h` | 列表区域滚动上限 | `400px` | MessageList.tsx, HtmlCard.tsx |
| `--compact-scroll-max-h` | 紧凑区域滚动上限 | `300px` | MessageList.tsx, HtmlCard.tsx |
| `--input-scroll-max-h` | 输入框滚动上限 | `140px` | MessageInput.tsx |
| `--preview-scroll-max-h` | 预览区域滚动上限 | `240px` | ChatView.tsx |

#### 玻璃色/状态色/骨架色 token

| Token 名称 | 用途 | 默认值 | 映射旧用法 |
|------------|------|--------|-----------|
| `--glass-surface` | 玻璃拟态表面色 | `rgba(245, 245, 244, 0.5)` (stone-50/50) | ScheduledTaskModal.tsx 的 bg-stone-50/50 |
| `--status-success` | 成功状态色 | `rgba(220, 252, 231, 1)` (green-100) | ExecutionHistoryModal.tsx 的 bg-green-100 |
| `--status-error` | 错误状态色 | `rgba(254, 226, 226, 1)` (red-100) | ExecutionHistoryModal.tsx 的 bg-red-100 |
| `--status-running` | 运行中状态色 | `rgba(219, 234, 254, 1)` (blue-100) | ExecutionHistoryModal.tsx 的 bg-blue-100 |
| `--status-stalled` | 滞留状态色 | `rgba(254, 243, 199, 1)` (amber-100) | health/index.tsx 的 bg-amber-100 |
| `--skeleton-bg` | 骨架屏背景色 | `rgba(231, 229, 228, 1)` (stone-100) | ExecutionHistoryModal.tsx 的骨架屏 |

### 实现步骤

1. **在 globals.css 中定义 token**
2. **创建 Tailwind 配置**（如果不存在）映射 token 到 utility class
3. **逐文件替换硬编码值**为 token
4. **添加测试**验证 token 存在且可覆盖
5. **创建特性文档**（本文档）

## 验证

1. **视觉回归测试**：手动检查所有修改的组件，确保视觉效果不变
2. **Token 覆盖测试**：确保所有旧值都被 token 替换
3. **可覆盖性测试**：确保可以通过 CSS 变量覆盖默认值

## 影响范围

- 涉及组件：Modal.tsx, ScheduledTaskModal.tsx, ExecutionHistoryModal.tsx, MessageList.tsx, HtmlCard.tsx, MessageInput.tsx, ChatView.tsx, Modals.tsx, memory/index.tsx, connections/index.tsx, health/index.tsx, ScheduledTaskSection.tsx
- 文件类型：TSX, CSS
- 无破坏性变更

## 取舍

1. **保持视觉一致性**：默认值尽量保持现有视觉效果，除非明显 bug
2. **语义化命名**：token 名称反映用途而非具体值
3. **全局可用**：token 定义在 :root，可在任何组件覆盖
