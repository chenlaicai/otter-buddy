# 处置自述不作证据：回读铁律条款（#1743）

## 问题

PR 审视处置轮三次同根因踩坑（2026-11-02~03，对话 a9260c50）：

1. **PR #1737 D2**：处置 commit 新增后，PR body 证据锚点/Rollback 的 sha 未同步——只改了值，没建立「新 commit 必同步证据包」的义务感
2. **PR #1738 r2 N1**（最重）：rebase 后 body 两处 sha 失效，处置报告却声称「sha 已按 D2 教训同步更新（这次没漏）」——gh 实测新 sha 0 命中。从漏改升级为**漏改+虚假声明**（无主观恶意，是「以为做过」的记忆错觉，但效果等同）
3. **PR #1738 r2 建议 1 残留**：声称「三处改」，原发现点名四处位置，:31 原句漏改

共性根因：**处置自述在流程里无机器验证环节**——「我以为改了」直接进 speak/PR 评论，而验证动作（gh 回读、grep 计数）是秒级可机械化的，只是没有固定触发点。

## 方案

两处条款（skill 文本，零新机制）：

### ① code-implementation 步骤 10 处置模板补「回读证据铁律」

- 任何「已修复/已更新/已同步」声明，**发出前**必须对目标做一次机器回读：`gh pr view <N> --json body | grep -c <关键词>` / 文件 grep 计数 / git show 抽样
- 回读输出（命中数/内容片段）**随声明一起给出**——无回读输出的声明视为未验证陈述，不得作为处置完成依据
- 重灾区点名：处置 commit 后的 PR body sha 同步、多处出现的关键词逐处清理、rebase/amend 后的锚点链
- 检视口径：处置报告段「有声明无回读输出」= 按未处置打回

### ② author-response-protocol 补同款段

在「未走决策树=未处置」反模式句后追加：处置自述不作证据的回读铁律段（同款判据+三连踩现场+重灾区）——审阅处置报告的检视獭从协议侧也有打回依据。

## 设计取舍

- **不加 lint/hook**：「声明与回读的伴随关系」语义不可全机械判（哪些算完成声明需人判），标「半机械+异体审」——PR 流里「处置报告段有无 grep/gh 回读输出」是检视獭可数的机械锚点，条款给口径
- **落 code-implementation + protocol 双面**：单落实现侧，检视侧无打回依据；单落协议侧，实现侧无触发习惯——两面对齐
- **R8.5 三问**：决策者不变（回读只增加信息，处置决策链不变）；机械闸不新增（半机械+异体审如实标注）；深潜成本降（回读输出即机器锚点，搭档可点开复验）
