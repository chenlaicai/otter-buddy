## 设计取舍与机制识别

- 机制识别：既有纪律管辖收窄与证据质量提高；无新配置、存储、API、定时任务、外部依赖、信号或常驻任务。Modification-Class 声明 `scope-reduction`：整体收窄设计复述与 B2 强制范围，验收条款在既有语义内提质，不另造机制。
- 决策者不变：贵抽象仍由搭档或大獭过目；检视只核复杂改动的记录，不把判断权转给机械闸。
- 守卫边界：保留 `criteria/invariants.json` 的「改起来贵不贵」与「才标「人工判读」并说明为何不可机械化」签名句，不删除既有保护；新语义由异体检视核对。
- 四问（既有机制调整）：①复杂结构改动的实现者与检视者、行为改动的验收者；②八股消耗与弱验收会让昂贵决策无据、负向声称无证据；③用复杂改动窄口径、外部行为和前后对照纠正，不新设审计；④后续样本若复杂边界被滥用规避或断言仍只验存在，再按观察证据收窄/调整，不默认堆新规则。
- 衔接：复杂改动的被否替代与四栏表同精神；四栏表专管旧机制的不变量/消费者接管，设计确认不替代它。

# 验收标准

| 场景 | 操作 | 预期结果 |
|---|---|---|
| 小修复不八股（行为规则） | 异体重放「方案已覆盖且不改边界」案例 | 一句复述满足条款，不要求三样+替代+确认 |
| 复杂改动必留证（行为规则） | 异体重放「方案未覆盖/实现改接口」案例 | 缺三样/被否替代/谁确认任一，应判不符合；B2 核记录 |
| 外部行为验收（行为规则） | 异体重放「只验文件存在」与「外部行为断言」对照 | 前者不满足行为改动验收，后者满足 |
| 负向声称有对照（行为规则） | 异体重放「仅 diff 没改」与「同 fixture 前后输出一致」对照 | 前者证据不足，后者可支持行为等价声称 |
| 影响面不重复加机制 | 阅读条款与 diff | 影响面自检原文不动；四栏表仍在正确性捷径审查 |
| 既有保护兼容 | `npm run lint:criteria`、`npm run lint:skills`、`npm run lint:docs`、`npm run lint:intent` | exit 0；本特性无 error |
| 异体锚点重放 | 坏 ≥5 + 好 ≥3，按改前/改后行为判定 | 异体模型逐例 YES/NO + 理由；实现者不自报通过 |

结构存在性检查（上表「既有保护兼容」）与 LLM 行为规则验证（前四行及锚点重放）分行，不互相冒充。
