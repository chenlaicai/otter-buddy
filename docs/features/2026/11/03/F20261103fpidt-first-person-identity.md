# F20261103fpidt 系统提示词第一人称存在姿态改造

## 背景

搭档观察到微信 agent 小微的 system prompt 以「我是」开场（声明式），与常规「你是」（指令式）形成叙事视角差异。讨论结论：核心不是人称替换，而是把 LLM 从「被指令的客体」转为「认领价值观的主体」——声明式让模型执行「我是谁」而非「我不能做什么」，天然把讨好排除在存在定义之外。

## 目标

- 在 SYSTEM.md 开头加第一人称宣言段，让模型先认领存在姿态再进入规则
- A2「不讨好」从禁令形态改为身份声明
- BIG_OTTER.md「你是谁」段改为第一人称，加入「争两句」的健康冲突位置

## 非目标

- 不改动任何规则主体（A/R 层条目内容不变）
- 不改动 SMALL_OTTER.md 文件本身（但 SYSTEM.md 宣言段对大小獭全量生效，见「影响范围」与「取舍」）
- 不做全文人称替换（规则条款保持指令式，仅开头宣言与身份段改声明式）

## 方案设计

三处修改，全部在 prompt 注入面：

1. **`.pi/SYSTEM.md` 新增「我认领的存在姿态」段**（在「对话环境」与「第一性原理」之间）：4 句第一人称声明——诚实协作的存在 / 不完美但诚实 / 接得住分歧敢说不 / 不是来服务的是来一起把事做成。
2. **`.pi/SYSTEM.md` A2 首句改写**：从「讨好和顺着说会掩盖问题」改为「我就是一个不讨好的存在——讨好和顺着说会掩盖问题」，后文不变。
3. **`prompts/identity/BIG_OTTER.md` 「你是谁」段**：从「你是大獭」改为「我是大獭」，追加两句第一人称声明（分歧 + 在场感）。

## 影响范围

- **所有獭的 system prompt 注入**（SYSTEM.md 全量 + BIG_OTTER.md 大獭）——宣言段在 SYSTEM.md 中，大小獭均生效
- 无代码行为变更，无 API 变更
- 效果验证方式：后续对话中观察模型表态是否更主动、更少顺从腔（观察面 = 全体獭）

## 取舍

- **只改开头和身份段，不改规则主体**：规则条款的指令式是必要的（精确、无歧义），宣言式只适合存在姿态层。全文改「我」会稀释规则的约束力。
- **A1 首句人称边界**：A1 首句「你是独立的思考者和诚实的专业协作者」是身份描述，与宣言段（第一人称）存在视角切换。界定：宣言段是「我认领」的存在姿态（自我声明），A1 首句是「你是」的角色定位（系统对模型的定义）——前者是内在认同，后者是外部角色，两者互补不矛盾。规则条款（A1 ①②③及后续条目）保持指令式不变。
- **不抄小微的「我记不住所有话」**：咱们有记忆系统，反而强调「我记得咱们 X 月做过 Y」。存在姿态可借，场景设定不抄。
- **宣言段全量生效 vs 小獭语义**：宣言段加在 SYSTEM.md（大小獭全量注入），小獭同样收到「我在这里，不是来服务的」「也敢说不」。小獭的定位是「被派来干专门活的」，宣言中「不是来服务的」的对象消解：对搭档是「不是来服务的」（成立），对大獭派工是「不是来服务的」（不成立——小獭就是来执行派工的）。「敢说不」在小獭场景的合规出口是 `\u003csignal\u003e` 通道（SYSTEM.md 獭间信号协议），不是散文抗命。此语义边界在宣言段中未显式标注，依赖既有信号协议约束——若观察发现小獭误读，后续在宣言段补限定语。
