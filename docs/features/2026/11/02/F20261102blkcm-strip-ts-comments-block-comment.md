# stripTsComments 块注释穿透修复（#1291）

## 问题

issue #1291（PR #1282 delta 复核新发现）：`subtotal /* 跨行块注释 */ / 100; // 注释` 形态中，行首续行除法被误判为正则——

1. **isLineStart 盲区**：回溯遇 `\n` 即判「行首语句位正则」。但纯注释行/空行不产生 token，`/` 的语法性质由更前面的代码决定——块注释夹在表达式与除法之间时，`/` 是除法续行。误判后正则态吞到行尾注释的首个 `/` 闭合（`/ 100; //` 的第一个 `/` 闭合正则），剩余 ` 100; ` 继续扫描、`//` 再进正则态自愈回填——尾部真注释不剥离（误报方向）+ stderr 未闭合告警。
2. **lastNonWhitespace 盲区**（同行形态 `a /* c */ / b`）：宣称「穿注释边界取 token」但实现未跳块注释，落点在块注释结束符的第二个字符 `/` 上——`isRegexStart` 的 c 是 `/`，落入「其余 → 正则」误判。

漏报方向已被自愈回填设计兜住（内容不丢、锚点仍被扫描），故原 issue 定级为误报方向技术债。

## 修复

两函数均增加**块注释感知回溯**（遇块注释结束符的第二字符 `/` 且其前一字符为 `*` 时，回溯找对应起始 `/*` 并跳过整个区间）：

- `lastNonWhitespace`：跳过块注释区间后取真正的上一个代码 token（subtotal 的 `l` → 除法判定正确）
- `isLineStart`：跨行回溯——块注释区间内的 `\n` 不构成语句边界；块注释外的 `\n` 检查上一行内容：纯空白/注释行继续回溯（不产生 token），有代码行时按「块注释介入 → 除法；纯换行 → 行首赌注」裁决

**口径拍板**（与检视发现③的既有赌注协调）：仅当 `/` 与上一代码 token 之间存在**块注释**时穿透判定（块注释=token 间空白，除法语义强）；**纯换行维持「行首赌正则」**——`const a = 1` 换行后行首 `/re/` 仍判正则（检视发现③锁定的行为，本修复不改变）。

跳过失败（字符串内伪结束符、未闭合）退化为修复前行为（不穿注释）——块注释误判是误报方向，自愈回填兜底。

- **残留声明（1723-r1 建议 3）**：行注释行介于块注释与除法之间时（subtotal 后接块注释、再接行注释行、再接行首除法的形态），穿透不生效——isLineStart 行内扫描遇行注释文字即判「上一行有代码」，行注释内容不会被跳过。旧新行为等价（既有盲区非本修复引入），误报方向，自愈回填兜底；与 F20261005rgxf 残留 2 同族归入启发式边界技术债

## 设计取舍

- **为何不用完整 JS parser**：本模块是 lint 脚本的轻量启发式（212 行），引入 parser 依赖换取完备性不成比例——启发式边界按发现一个修一个（ratchet 式收敛），本修复即该模式
- **为何块注释穿透而纯换行不穿透**：块注释是 token 间空白（`a /* c */ / b` ≡ `a / b`），除法语义强；跨行除法本身罕见，纯换行后行首 `/` 更可能是语句位正则（检视发现③的赌注是历史锚定的合理默认）
- **机制判定**：纯存量启发式缺陷修复，无新机制引入——机制预算四问不触发
