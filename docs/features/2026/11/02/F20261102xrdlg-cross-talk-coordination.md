# 跨对话工作协调：接手预检 + 双向接管协议（#1735）

## 问题

同日两起跨对话撞车（#1735 原文 colink2 案 + 本方补充 a9260c50×3241317b 案），共享同一深层根因：**工作产权信号不在工作现场**。

**案 1（colink2，原 issue 正文）**：前世中断工作后重启，新世从跨对话共享的记忆推断「P3 是我的事」，误接手另一对话正在处理的 PR #2661——修 CI、派检视，直到搭档指出。

**案 2（本方补充，同日 17:02–18:42）**：a9260c50（issue 流水线线程）在 PR #1734 页推进处置；3241317b（三省吾身线程）17:02 在 **issue 页**发接管声明并接管编排。双方各扫各的一亩三分地（一个只看 PR 页、声明只发 issue 页），互不知情并行推进，分支双头 amend 至少三轮。次生灾害：a9260c50 大獭把对方 17:15 的 commit 误判为「我方检视獭越界」，错误归责写入 F 文档边界记录段——对方检视獭 r1 已第一时间标注 PR body 警示「并行线程嫌疑」，仍被误判，直到检视獭1734 objection 三重时间线锚点（c355126a 早于其入对话/1a87e644 落其休眠期/PR review 三实体分立）才纠正。

## 开工核验（方案前提修正）

issue 认领协议（otter-claim 带 conversation ID）**已存在且完整**——登记面基础设施在位，无需新建（推翻 issue 原文「候选 A：显式记 owner 对话 ID」的必要性）。真实缺口三处：

1. **接手半途工作无产权核验步骤**：开工三问管「从零开工」，不管「接手半途工作」——新世/并行线程接手在途 PR 时没有「先查归属」的步骤
2. **接管协议单向且发错面**：接管声明发 issue 页，PR 侧工作线程看不到；无 stand down 确认环节，原线程可能正在处置中
3. **交接摘要模板无产权段**：前世在途工作不标注「本对话续做/已移交」，新世只能靠记忆推断

## 方案

### ① worktree-isolation 认领协议补两条（SKILL.md）

- **半途工作接手预检**：接手非本对话起的半途工作（重启后发现在途 PR、记忆里的未闭环工作、别人的 worktree/分支）前，开工三问之外必须——查 PR 页全量 timeline + issue 认领评论确认驱动对话归属；归属不明或归属他对话 → 停手问搭档；重启新世：交接摘要未标「已移交」的在途工作一律先归档不动手
- **接管协议（双向确认制）**：接管他对话在途工作——声明必发 PR 页（issue 页对 PR 侧不可见）；等原线程 stand down 回执（或 24h 无响应）才推进；单向声明不算完成接管；接管后 PR body 补记 driver conversation 变更；原线程见声明后尽快回执退场不留悬置

### ② 交接摘要产权段（指针形态）（模板增补，真相源不动）

已合入特性文档不可历史性修改（commit hook 铁律，本 PR 开发中实测拦截）——模板增补以「worktree-isolation 认领协议节 + SYSTEM.md 交接指针补注」形态落地：交接摘要④产物段下必填「**在场工作与产权**」：前世进行中工作逐项标注 `本对话续做 / 已移交他对话（ID）/ 待定不动手`，无在途工作写「无」。SYSTEM.md 指针行同步补「在途工作必填产权标注」提示。

### ③ PR body 归属信号（模板级约定，落特性文档不改 PR 模板文件）

PR body 变更清单上方加一行 `Driver: conversation=<短ID>`（创 PR 时写，接管时改）——机械可 grep，与认领评论同构。

## 设计取舍

- **零新机制**（R8.5 三问通过）：①决策者不变——预检/接管都是把「问搭档」的时机提前，不替搭档决策；②机械闸不新增——产权判定（归属哪个对话）语义不可机械判，标「半机械+异体审」（PR 页声明/回执是机械可查的文本锚点，但「是否算接管完成」需人判）；③深潜成本降——两起事故现场（PR timeline/认领评论/reflog）均可下钻复盘
- **不改 PR 模板文件**：Driver 行用约定不强制（check-pr-evidence 若加必填段会拦所有存量 PR），先靠 skill 条款 + 事故威慑
- **不建中央登记表**：linked_resources 已有 worktree/pr 登记且带 conversationId——再加表是重复登记面，把「查产权」步骤指向既有信号源（认领评论 + PR timeline + linked_resources）即可
