## 设计取舍

- **机制识别检查点**（七项）：全部未命中——纯 prompt 阈值参数修改 + 死口径删除，无新配置字段/状态/任务/信号/持久化/决策分支/跨模块调用。走修法决策树①既有机制语义内修（F20261006obsv 建立的观测口径内调参数），Modification-Class: narrow-fix。
- 单日阈值取 100 不取 86+ε：观察期残余峰值 86 是「已修家族最后挣扎」的实测，但同族边界残余 W45 仍漏 2 条——若残余再发作冲到 90，建 issue 定性为「同族残余复发」仍是合理动作；取 100 是把「残余量级」与「风暴量级」分开，不追求精确最优。
- 观察带 ≥3 不取 0：≤2 实测为孤立噪音（10-13=2、10-26=2，均未再连日出现）；取 0 则任何单次孤立失败都记观察行，观察行本身退化为白名单噪音，违背「观察行=值得盯的持续性信号」语义。
- 升级条件「连续 2 日」不取「单日即升」：单日 ≥3 已记观察行（体检獭肉眼可见），升 issue 需要持续性佐证——单日 3 次孤立失败建 issue 违背 R2「Issue = 承诺不是收纳箱」（两问：可验证完成条件/有人修有排期位，孤立失败两问都难答）。
- 删 hook fallback 而非量化：该日志源已物理消失（机制退役），量化一个不存在的东西没有意义；死口径留存会让体检獭每次都写「fallback=0」的空转行。
- shadow 阈 3 = 观察期上界 2 + 1.5x 舍入缓冲；单日差 3 次合成失败已值得记异常（W45 实测最差日 2 次硬错误）。
