### 10-14 定性（初版最大盲区，本版核心修正）

**它不是「已修残余」，也不是「新风暴」，而是第三形态：大獭超长会话摘要请求超 kimi-256k 窗口的物理性死锁。**

证据链：
1. **主体归属**：210/221 来自大獭本体（6f92e42b，当日 DB 确认），仅 11 条来自另一大獭 id（106a95b6，10-01/05/13 的同一主体——跨 4 日同模式）。
2. **时间形态**：10:29~11:00 每分钟 5-9 条、15:42~15:46 一小波——「同会话内压缩重试死锁」形态（上下文涨到阈值线→触发压缩→摘要请求超 262144 窗→400 拒→上下文继续涨→再触发，循环）。与 9/23 风暴的「多会话多 id 同时爆发」不同构。
3. **错误内容**：`kimi-256k API error (400): request exceeded k3-256k model token limit: 262144`——摘要请求超模型窗口上限，与 #1148（trimMessagesToBudget 密度校准，治本项）记载的 9/23 形态同构：合成 prompt 含机械供料密度 <2.16 chars/token，chars/3 估算下裁剪后仍超窗。
4. **无治愈证据**：10-01（17）→10-05（10）→10-13（4）→10-14（221）→10-20~29（6/86/14/66/73）——同族 400 贯穿整月，10-30 归零与「大獭换新会话」同时发生。**该模式随时可随任一超长会话复发。**
5. **与 #1511（glm 429 配额）无关**：时间窗部分重叠但错误类型不同（400 超窗 vs 429 配额）、主体不同（6f92e42b 会话 vs 定时任务执行体），排除同因。

### 体检观测行实战史（#1317 上线 10-06 后）

10-06~11-01 观测行在案 ≥10 天（issue #1319 验证断言满足），其中超现行阈值 ≥20 的日子：**10-14（221）与 10-21（86）两天**。10-14 当天及次日体检**未建 issue、未升级**（issue 台账 10-14~17 无压缩相关立案）——现行规则首个实战超阈日在体检执行层面被静默漏检。这不是阈值的错（221 ≥ 20 规则本身会触发），而是观测行与「建 issue 动作」之间的执行链在 10-14 未闭环。本 PR 校准的是阈值口径；**执行链断点（体检獭拿到超阈数据为何没建 issue）超出 #1319 范围，遗留为独立问题**——见「遗留问题」节。

**episode 视角**（建议 1 采纳）：「连续 2 日 ≥3」在全量数据上识别出 10-13~14、10-20~23 两个 episode（4 日滑动窗内多次成对触发属同一持续段）。规则措辞「升 issue」的 episode 去重与同根因聚合由体检獭按 R2「同根因不拆条」执行——prompt 行不加去重指令（体积预算内无空间，且 R2 是全局纪律已在 SYSTEM.md）。特性文档此处明确 episode 语义：**同段持续期内的重复触发归并为一个 episode，升 issue 一次**。

## 设计取舍

- **机制识别检查点**（七项）：全部未命中——纯 prompt 阈值参数修改 + 死口径删除。修法决策树①：既有机制语义内修。Modification-Class: narrow-fix。
- **单日线维持 ≥20 不上调**：初版上调至 100 的论证（「残余峰值 86」「风暴 220+ 二分」）被 10-14=221 同族日击穿——同族在窗口外打出 221，说明该族量级谱系是 10~221 连续谱，不存在「残余 ≤86 / 风暴 ≥220」的清晰断层。在连续谱上，≥20 在全量数据上 7 次触发全部是真信号（风暴+死锁都是要 issue 的），上调只会漏掉 59~97 档的真信号。**阈值的目标是信号真，不是少报。**
- **观察带底取 ≥3**：≤2 实测孤立噪音（10-26=2 且次日归零）；≥3 连续两日是最小持续信号判定。
- **10-30 归零不作为基线**：归零与大獭换新会话同时发生（DB otterId 更替），会话周期噪声使「趋势向好」不可证——若把 10-30 后零值当「残余消退」证据，会重演初版的窗口取样偏差。
- **删 fallback 而非量化**：日志源已物理消失。
- **shadow 阈 3**：实测上界 2 + 缓冲。

## 遗留问题（超出 #1319 范围，不阻塞本 PR）

1. **体检执行链断点**（10-14 漏检）：现行规则 ≥20 在 10-14=221 上应触发建 issue，但当天体检未执行立案动作。是观测行没跑、跑了没记、还是记了没升——断点在哪需要排查体检当日产物（日报 issue / healing 台账），属 daily-health-check 执行层问题，建议独立立案。**注意**：这是执行层问题不是阈值问题——本 PR 不因执行链断点而改阈值（改阈值解决不了执行断点）。
2. **超窗死锁模式本身**：10-14 型（超长会话摘要请求超 kimi-256k 窗口循环失败）无根治方案在案。#1148 治本项（trim 密度校准）PR #1273 待查合入状态；若无合入，该模式将随超长会话随时复发——10-20~29 的观察期数据本身就是它复发的实录。建议在大獭侧或 #1148 跟踪。
3. **跨 id 聚合口径**：大獭每日重启产生不同 otterId，按日聚合计数不受影响，但「按 otterId 关联 messageId/otterId」的 issue 排查指引在大獭场景下需按日切窗口。轻量提示，不立案。
