# PR 呈递拍板机械闸（F20261119prcrd）

## 事故现场（#1952 原文摘录）

2026-11-19 08:43-09:05，同一诉求 20 分钟内三次：

| 时间 | 搭档 | 大獭实际输出 |
| --- | --- | --- |
| 08:43 | 「已合入」（#3509 合入） | 一段 md 文本 + 一张「待你一句话」卡——无 PR 号锚点、无可点开的 PR、无授权按钮 |
| 08:45 | 「给我1941的pr卡片」 | 才补出裸 URL + 卡片 |
| 09:05 | 「pr卡片」 | 又重发一次卡片 |

卡片是被要了才给的，不是交付时本来就在的。搭档要的不是好看的 HTML，是一张**不读正文就完成决策的卡**：这是什么 PR、能不能合、证据够不够、按哪个键。

## 根因：约束错位（与 #1907/#1951 同构）

- **没有机械闸**：speak 形态选择全是提示词自律（SYSTEM.md/speak description/skill），yield 只校验「先 speak 再 yield」不校验汇报内容形态——违反零成本，回退零摩擦。
- **没有固定模板**：每次手搓卡片字段随心情浮动，缺最关键的授权按钮（otterCard.submit 能把「拍板」变成一次点击，且直接充当 merge_pr 的合法授权源）。
- **「PR 卡片」高频词未绑定动作**：未进术语库，模型把它理解成「贴个链接/做张图」。
- **汇报视角漂移**：文本主线是操作流水，搭档视角要的是「你现在要不要按、按了会发生什么」。

## 修法四件套

### A. 机械闸（双闸点，本 PR 核心）

判定核心三信号共现：**PR 引用**（`#\d{3,}` 或 pull URL；issue/PR 共号域——呈递语境 #N 泛指待拍板对象，通报 issue 完成同样该出卡）× **请求措辞**（词表见下）× **决策卡不在场**（无含 otterCard.submit 的 html-card 围栏）。

| 闸点 | 判定面 | 词表 | 拒绝点 |
| --- | --- | --- | --- |
| 辅闸（speak 落库前） | 单条 body | 窄表：拍板/授权/一句话纯请求措辞（**不含**「可以合入」等评价措辞） | errorResponse 拒落库，含补卡模板 |
| 主闸（yield to user 前） | 回合累计 speak + yield reason | 宽表：窄表 + 合入请求族（可以合入/待合入/要不要合入/是否合入/能否合入…） | errorResponse 拒交棒，指导补 speak 决策卡 |

两表分离的防误拦论证：
- **窄表不收评价措辞**：独立检视獭的检视报告（「对抗检视通过，可以合入，无阻塞项」）常态无卡——speak 侧收「可以合入」会把检视回呈也拦掉。
- **宽表只在 yield-to-user 上下文收评价措辞**：yield to user 本身是「请搭档行动」的结构信号；检视獭 yield 回大獭（to 不含 user）不触发。「可以合入了」在 yield-to-user 语境正是 08:43 事故形态。
- **主闸判定面用累计而非单条**：防拆条规避——先说「#1960 检视完了」（无请求词过辅闸）再说「可以合入了，等你」（无 PR 引用过辅闸），单条都不共现，累计才拼出呈递形态（集成测试实证）。

**否定/过去式剔除（三轮收窄终态）**：否定前缀词表只收**双字及以上否定词**（不是/并非/没有/无需/无须/不用/不需要/没必要/暂无/不再/不要/并不/毫不 + 无/非/没/别/勿/莫）与请求词**就近组合**剔除，否定词与请求词之间允许 0-2 字封闭集副词窗（再/先/都/也/就/还/且/而——「无需**再**等你拍板」）。**单字「不」删除**：它是全部语气歧义的根源（要不/何不/不得不/不能不 X 都是真实请求，「若不需要/或不用」又是否定），语气断言特例三轮实证打不收敛；删它之后这些形态全部自然正确。完成态（已合入/已合并/已授权/已批准/已 merge/squash）同前剔除。剔除按片段不按整句：同回合「A 已合入，B 可以合入」→ 前者剔除后后者仍命中（呈递在途）；否定词与请求词隔实义字（「不阻塞，可以合入」）不构成否定，肯定语义保留。

**fail-open 边界（口径收窄）**：ctx.speakBodiesThisTurn 未注入（旧装配路径）→ 仅 speak 累计面视为空（宁漏勿误——闸失效不能反过来阻断发言）；**yield reason 面恒生效**（reason 是 yield 参数必在，不属装配缺失维度）；辅闸不依赖注入字段。

### 对抗检视处置（首轮 BLOCK 2🔴3🟡 全处置）

- **空壳卡绕过（🔴，二轮再修）**：原判定只查字符串子串。首轮清展示区（HTML 注释/块注释/行注释/code/pre）后查调用形态；二轮实证缩进行注释、JS 字符串、textarea、data-* 属性仍绕过。终态：结构化可执行路径判定——script 块内清 JS 语义区后查调用 + on* 事件属性白名单（见上节终态描述），二轮五形态全部入回归矩阵。
- **否定误拦（🔴，二轮再修）**：穷举否定短语不可收敛。首轮修正为通用否定前缀法（窄表 12 前缀）；二轮实证仍双向失误——不用/不需要/没必要/无须/不再仍误拦，「要不请你拍板」建议语气被误剔漏拦。终态：前缀表扩充至 19 词 + 含「不」前缀统一 `(?<![要若或])` 语气词组保护断言（见上节终态描述）。
- **词表直接变体漏拦（🟡）**：补「请你拍板/请你授权/请你批复」（宽窄双表）与合并族（可以合并/待合并/请合并/要不要合并/是否合并/能否合并/批准合并/等你合并，仅宽表——同评价措辞逻辑）；过去式剔除补「已合并」。
- **指代自足缺位（🟡 采纳 issue 补充现场判据 1）**：本条「卡片在上一条/见上文」式指代 + PR 引用 + 本条无卡 → 辅闸拦（话术专列：决策节点必须复述载体）。命中事故样本 2725 形态（「#1941 现在真的可以合了（卡片在上一条）」）。判据 2（卡内须有可点开 URL）与判据 3（里程碑语提醒）与 #1962 的检测面重叠，留归其处置——本闸不重复建机制。
- **fail-open 口径（🟡）**：文档与实现对齐——fail-open 仅覆盖 speak 累计缺失维度，reason 面恒生效（见上）。
- **三轮 BLOCK（2🔴2🟡）→ 架构收窄决断**：两个 🔴（空壳卡新五形态 + 语气断言新双向失误）证明 JS 语法解析与中文语气判定在正则层不可收敛（每轮修完样本，同一算法边界又冒反例——与通用 shell 语义建模四轮实证同构）。终态不是第四轮打地鼠，而是收窄：①可执行判定回弱信号（稳定展示区清理 + 字样匹配，空壳卡记边界）；②否定法删单字「不」+ 副词窗（语气断言特例整体撤销，「要不/何不/不得不」自然正确）；③指代豁免补全引号形态（反引号/弯单引号/ASCII 单引号，Unicode 精确字符类）。**收窄而非放弃的依据**：主目标（拦卡片整体缺位）不受影响，三轮全部误拦样本与真实请求样本在新算法下语义正确，边界行为有显式测试记录（防未来误改）。

**授权按钮判定（三轮收窄终态）**：弱信号——剔除**语法稳定无嵌套歧义**的展示区（HTML 注释 / code / pre / textarea 块）后围栏内含 `otterCard.submit` 字样。JS 语义级判定（script 块解析/注释字符串清理/on* 事件白名单）三轮对抗实证不可收敛（缩进注释/转义引号/非 JS script/伪事件属性每轮修完又冒新语法上下文反例，真实写法反被误拒）——用正则重写 HTML+JS parser 的路走不通，同族先例：通用 shell 语义建模四轮实证后收窄为固定模板。按守卫总则（明确拦不明确放通）：「有卡但按钮是假的」的空壳形态机械不可证明，放通记边界——本闸主目标是拦「卡片整体缺位」（事故本形态），卡片质量由 get_html_card_contract 模板纪律与独立检视兜底，运行时真相由卡片回执（html-card-reply）事后可证。summary 固定格式「<PR号>合入」（merge_pr 合法授权源，F20260922pmgd）是模板纪律留给 prompt 层。

## 已知边界与兜底

- **请求措辞词表是白名单制**：表外措辞（如「看着办」「你定」）不拦——守卫总则「明确拦不明确放通」，宁漏勿误；漏拦由 prompt 层四件套纪律兜底（skill/契约/术语三层在场）。
- **单字「不」否定的收窄代价**：「不可以合入/不要拍板吧」类单字否定形态在宽表命中（yield to user 语境下被要求补一张阻塞说明卡——出卡解释为什么不能合也是合理呈递形态，非伤害性误拦；speak 辅闸窄表不含评价措辞故不拦）。换取「要不/何不/不得不/不能不 X」等建议/双重否定语气全部自然正确。
- **空壳卡（有卡但按钮是假的）放通**：JS 内嵌伪调用（注释/字符串/data-* 属性/text-plain script 中的 otterCard.submit 字样）机械不可证明，按弱信号放行——由 get_html_card_contract 模板纪律与独立检视兜底，运行时真相由卡片回执事后可证。机械闸的主目标是拦「卡片整体缺位」（08:43 事故本形态：连卡都没有）。
- **「可以合入」的检视报告依赖主闸的 to-user 判定**：检视獭 yield 回大獭不触发主闸；若检视獭被误派直接 yield to user 且说了「可以合入」，会被要求补卡——补一张状态通报卡成本低，属可接受误拦（宁漏勿误的反向边界：结构信号+请求措辞共现时，出卡总是合理的）。
- **辅闸不校验决策卡质量**（有无 submit 由主闸管）：单条带任意卡片的呈递措辞过辅闸——卡片有没有授权按钮在 yield 时才判。中间态（speak 完未 yield）无闸覆盖，设计如此（yield 是最终闸点，speak 可连续多次）。
- **PR 引用与 issue 共号域**：#N 不区分 PR/issue——「issue #1952 处理完了，等你拍板」也会被要求出卡（issue 完成的拍板呈递同样该有决策卡，泛化是收益不是误拦）。

## Rollback

`git revert <merge-commit>` 即可——闸是独立校验层（speak/yield execute 内各一个函数调用），无数据迁移；术语 seed 下次启动不重复导入（id 幂等）。
