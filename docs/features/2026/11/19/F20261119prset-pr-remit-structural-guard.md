# PR 呈递三件套结构化守卫（F20261119prset）

## 一版误诊与完整重做（搭档裁决）

一版（PR #1958，已关闭）：往 BIG_OTTER.md 六形态段追加「2026-11-16~17 四 PR 回退 + 搭档原话」案例段，claim 是「负向案例锚定比抽象规则稳」。搭档三点击穿：

1. **日期进 skill 是错层**——skill 是跨时间行为规则，案例日期是一次性历史事实，对未来执行零增益且每轮注入占上下文
2. **失效不在规则层**——回退期间 BIG_OTTER.md 六形态段与 speak 工具描述（每轮注入）双层在场；规则在场而行为缺席，往规则层加码是症状层打补丁
3. **检视流于表面**——检视獭 B2.5「方案前提」给通过只是一句断言（「负向案例与问题本质匹配」），查的全是形式合规（台账/豁免/证据块），没对抗方案作用于哪层

## 失效层分析（第一性）

呈递行为链路三层：

| 层 | 职责 | 现状 | 失效判定 |
|---|---|---|---|
| 规则层 | 该做什么 | 六形态段 + 工具描述双层在场 | ❌ 不是失效层（在场未生效） |
| 执行层 | 交付时刻做出来 | speak（第二步）与 create_linked_resource（第三步）分离工具调用，无耦合，靠「记得」 | ✅ **失效层**：缺结构化耦合 |
| 反馈层 | 漏了被发现 | unfurl 缺席靠搭档体感；登记缺席靠检视獭碰巧查台账 | ✅ **失效层**：缺机械检测 |

## 三层修复

### 执行层：yield 边界机械复核（核心，检视一轮重构）

`speak-pr-remind.ts` + speak 记录 / yield 复核双侧挂接。检测点锚在 **yield 边界**（回合自然完成点）——检视一轮两击修正：speak 时刻登记必然尚未发生（正确顺序 speak→登记→yield），回执提醒必误报；独占段-only 口径对原事故形态（句中夹带/仅摘要卡）沉默。

- **speak 侧只记录**：回合寄存器（invoke 入口重置）分强弱两层——强信号 = 独占段 PR URL（复用 unfurl 真扫描器 scanBareUrls，口径天然一致）；弱信号 = 句中/markdown 链接形态（覆盖原事故现场）；同 URL 两种形态并存归强（独占段是更强呈递证据）
- **登记侧挂接**：create_linked_resource 成功登记 pr 类型时并入回合寄存器（确认呈递信号，不变量二的输入之一）；fact 类型含 PR URL 时回执引导改 pr 类型（原事故「仅摘要卡」形态的登记侧入口）
- **yield 侧复核两不变量**：一：强信号必须已登记（第三步缺席顶回，补 create_linked_resource 后重新 yield）；二：确认呈递的 PR（本回合 pr 登记/弱信号已在台账）speak 必须有裸链独占段（第二步缺失=形态不合规顶回，补裸链 speak 呈递；误登记/非呈递走零进展放行）——封堵「补登记放行但无 unfurl」假闭环（检视 delta 1 复现的两类原事故现场由此收口）。弱信号未登记：呈递/提及不明，拒绝给双出路。台账比对完整路径归一（owner/repo 小写 + pull/<n>，跨仓库同号不吞）。**拒绝/放行按缺口快照比对**（检视 delta 2 修正——替代「同回合二次无条件放行」：多 PR 混合缺口按回执部分修复后，剩余缺口会被无条件放行构成第三类假闭环）：缺口空→放行；与上次拒绝时完全相同（零进展 = 确认仅提及的刻意出口）→放行但交棒回执留声防死循环；缺口有增减（部分修复/新违反）→继续拒绝并附完整缺口回执（逐类全列不吞类）；正确流程台账已齐+有裸链，静默放行零打扰
- **不代替登记**：pr 类型登记的 groupId（特性文档编号）只有 agent 知道，机械层只拦「漏了」不猜「该填什么」
- **best-effort**：speak 记录与 yield 复核异常均 catch + warn 不阻断（发言/交棒是主路径，守卫是增益）

### 反馈层：B2.5 可操作判据

adversarial-review skill B2.5 补两组判据（SKILL.md 主表 + review-dimensions.md 详情同步）：

- **失效层定位三问**（软代码/规则类改动硬前置）：①回退/事故时相关规则在场吗？②若在场，失效在哪层？③方案作用于哪层、与失效层一致吗？——未做失效层定位就改规则层 = 打补丁默认质疑（阻塞级）
- **症状层形态清单**：追加一次性事实（日期/原话/个案回放）；规则在场仍往规则层加码；用「负向案例锚定更稳」替代结构化耦合论证；「下次再回退就升级」无限延期条款无当下触发条件

一版 PR 在此判据下会在 B2.5 被阻塞（规则在场+失效层未定位+症状形态命中两条），而非形式合规通过。

### 规则层：不加码

BIG_OTTER.md 既有六形态段保持原样——规则已足，失效不在这层。一版追加的案例段随 PR #1958 关闭撤回。

## 边界与取舍（mechanism-addition 机制四问）

1. **谁需要**：所有用 speak 呈递 PR 的 otter（编排主体是大獭）；直接受益人=搭档（时间轴摘要卡完整）+检视獭（台账不再是唯一检测点）
2. **失败后果**：复核失败（台账查询异常）退化为现状（无拒绝），不比修复前更坏；提及场景被拒绝（误伤）成本=再 yield 一次（话术已给出口，缺口零进展即放行留声，不死循环）
3. **后续机制与失误面**：拒绝回执每轮完整列出剩余缺口（多 PR × 两不变量逐类），agent 按回执修复即缺口收敛；agent 无视回执零进展时放行留声（交棒回执仍列缺口供搭档知悉），下一道防线是检视獭 B9 产物核查（本次检视实际抓到过）——重复提醒不是缺陷而是刻意：呈递不齐就该每次被顶，只有确认仅提及的刻意出口才放行
4. **退役条件**：若三件套被更高阶机制取代（如 create PR 工具化自动登记），检测可随呈递形态一起退役；监控信号：提醒高频出现且 agent 持续忽略=提醒语义失效，需升级为阻塞
