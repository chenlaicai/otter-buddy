# PR 呈递三件套回退案例沉淀（F20261119prcrn）

## 回退现场（#1907）

2026-11-16~17，四个 PR（#1890/#1901/#1903/#1906）交付时只走 create_linked_resource 摘要卡或在句中夹带 URL——前端 unfurl 预览卡不触发，搭档原话：「最近几天，你都不咋给我主动展示 pr 卡片，之前明明你还记得给我展示的」。

关键事实：六形态规则与「裸链独占段」指引**一直在 BIG_OTTER.md 在场**，回退不是规则缺失而是规则失效——抽象正向表述（「最常见的纠偏：…」）在长上下文里敌不过惯性。

## 修复：负向案例锚定

在既有条目下追加（与文件内其他回退标注同构）：

> **回退案例（#1907）**：2026-11-16~17 连续四个 PR 只走摘要卡或句中夹带 URL，搭档原话「你都不咋给我主动展示 pr 卡片」——三件套是**固定动作**不是可选风格：①结论 1-2 句 → ②PR URL 裸写独占一段（unfurl 卡）→ ③create_linked_resource 登记（摘要卡）。任何一步缺席都是回退；交付 PR 时自查三步齐。

三要素：具体事故锚（日期+PR 数+搭档原话）负向记忆 > 抽象规则；三步编号动作清单（可执行）；「交付 PR 时自查」触发词绑定到交付时刻。

## 为何不动 speak 工具描述

speak 工具描述已含「URL 裸写独占一段（编排者动作）」且每轮注入——回退期间它也在场。本 PR 先走提示词案例层（成本最低）；若后续仍回退，说明静态注入层都不够，届时升级为运行时结构化检查（呈递类 speak 的卡片预算/裸链检测提醒），由下次回退事故触发，不预做。
