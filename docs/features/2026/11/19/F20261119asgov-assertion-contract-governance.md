> 3. 这个没太看懂，但你从第一性原理出发来分析这个问题本质是什么，然后给出根治方案来做

## 第一性分析：断言问题本质

验证断言是「产出时写死、30 天后兑现」的契约。契约成立要求两个不变量：**方向**（=问题还在判据：什么条件满足=问题仍在）与**可判性**（机械可执行）。失效链：

1. **产出侧无机械约束**：方向规范（F20261116）只住在 daily-health-check 建单路径的 prompt 里；海獭运行中开单是第二条产出路径，零覆盖——11-19 实测 #1949（当日新建）仍是「修复后 X 能正常执行」好结果方向。
2. **验证侧退回无受体**：好结果方向 → ⚠️ 退回「等作者改写」，但作者=每日流水线自身，没有独立的作者会来改——死循环。11-15/11-18 两轮对同 4 issue 重复 ⚠️；清单生成只排除 pass，unknown 每日重列（F20261110rvded 设计「允许后续回查」，但没人修断言就成永久循环）。
3. **拍板取代无感知**：搭档拍板可取代断言的问题定义（#1067 评测机制去留、#1511 配额边界），验证侧按旧字面判据硬判会撞翻拍板（历史上 #1067 被反复重开的事故正是此类）。

本质：**契约的验证在 D+30，但契约的签订在 D+0 却无人校验**——修复必须前移到签订时点，且验证侧要有终止空转与感知拍板的协议。

## 根治三件套

| 层 | 手段 | 载体 |
|---|---|---|
| 产出侧机械闸 | 方向 lint（启发式分类），每日任务例行跑，坏方向当日作者身份机械取反改写 | scripts/lint-issue-assertions.mjs + 每日-issue-处理.md 例行职责 |
| 验证侧协议 | 方向修复协议（可取反→改写后判定；不可取反→⚠️+补写可判断据；同因 ⚠️ 不许跨轮留）+ 判定前置拍板取代感知 | regression-verify.md |
| 任务目标重构 | 在途 PR 项忽略不进清单；「孤儿检出」置顶段为第一职责 | 每日-issue-处理.md |

### 方向分类器设计要点（踩坑实录）

- 否定形态剥离：「未下降」含「下降」、「未归零」含「归零」子串——先剥否定再扫好结果词，否则改写后的问题侧断言被误判回好结果（#1540/#1766 改写形态实证）。
- 改写标注剥离：改写标注块【YYYY-MM-DD lint/回查改写：…】内嵌原文引用含好结果词，标注是溯源不是断言语义（#1766 改写后复扫实证）。
- 裸 ≤/≥ 不作好结果标记：「仍 ≥ 基线」是问题侧表述；纯阈值好结果断言（≤1 条/周无其他好结果词）落 unclear 同样进改写路径，不漏。
- 复合断言（问题词+好结果词并存）保守判好结果交人工取向，不误放行。

### 孤儿检出定义（每日任务第一职责）

open 且挂龄 ≥3 天且无 open PR 引用，满足其一：① 认领后超 48h 无后续 PR/无评论更新；② 无认领无 PR、非等输入类，最后活动超 3 天（无评论 issue 以创建时间为最后活动）。两支均要求对应对话近 48h 无活动（对话活跃=在推进不判孤儿；无对应对话视为满足——无主单本无活跃驱动方）；与 1b 认领回收同口径（48h+24h）。搭档拍板搁置（评论含「别管/勿动/勿捞取」原话）不进清单不进孤儿段；「等搭档输入」型不算孤儿，照列清单标「等输入」；空态输出一行交代。

## 边界与不做

- lint 是启发式初筛不是终判（终判在回查窗口按协议）；误报的代价是多一次人工看一眼，漏报由验证侧协议兜底（unclear 也进改写路径）
- 不给断言上硬 CI 闸（拒绝成本高于收益）：每日任务例行跑 + 记录行，软强制沿用 F20260917rgsv 定位
- 每日任务「搭档勾选后才开工」纪律不变——孤儿检出是呈报面重构，不是自启开工授权

## 设计取舍（新机制四问）

1. **具体需要角色**：每日流水线（9:30 任务执行体）与到期回查执行体（regression-verify 触发的獭）——两者都是「断言作者=流水线自身」场景的机械执行方；搭档不需要该机制（人工本来就能读语义），受益面是自动化链路的判定确定性。
2. **新机制失败的用户可感知后果**：lint 误报（好结果方向误判）→ 当日多一次人工复核/一次多余改写（改写自含原文标注，可还原）；lint 漏报 → 断言带病存活到 D+30，回查侧方向修复协议兜底（unclear 也进改写路径），最坏退回本轮之前的 ⚠️ 循环，不劣于现状。协议误取反（极小概率，机械取反限定纯量词/阈值/趋势形态）→ 回查判据方向反了——防线：取反仅限可机械判定形态，复合断言一律 ⚠️+补写。
3. **新状态出错后的后续处理**：改写争议（搭档不认可某次机械取反）→ 原文留档于标注与特性文档，一键还原；改写后断言仍无法判 → 回查标 ⚠️ 且补写可判断据，同因 ⚠️ 不许跨轮留（第二轮必须升级搭档）；孤儿检出的误报/漏报 → 每日产出含空态交代与计数行，搭档在清单上可见可纠。
4. **退役条件**：断言产出侧若未来上硬门（创建时机械校验拒绝坏方向断言，fail-closed），本 lint 的每日例行职责退役（脚本保留作迁移期双保险）；方向修复协议在断言 100% 问题还在判据产出后自然休眠；孤儿检出在 issue 全生命周期有机械 owner 跟踪（如 in-flight 检测进 CI）后可退役置顶段。
