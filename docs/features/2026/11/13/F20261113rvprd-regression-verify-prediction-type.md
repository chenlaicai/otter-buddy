# F20261113rvpt: 回归回查区分预测型与修复型断言

## 问题

#1067 的验证断言是**预测型**：「止损线 issue 创建后 30 天内 golden-results.jsonl 仍不存在且 intent 率仍 <30%（机制确认死亡/空心）」——断言预期的是坏结果（机制死亡）。

现实走向相反：golden-results.jsonl 建立并持续写入、intent 率回到 60-100%，机制存活。regression-verify 按字面判定「断言不成立」→ ❌ → 命中「未通过处置：❌ 已 closed → 重开并升一级」，把一件「机制活着」的好事当成「修复未兑现」重开升级。

而 #1067 的实质决策（评测机制去留）已于 2026-10-23 由搭档拍板终结：「评测机制肯定要留啊」。重开 = 违背拍板 + 制造每日 ❌ 噪声循环（10-30 收口关闭 → 11-10 又被重开）。

## 根因

`prompts/scheduled/regression-verify.md` 的「判定」与「未通过处置」步骤只有单一语义：「证据满足断言 → ✅；不满足 → ❌；❌ 已 closed → 重开升级」。这个语义只适用于**修复型断言**（断言修复已生效，$\\neg$断言 = 修复未兑现 = 真问题）。对**预测型断言**（断言坏状态持续，$\\neg$断言 = 坏状态未发生 = 好消息），判定方向与处置语义错配。

## 修复契约

在 prompt 的「判定」步骤前置断言类型分辨：

- **修复型断言**（预期好结果，如「修复后 X 不再发生」）：维持原语义——✅ 通过 / ❌ 未通过 / ⚠️ 无法判定，❌ 已 closed 重开升级。
- **预测型断言**（预期坏结果，如「仍不存在」「仍 <30%」「机制死亡/空心」）：
  - 证伪（坏结果未发生、机制存活）→ 判定 ✅（预测证伪=机制存活），**不按未通过处置**；issue 若 open 正向销案关闭，若已 closed 保持不动，绝不重开。
  - 成真（坏结果确实持续）→ ❌，按问题持续处理。

纪律新增一条：「预测型断言证伪 ≠ 修复未兑现」——重开/升级只针对「修了没修好」，不针对「预言的坏结果没发生」。

## 非目标

- 不改 `buildRegressionVerifyBody` 的清单生成（F20261110rvded 已处理 pass 排除；fail/unknown 仍保留在清单是正确的——允许后续回查）。
- 不做机器断言/硬门（沿用 F20260917rgsv 的「软强制」定位）。
- 不撤销 #1067 的搭档拍板结论。
