# 汇报先重建共同处境——修复「没头没尾」的思考起点

## 预注册

- 原预期：若规则已删除或未注入，则是加载退化；若规则仍在注入且样本仍缺背景，则须继续查定义与执行，而不能归因于「模型偶发」。
- 成立标准：实际 prompt 文件、装配路径和当前会话注入一致；近几天不同汇报存在同类缺背景样本。
- 放弃条件：若规则实际未加载，或坏样本来自规则实施前，则不能用「规则出口太宽」解释。

## 现场与根因

2026-11-05 17:06/17:10，chen 两次指出汇报「不说人话/不说完整」「这几天都没头没尾」，并明确上周已经优化过一次，要求排查而不是只重写。

已核实：F20261030rdpov 由 PR #1715 在 2026-10-30 合入；后续 2026-11-03 的 PR #1754 只统一人称，没有删除汇报规则。当前 `prompts/identity/BIG_OTTER.md:49-51` 仍含共同处境前置、三问与发前盲测；`identity-builder.ts:35-37,58-67,101-110` 仍从 prompts/identity 加载并拼入身份前缀，`bootstrap/platforms.ts:107` 指向该目录。当前会话也实际收到了这两条规则。因此「规则被删/没接线」不成立。

### 第一版误诊（保留，不掩盖）

本特性最初将根因归为两层：①定位句定义允许编号替代事情；②发前盲测漏执行。chen 18:46 进一步指出：问题不是「已站其角度但描述不好」，而是「根本没站其角度」，并要求回读犯罪獭自己的思考旅程。

回读 `data/sessions/2026-11-05T07-48-37-121Z_01a1aaae-6081-745f-81bf-e8dccd028683.jsonl` 后确认第一版把根因降成写作技巧，前提错误：

- #1785 终审前思考集中在 CI、简报、授权，没有先建立「chen 此刻知道什么、为什么被拉回这件事」。
- 17:06 被指出后，立即将任务改写成「把这段补到能过盲测」，仍未重建共同处境。
- 盲测题只问「文本能否解析出事情/影响/动作」，不测「组织起点是否在搭档所在处」。所以后来 #1789 的稿即使通过盲测，也不能证明视角成立。

### 更准确的根因

**组织起点错误：大獭从任务执行者/审批申请者的进度出发，没有先从协作者的共同处境出发。** 具体机制是上下文所有权误判：chen 几小时前说过「处理下一个issue」，大獭把这当成 chen 仍完整记得 #1760 的内容；在长任务后直接用 RHI/归口/CI 续接自己的执行上下文。对 chen 来说这不是续接而是空降。

定位句定义与盲测时点是次级症状/辅助手段，不是根因。不能把所有汇报恶化归因于模型切换，也不能把好样本否认掉；根因置信度高，来源是本人原始思考记录+chen 对误诊的明确纠正。

## 最小修正

修法①：在既有 F20261030rdpov 语义内收窄定义，`Modification-Class: narrow-fix`。不新增状态、配置、存储、定时任务或审批机制。

0. **先于写作的共同处境重建**：动笔前分清哪些上下文只有自己拥有、搭档此刻缺哪段；接上他最后真正理解的位置，再补独自推进的变化与现在。搭档原话「处理下一个issue」不等于记得条目内容。此步是思考起点，不是四问勾选项或输出栏目。
1. 定位句首句必须用搭档可识别的场景/问题，编号/PR/内部阶段只能作定位补充；首段让没参与执行的人能回答「本来什么问题、不修有什么影响、现在变成什么」。
2. 测试、CI、delta、commit 是可信度证据，不是叙事主体；默认一句或折叠详情。
3. 重要汇报先写完整人话稿，再把**首句、正文、卡片 title/首屏、按钮含义**作为同一稿发前盲测；回执回来前不得发搭档。无可召唤的未参与獭或召唤失败时，逐项自查并显式标注「未经异体盲测」；能召唤时不得绕过。已有「没看懂」协议不变。
4. 保留 L2 卡片与三层结构，但卡片是呈现详情，不豁免首屏人话。避免把旧卡片字段表重新变成正文。

机制准入三问：决策者不变（仍 chen 拍板）；不增加机械语义判定，沿用半机械流程+异体盲测；深潜成本降低（先看事情，需要时再查 PR 证据）。不命中 P0 负面清单：不自动巡检替人看、不自动跳过。

## 验证（根因层与症状层分开）

- **根因层失败证据**：chen 17:06/17:10 反馈，加上本人 session 原始思考显示终审前只关注 CI/简报/授权，没有先重建搭档处境；这比文本结果更直接指向组织起点。
- **根因层验证**：不能由单次文本或盲测宣告完成。后续真实汇报需能从搭档最后理解的位置续接；由 chen 反馈与下一次汇报前思考回读判断是否仍从任务进度起跑。
- **症状层对照（仅可懂性）**：将「#1760 已修好，CI 四绿，delta 0 严重」重构为「健康检查发现的异常记录需要挂到 GitHub issue 处理；此前还能挂到已关闭 issue，导致没人接手；修复只许挂开放 issue」。17:08 盲测未跟丢，只证明后者更可懂，不证明根因已修。
- 重要终审仍按既有规则发前盲测完整首屏；它是辅助，不是根因验证。不用关键词 lint 冒充语义解决。

## 预期 vs 实际

原预期「prompt 未生效」被证据推翻：规则确实持续加载。第二预期「定义过宽与发前回路未执行就是根因」又被本人思考记录与搭档纠正推翻：它们是次级表现。最终根因是没有先重建共同处境，修正首先调整组织顺序，不新增汇报官僚流程。

## 方案审视处置

- 初轮异体（glm）0 严重、2 建议，独立复验 PR 时间线、规则存活/加载和全部样本。
- S1 硬门可能卡死：**采纳**，补「无可召唤未参与獭/召唤失败→自查并标注未经异体盲测；能召唤不得绕过」。
- S2 PR 需 Golden Gate human_judge 豁免、证据分层与 Rollback：**采纳**，创建 PR 时按模板落实。
- Delta：通过，0 严重/0 新发现；卡片自检同步补「或按降级路径自查并标注」，消除与降级出口的轻微不一致。
- 未新增自动预审/状态/审批；未把汇报质量归因于模型或全量恶化。
- **后续根因更正**：chen 18:46 指出误诊；本人回读原始思考后补上「共同处境未重建」为根因，原两因素降为症状。修订 PR 须重新异体审视，不能沿用此前 delta 通过宣称新根因方案已审。
- **根因更正复核发现（mimo-pro）**：方向确认不是换词修辞；S1 验证层拿盲测当根因证据、S2 frontmatter 写旧根因，另有措辞重叠/四问八股/层级不清/引文示例建议。
- **处置**：S1/S2 与 A1-A4 均已修；delta 通过（0 严重），O1-O4 的引文、capability_test、发现/处置分行与行号同步修正。根因层仍只由后续真实汇报与思考回读校准。

## 影响与回滚

只改大獭说话纪律与既有决策简报参考，不动代码逻辑。风险是写背景稍长；通过「首段完整、过程下沉」控制，而非恢复黑话缩写。回滚 revert 本修订即恢复旧规则，但旧出口会重新出现。
