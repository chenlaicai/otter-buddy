# 汇报定位句不能只报编号——修复「没头没尾」规则退化

## 预注册

- 原预期：若规则已删除或未注入，则是加载退化；若规则仍在注入且样本仍缺背景，则须继续查定义与执行，而不能归因于「模型偶发」。
- 成立标准：实际 prompt 文件、装配路径和当前会话注入一致；近几天不同汇报存在同类缺背景样本。
- 放弃条件：若规则实际未加载，或坏样本来自规则实施前，则不能用「规则出口太宽」解释。

## 现场与根因

2026-11-05 17:06/17:10，chen 两次指出汇报「不说人话/不说完整」「这几天都没头没尾」，并明确上周已经优化过一次，要求排查而不是只重写。

已核实：F20261030rdpov 由 PR #1715 在 2026-10-30 合入；后续 2026-11-03 的 PR #1754 只统一人称，没有删除汇报规则。当前 `prompts/identity/BIG_OTTER.md:49-50` 仍含三问与发前盲测；`identity-builder.ts:35-37,58-67,101-110` 仍从 prompts/identity 加载并拼入身份前缀，`bootstrap/platforms.ts:107` 指向该目录。当前会话也实际收到了这两条规则。因此「规则被删/没接线」不成立。

真实样本（记忆条目 ID）：

| 时间/样本 | 首屏问题 | 判定 |
|---|---|---|
| 11-02 `bdf9d3cf…` | 「PR #1724…走完整审视循环」 | 以内部编号与审查进度定位，未先讲使用场景/原始问题 |
| 11-05 `5c9c26a0…` | 「#1761 批量处置修复已到终审」 | 编号不是事情，「批量处置」没有解释谁遇到什么问题 |
| 11-05 `b20adf06…` | 「#1760 已修好…CI 四绿，delta 0 严重」 | 本次现场：流程信息淹没问题和影响 |
| 11-04 `2cceb4ba…` | 首句报审查，但下一段解释「规则写错以前 CI 5 分钟才发现」 | 部分自足，说明同一规则下质量波动 |
| 11-02 `9d1f86e1…` | 「弹窗透明问题…正文从半透明变实色」 | 好对照：有搭档可感知的问题和效果，不需理解内部流程 |

根因两层，置信度高：

1. **规则定义留错出口**：BIG_OTTER:49 与 decision-briefing.md:32 把定位句定义为「这是哪件事+现在什么状态」，同时说「不是从头讲故事」。执行者可把 issue/PR 编号当作「哪件事」，把 CI/delta 当作「状态」，形式合格却不知所云。缺少「编号不能替代事情本身」与「首段最低交代：场景/原始问题/影响」。
2. **反馈回路没在正确时点执行**：原规则要求决策/收尾/坏消息发前盲测；本次 #1785 首次终审直接发卡并交棒，chen 指出后才补盲测。只重写散文而漏测卡片首句/按钮，也救不了已发出的首屏。

不是证据支持的原因：没有证据显示模型切换必然造成退化；也不能说所有近几天汇报都差。结论是「规则+执行均不稳定」，不是全量恶化或某个模型背锅。

## 最小修正

修法①：在既有 F20261030rdpov 语义内收窄定义，`Modification-Class: narrow-fix`。不新增状态、配置、存储、定时任务或审批机制。

1. 定位句首句必须用搭档可识别的场景/问题，编号/PR/内部阶段只能作定位补充；首段让没参与执行的人能回答「本来什么问题、不修有什么影响、现在变成什么」。
2. 测试、CI、delta、commit 是可信度证据，不是叙事主体；默认一句或折叠详情。
3. 重要汇报先写完整人话稿，再把**首句、正文、卡片 title/首屏、按钮含义**作为同一稿发前盲测；回执回来前不得发搭档。无可召唤的未参与獭或召唤失败时，逐项自查并显式标注「未经异体盲测」；能召唤时不得绕过。已有「没看懂」协议不变。
4. 保留 L2 卡片与三层结构，但卡片是呈现详情，不豁免首屏人话。避免把旧卡片字段表重新变成正文。

机制准入三问：决策者不变（仍 chen 拍板）；不增加机械语义判定，沿用半机械流程+异体盲测；深潜成本降低（先看事情，需要时再查 PR 证据）。不命中 P0 负面清单：不自动巡检替人看、不自动跳过。

## 验证

- 修复前最小复现：用「#1760 已修好，CI 四绿，delta 0 严重」给未参与者读，无法知道原始问题与影响；chen 17:06 的反馈是直接失败证据。
- 修复后对照：同一件事改写为「健康检查发现的异常记录需要挂到 GitHub issue 处理；此前还能挂到已关闭 issue，导致没人接手；修复只许挂开放 issue，等你决定是否合入」。2026-11-05 17:08 异体盲测回执「未跟丢：能回答这是什么事/有什么影响/要搭档做什么」。
- 本修订的重要终审须先发前盲测完整首屏；只测可懂，不评技术/是否该合。
- 不用关键词 lint 声称语义已解决；实际效果由后续真实汇报与 chen 反馈校准。

## 预期 vs 实际

原预期只是「prompt 未生效」被证据推翻：规则确实持续加载。最终定位到定义过宽与发前回路未执行。修正聚焦这两个根因，不新增汇报官僚流程。

## 方案审视处置

- 初轮异体（glm）0 严重、2 建议，独立复验 PR 时间线、规则存活/加载和全部样本。
- S1 硬门可能卡死：**采纳**，补「无可召唤未参与獭/召唤失败→自查并标注未经异体盲测；能召唤不得绕过」。
- S2 PR 需 Golden Gate human_judge 豁免、证据分层与 Rollback：**采纳**，创建 PR 时按模板落实。
- Delta：通过，0 严重/0 新发现；卡片自检同步补「或按降级路径自查并标注」，消除与降级出口的轻微不一致。
- 未新增自动预审/状态/审批；未把汇报质量归因于模型或全量恶化。

## 影响与回滚

只改大獭说话纪律与既有决策简报参考，不动代码逻辑。风险是写背景稍长；通过「首段完整、过程下沉」控制，而非恢复黑话缩写。回滚 revert 本修订即恢复旧规则，但旧出口会重新出现。
